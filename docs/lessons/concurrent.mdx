# 并发特性：useTransition 与 useDeferredValue

<LessonHeader />

<Warmup />

<LessonGoals />

<LessonProse>

React 18 引入了**并发渲染**。核心思想是：并非所有更新都同样紧急。

- **紧急更新**：打字、点击、按键。用户期望立刻有反馈，哪怕慢 100ms 都能感觉到卡顿。
- **过渡更新（Transition）**：根据输入筛选一个大列表、切换标签页内容。稍微慢一点用户可以接受。

以前，所有更新都是同步的，不能中断。一次耗时的渲染会“冻住”整个页面，连输入框都不能打字。并发渲染让 React 可以**中断**正在进行的低优先级渲染，先处理紧急的用户输入。

<CallBox kind="like" label="打个比方">

像医院急诊分诊：心脏骤停的病人（打字）必须立刻处理，而例行体检（渲染大列表）可以先等等，甚至做到一半被打断。

</CallBox>

## useDeferredValue：延迟一个值

`useDeferredValue(value)` 返回一个“滞后”的版本。紧急渲染时它保持旧值。这次渲染提交后，React 立即在后台用新值再渲染一次。如果期间又有新输入，就丢弃这次后台渲染。

```jsx play title="对比开启与关闭的输入体验"
import { useState, useDeferredValue, memo } from 'react';

// 一个故意很慢的列表：每项渲染都要耗费一点时间
const SlowList = memo(function SlowList({ text }) {
  const items = [];
  for (let i = 0; i < 200; i++) items.push(<SlowItem key={i} text={text} />);
  return <ul style={{ height: 160, overflow: 'auto' }}>{items}</ul>;
});

function SlowItem({ text }) {
  const start = performance.now();
  while (performance.now() - start < 1) {} // 每项阻塞 1ms
  return <li>结果：{text}</li>;
}

function App() {
  const [text, setText] = useState('');
  const [useDeferred, setUseDeferred] = useState(true);
  const deferredText = useDeferredValue(text);
  const listText = useDeferred ? deferredText : text;

  return (
    <div>
      <label><input type="checkbox" checked={useDeferred} onChange={e => setUseDeferred(e.target.checked)} /> 使用 useDeferredValue</label>
      <p><input value={text} onChange={e => setText(e.target.value)} placeholder="快速打字，感受卡顿差异" /></p>
      <div style={{ opacity: text !== listText ? 0.5 : 1 }}>
        <SlowList text={listText} />
      </div>
    </div>
  );
}
```

<CallBox kind="tip" label="要点">

注意 SlowList 用了 `memo`。这一点很关键。紧急渲染时，deferredText 还是旧值。memo 让列表跳过这次渲染，所以输入框能立即更新。

</CallBox>

## useTransition：标记一次状态更新为“不紧急”

当你能控制 set 函数调用的位置时，用 `useTransition`。它返回 `isPending`（是否有过渡正在进行）和 `startTransition` 函数。

```jsx title="切换标签页时不阻塞界面"
const [isPending, startTransition] = useTransition();

function selectTab(next) {
  startTransition(() => {
    setTab(next); // 这次更新可以被打断，旧界面保持可交互
  });
}

return (
  <>
    <TabButtons onSelect={selectTab} />
    {isPending && <Spinner />}
    <TabContent tab={tab} />
  </>
);
```

```jsx play title="用 useTransition 切换标签页"
import { useState, useTransition } from 'react';

// 一个故意很慢的标签页：500 项，每项阻塞 1ms
function SlowPosts() {
  const items = [];
  for (let i = 0; i < 500; i++) items.push(<SlowPost key={i} i={i} />);
  return <ul style={{ height: 160, overflow: 'auto' }}>{items}</ul>;
}

function SlowPost({ i }) {
  const start = performance.now();
  while (performance.now() - start < 1) {}
  return <li>文章 #{i + 1}</li>;
}

function App() {
  const [tab, setTab] = useState('about');
  const [useT, setUseT] = useState(true);
  const [isPending, startTransition] = useTransition();

  function selectTab(next) {
    if (useT) startTransition(() => setTab(next)); // 勾选时
    else setTab(next);                             // 未勾选时
  }

  const btn = (id, label) => (
    <button onClick={() => selectTab(id)} style={{ fontWeight: tab === id ? 'bold' : 'normal' }}>{label}</button>
  );

  return (
    <div>
      <label><input type="checkbox" checked={useT} onChange={e => setUseT(e.target.checked)} /> 使用 startTransition</label>
      <p>{btn('about', '关于')} {btn('posts', '文章（很慢）')} {btn('contact', '联系')} {isPending && <small>加载中…</small>}</p>
      <div style={{ opacity: isPending ? 0.5 : 1 }}>
        {tab === 'about' && <p>这是关于页。</p>}
        {tab === 'posts' && <SlowPosts />}
        {tab === 'contact' && <p>邮箱：hi@example.com</p>}
      </div>
    </div>
  );
}
```

|  | useTransition | useDeferredValue |
|---|---|---|
| 包装的是 | 一次 set 函数调用 | 一个值 |
| 适用场景 | 能拿到这个 state 的 set 函数 | 值来自 props 或第三方，拿不到 set 函数 |
| 加载提示 | 提供 isPending | 比较 value !== deferredValue |

<CallBox kind="warn" label="常见坑">

不要把控制输入框的 state 放进 startTransition。输入框的 value 必须同步更新，否则会出现输入丢字。正确做法是用两个 state，或者用 useDeferredValue。

</CallBox>

## 异步过渡：startTransition 接收 async 函数

React 19 起，`startTransition` 可以接收 async 函数。这样的函数叫 **Action**（见[Actions:异步提交、表单与乐观更新](/lessons/react-19)一课）。`isPending` 在整个异步过程中都是 true，直到函数结束。先看代码，再预测：

```jsx play title="异步过渡的 isPending"
import { useState, useTransition } from 'react';

// 模拟保存：0.8 秒后完成
const save = name => new Promise(resolve => setTimeout(() => resolve(name), 800));

function App() {
  const [isPending, startTransition] = useTransition();
  const [name, setName] = useState('旧名字');
  console.log('渲染：isPending = ' + isPending + '，name = ' + name);

  function saveA() {
    startTransition(async () => {
      const saved = await save('新名字 A');
      setName(saved); // await 之后直接调用
    });
  }

  function saveB() {
    startTransition(async () => {
      const saved = await save('新名字 B');
      startTransition(() => setName(saved)); // await 之后再包一层
    });
  }

  return (
    <div>
      <button onClick={saveA}>保存 A</button>
      <button onClick={saveB}>保存 B</button>
      <p>{isPending ? '保存中…' : '空闲'}：{name}</p>
    </div>
  );
}
```

`await` 之后的 set 函数调用不再属于这次过渡。要让它仍是过渡更新，就再包一层 `startTransition`，像“保存 B”那样。这是最常见的坑。对照控制台：A 的 `name` 变成新值的那次渲染里，`isPending` 还是 true，下一次渲染才变回 false，是两次渲染。B 只有一次。

## useDeferredValue 的初始值

`useDeferredValue(value, initialValue)` 的第二个参数是**首次渲染**时用的值。首次渲染先用 `initialValue`，随后 React 立即在后台再渲染一次，换成真正的 `value`。不传第二个参数时，首次渲染直接用 `value`。

```jsx play title="useDeferredValue 的初始值"
import { useDeferredValue } from 'react';

function Results({ query }) {
  const deferred = useDeferredValue(query, '（初始值）');
  console.log('query = ' + query + '，deferred = ' + deferred);
  return <p>显示：{deferred}</p>;
}

function App() {
  return <Results query="搜索词" />;
}
```

初始值常用来在首次渲染时跳过昂贵的内容，先显示一个轻量的占位，再在后台渲染完整的结果。

`useDeferredValue` 还能和 Suspense 配合。Suspense 在下一课讲：内容还没准备好时，它显示一个备用界面（fallback）。配合时，新值的内容挂起，用户看到的是旧内容，而不是 fallback。这是它在真实项目里最常见的用法。

<CallBox kind="tip" label="维护 React 18 项目时">

React 18 中，`startTransition` 只能接收同步函数，`useDeferredValue` 也没有第二个参数。

</CallBox>

<CallBox kind="deep" label="深入一点">

并发特性和防抖（debounce）不同，它没有固定的延迟。设备快，更新几乎立刻发生。设备慢，更新自动推迟。后台渲染还可以被中断，不浪费计算。注意：并发特性不会减少计算量，它只让慢的渲染可以被打断。要真正减少计算，仍要靠 memo、虚拟列表，或减少渲染的内容。

</CallBox>

## 隐藏界面，但保留 state：`<Activity>`

前面讲的是“更新有轻重缓急”。隐藏一块界面时也有同样的问题：隐藏的内容该占多少优先级？

先看需求。切换标签页或收起侧边栏时，你想“隐藏”一块界面，又不想丢掉用户已经输入的内容。组件的 state 跟着它在树里的位置走（见[渲染机制](/lessons/rendering)）。条件渲染把组件卸载了，state 随之丢失。React 19.2 起稳定的 `<Activity>` 能做到保留。它的 `mode` 属性只有两个值：`"visible"` 和 `"hidden"`。

```jsx play title="三种隐藏方式"
import { Activity, useState, useEffect } from 'react';

function Draft({ name }) {
  const [text, setText] = useState('');
  useEffect(() => {
    console.log(name + '：effect 开始');
    return () => console.log(name + '：effect 清理');
  }, [name]);
  return <input value={text} onChange={e => setText(e.target.value)} placeholder={name} />;
}

function App() {
  const [show, setShow] = useState(true);
  return (
    <div>
      <button onClick={() => setShow(!show)}>{show ? '隐藏' : '显示'}</button>
      <div>{show && <Draft name="条件渲染" />}</div>
      <div style={{ display: show ? 'block' : 'none' }}>
        <Draft name="CSS 隐藏" />
      </div>
      <Activity mode={show ? 'visible' : 'hidden'}>
        <Draft name="Activity" />
      </Activity>
    </div>
  );
}
```

`mode="hidden"` 时，React 做三件事：

1. 用 `display: none` 隐藏子树的 DOM。DOM 和 state 都留着。
2. 清理子树里的 effect，就像卸载一样。
3. 子树仍会随新的 props 重新渲染，但优先级比可见的内容低。

切回 `"visible"` 时，state 原样恢复，effect 重新运行。三种隐藏方式的对比：

| 做法 | state | effect | 隐藏时的渲染 |
|---|---|---|---|
| 条件渲染 `{show && <Page />}` | 丢失 | 卸载时清理 | 不渲染 |
| CSS `display: none` | 保留 | 一直在运行 | 照常重新渲染 |
| `<Activity mode="hidden">` | 保留 | 被清理，显示时重新运行 | 低优先级重新渲染 |

第 3 件事和本课的主题直接相连。隐藏的子树对用户不可见，所以它的更新不紧急。React 先渲染并提交可见的部分，再找空档渲染隐藏的部分。和过渡更新一样，这次后台渲染可以被打断：用户一操作，React 先去处理可见内容。所以隐藏的子树再大，也不会拖慢你正在看的界面。

下面的示例把这个顺序打印了出来。隐藏区和可见区读同一个 `n`。

```jsx play title="隐藏的子树晚一步渲染"
import { Activity, useState, useEffect } from 'react';

function Panel({ name, n }) {
  console.log(name + ' 渲染，n = ' + n);
  useEffect(() => {
    console.log(name + ' 提交，n = ' + n);
  });
  return <p>{name}：{n}</p>;
}

function App() {
  const [n, setN] = useState(0);
  return (
    <div>
      <button onClick={() => setN(n + 1)}>n + 1</button>
      <Panel name="可见区" n={n} />
      <Activity mode="hidden">
        <Panel name="隐藏区" n={n} />
      </Activity>
    </div>
  );
}
```

隐藏区的“提交”一行从不出现，因为 effect 在隐藏时被清理，不会运行。

<CallBox kind="warn" label="常见坑">

Activity 隐藏的是 DOM，不会替你停掉有副作用的 DOM。隐藏的 `<video>` 会继续播放。要在 effect 的清理函数里暂停它。

另外，只渲染文字的组件没有 DOM 元素可以隐藏，所以 `hidden` 时什么也不渲染。保留 state 也有代价：隐藏的子树仍占着内存，还会重新渲染。只对来回切换的界面使用它。

</CallBox>
