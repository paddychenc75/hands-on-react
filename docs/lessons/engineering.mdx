## 创建项目

Create React App 已于 2025 年 2 月被官方正式弃用。今天的主流选择是：

| 场景 | 推荐 |
|---|---|
| 全栈应用、需要 SEO、需要 RSC | **Next.js**（App Router）或 **React Router** 框架模式（Remix v2 已并入） |
| 纯客户端应用、后台管理系统、学习练手 | **Vite**：`npm create vite@latest my-app -- --template react-ts` |
| 移动端 App | **React Native** + Expo |

## TypeScript 与测试：先记住一句话

- **TypeScript**：给 props 和 state 写上类型，组件 API 就自带文档，编辑器在你写代码时就标出错误。团队项目几乎都用它。详见第 32 课。
- **测试**：React Testing Library 的原则是**测试用户看到和做的事，不测试实现细节**。按文字、角色、标签查找元素，模拟点击和输入，断言界面结果。不要断言 state 的值或组件内部方法。详见第 35 课。

<CallBox kind="tip" label="要点">

本应用的“检查答案”按钮思路相同：渲染组件，模拟点击和输入，再检查页面。为了简单，它用 id 查找元素。真实测试应优先按角色和文字查找。

</CallBox>

## 项目结构与好习惯

- **按功能组织文件**，例如 features/cart、features/auth。不要按类型把文件全堆在 components/、hooks/ 里。
- 开启 **StrictMode** 和 **ESLint**（包括 react-hooks 插件，v6 起使用 flat config，并包含 React Compiler 的规则）。它们在开发阶段就能发现很多 bug。
- 考虑启用 **React Compiler**（2025 年 10 月发布 1.0 稳定版），让它自动做记忆化。
- 组件保持**纯函数**：同样的 props 和 state，返回同样的 JSX。
- 先让它工作，再用 Profiler 测量，最后才优化。
