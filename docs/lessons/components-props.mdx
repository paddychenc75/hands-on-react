# 组件与 Props

**组件就是一个返回 JSX 的函数**。组件名必须以**大写字母**开头。React 用这一点区分组件和 HTML 标签：`<div>` 是标签，`<Card>` 是组件。

```jsx play title="定义一次，到处使用"
function Avatar() {
  return <span style={{ fontSize: 40 }}>🦊</span>;
}

function App() {
  return (
    <div>
      <Avatar />
      <Avatar />
      <Avatar />
    </div>
  );
}
```

## Props：组件的参数

如果每个组件都只能显示一模一样的内容，用处就不大了。**props**（properties 的缩写）让父组件把数据传给子组件。这就像给函数传参数。

```jsx play title="通过 props 传入数据"
function UserCard({ name, role, emoji = '🙂' }) {
  return (
    <div style={{ border: '1px solid #ccc', borderRadius: 8, padding: 10, margin: 6 }}>
      <b>{emoji} {name}</b>
      <div style={{ color: 'gray' }}>{role}</div>
    </div>
  );
}

function App() {
  return (
    <div>
      <UserCard name="张三" role="前端工程师" emoji="👨‍💻" />
      <UserCard name="李四" role="设计师" emoji="🎨" />
      <UserCard name="王五" role="产品经理" />
    </div>
  );
}
```

上面用到了 **解构**：`function UserCard({ name, role })` 等价于先接收一个 `props` 对象，再取出 `props.name`、`props.role`。`emoji = '🙂'` 是解构时的默认值。

<CallBox kind="like" label="打个比方">

组件像一个模具，props 像往模具里倒的材料。同一个“卡片模具”，倒入不同的名字和职位，就做出不同的卡片。

</CallBox>

## Props 是只读的

<CallBox kind="warn" label="常见坑">

组件**绝对不能修改自己的 props**。`props.name = '新名字'` 这样的代码是错误的。props 属于父组件，子组件只能读取。想要“可变化的数据”，要用下一课的 **state**。

开发环境中，React 会冻结 props 对象：在真实项目（ES 模块，严格模式）里，改 props 的那行代码会直接抛出 TypeError；在本站实验台里会静默失败。生产构建不冻结，赋值会“成功”，但 React 不知道，界面不会更新。无论哪种情况，这都不是修改数据的办法。

</CallBox>

## 组件必须是纯函数

组件要像**纯函数**：同样的 props 和 state，返回同样的 JSX。渲染时不要修改组件外的变量，不要发请求，不要改 DOM。这些事放在事件处理函数里。第 14 课会讲剩下的情况。

React 怎么帮你发现违反这条规则的代码？开发环境里的**严格模式**（`<StrictMode>`）会把每个组件函数调用两次。纯函数调用两次，结果和调用一次相同。不纯的函数就会露馅。生产环境没有这个检查。

下面的 `Cup` 在渲染时修改了模块变量 `guest`，并包在 `<StrictMode>` 里。

```jsx play title="渲染时修改外部变量"
import { StrictMode } from 'react';

let guest = 0;

function Cup() {
  guest = guest + 1;
  return <p>{guest} 号杯子</p>;
}

function App() {
  return (
    <StrictMode>
      <Cup />
      <Cup />
      <Cup />
    </StrictMode>
  );
}
```

修复办法是不在渲染时改外部变量，让编号从 props 来：`<Cup no={1} />`，组件里写 `<p>{no} 号杯子</p>`。

<CallBox kind="warn" label="常见坑">

在组件函数里 `guest++`、`list.push(x)`、`document.title = …`，都是渲染时的副作用。前两个在严格模式下会出现“多做一次”的现象；改 DOM 的那种即使看不出来，也该移走。把这类代码移进事件处理函数或 effect。

</CallBox>

## 特殊的 prop：children

写在组件开闭标签之间的内容，会作为 `children` prop 传进去。这让你可以做出“容器”类组件，比如面板、弹窗、布局。

```jsx play title="children 让组件可以“包裹”任意内容"
function Panel({ title, children }) {
  return (
    <section style={{ border: '2px solid #087ea4', borderRadius: 10, padding: 12, margin: 8 }}>
      <h3 style={{ margin: 0 }}>{title}</h3>
      <div>{children}</div>
    </section>
  );
}

function App() {
  return (
    <>
      <Panel title="公告">
        <p>本周五下午 3 点开会。</p>
      </Panel>
      <Panel title="待办">
        <ul><li>写周报</li><li>修 bug</li></ul>
      </Panel>
    </>
  );
}
```

## 给组件加样式

用 `className` 指定 CSS 类名，样式写在 CSS 文件里。`className` 接收一个字符串。常见做法是让组件的 prop 决定类名：

- `variant` 这样的 prop 对应一个类名，例如 `className={'btn btn-' + variant}`。
- 条件类名：用模板字符串，或者把类名放进数组再 `filter(Boolean).join(' ')`。
- 内联 `style` 只用于随数据变化的数值，例如进度条的宽度。固定样式放进 CSS。

```jsx play title="用 className 和 variant 加样式"
function Button({ variant = 'primary', disabled, children }) {
  const cls = ['btn', 'btn-' + variant, disabled && 'btn-disabled'].filter(Boolean).join(' ');
  return <button className={cls} disabled={disabled}>{children}</button>;
}

function App() {
  return (
    <div>
      <style>{`
        .btn { padding: 6px 14px; margin: 4px; border: 0; border-radius: 6px; color: white; }
        .btn-primary { background: #087ea4; }
        .btn-danger { background: crimson; }
        .btn-disabled { opacity: 0.4; }
      `}</style>
      <Button>保存</Button>
      <Button variant="danger">删除</Button>
      <Button disabled>不可用</Button>
    </div>
  );
}
```

真实项目里，样式写在 `.css` 文件中，用 `import './app.css'` 引入。本站实验台没有文件，所以这里把 CSS 放进 `<style>` 标签。

<CallBox kind="tip" label="要点">

组件拆分的经验法则：一个组件只做一件事。如果一个组件越来越长，或者某块界面在多处重复出现，就是拆分的信号。

</CallBox>
