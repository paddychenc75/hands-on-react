# useReducer：集中管理复杂状态

<LessonHeader />

<Warmup />

<LessonGoals />

<LessonProse>

有的组件有很多种修改 state 的方式，例如添加、删除、编辑、切换、清空。这些逻辑分散在多个事件处理函数里，代码会越来越难维护。`useReducer` 让你把所有“状态如何变化”的逻辑**集中到一个纯函数**里。

```jsx
const [state, dispatch] = useReducer(reducer, initialState);

// reducer：接收旧状态和一个“动作”，返回新状态
function reducer(state, action) {
  switch (action.type) {
    case 'increment': return { count: state.count + 1 };
    default: return state;
  }
}

// 组件中只需要“派发”动作，描述发生了什么
dispatch({ type: 'increment' });
```

<CallBox kind="like" label="打个比方">

reducer 像银行柜台。你不能自己进金库拿钱。你填一张单子（action：“取款 100 元”），交给柜员（dispatch）。柜员按规定流程（reducer）更新账户（state）。所有账户变动都遵守同一套规则。

</CallBox>

```jsx play title="待办清单 reducer"
import { useReducer, useState } from 'react';

const initialTodos = [
  { id: 1, text: '学习 useReducer', done: false },
  { id: 2, text: '喝杯咖啡', done: true },
];

let nextId = 3; // 放在组件外

function todosReducer(todos, action) {
  switch (action.type) {
    case 'added':
      return [...todos, { id: action.id, text: action.text, done: false }];
    case 'toggled':
      return todos.map(t => t.id === action.id ? { ...t, done: !t.done } : t);
    case 'deleted':
      return todos.filter(t => t.id !== action.id);
    case 'clearedDone':
      return todos.filter(t => !t.done);
    default:
      throw new Error('未知的 action: ' + action.type);
  }
}

function App() {
  const [todos, dispatch] = useReducer(todosReducer, initialTodos);
  const [text, setText] = useState('');

  function handleSubmit(e) {
    e.preventDefault();
    if (!text) return;
    dispatch({ type: 'added', id: nextId++, text });
    setText('');
    console.log('todos.length =', todos.length);
  }

  return (
    <div>
      <form onSubmit={handleSubmit}>
        <input value={text} onChange={e => setText(e.target.value)} placeholder="新待办" />
        <button>添加</button>
      </form>
      <ul>
        {todos.map(t => (
          <li key={t.id}>
            <label style={{ textDecoration: t.done ? 'line-through' : 'none' }}>
              <input type="checkbox" checked={t.done} onChange={() => dispatch({ type: 'toggled', id: t.id })} />
              {t.text}
            </label>
            <button onClick={() => dispatch({ type: 'deleted', id: t.id })}>删除</button>
          </li>
        ))}
      </ul>
      <button onClick={() => dispatch({ type: 'clearedDone' })}>清除已完成</button>
    </div>
  );
}
```

## 先把 state 结构设计对：五条原则

reducer 管的是 state 怎么变。但 state 长什么样，决定了“变”好不好写。结构设计得不好，reducer 再整齐，也会在更新时漏改某一处。下面五条原则来自 React 官方文档《选择 State 结构》。写 reducer 之前先过一遍。

| 原则 | 有问题的写法 | 改法 |
|---|---|---|
| 合并相关的 state | `x`、`y` 两个 state，总是一起变 | 合成一个对象 `position`，值是 `{ x, y }` |
| 避免矛盾的 state | `isLoading` 和 `isError` 两个布尔值，可能同时为 true | 用一个 `status` 字段，一次只能有一个值 |
| 避免冗余的 state | `firstName`、`lastName` 之外，又存一份 `fullName` | 渲染时直接算：`first + ' ' + last` |
| 避免重复的 state | `items` 里有一个对象，`selectedItem` 里又存了同一个对象 | 只存 `selectedId`，用 id 到 `items` 里找 |
| 避免深嵌套的 state | 多层嵌套的对象，改一个叶子要层层展开 | 拍平成数组或按 id 索引的对象，用 id 互相引用 |

这五条的共同点是：**同一个事实只存在一处**。同一个事实存了两处，每次更新就要同时改两处，漏掉一处，界面就和数据对不上。

下面的示例演示第二条。左边用两个布尔值，右边用一个 status，由 reducer 管。两边都点“请求（会失败）”，再点“请求（会成功）”。

```jsx play title="两个布尔值，还是一个 status？"
import { useState, useReducer } from 'react';

// 模拟请求：0.6 秒后成功或失败
function request(fail) {
  return new Promise((resolve, reject) => {
    setTimeout(() => (fail ? reject(new Error('失败')) : resolve('成功')), 600);
  });
}

function Flags() {
  const [isLoading, setIsLoading] = useState(false);
  const [isError, setIsError] = useState(false);

  function load(fail) {
    setIsLoading(true);
    request(fail)
      .catch(() => setIsError(true))
      .finally(() => setIsLoading(false));
  }

  return (
    <div>
      <h4>两个布尔值</h4>
      <button onClick={() => load(true)}>请求（会失败）</button>{' '}
      <button onClick={() => load(false)}>请求（会成功）</button>
      <p>isLoading = {String(isLoading)}，isError = {String(isError)}</p>
      <p>界面：{isLoading && '加载中… '}{isError && '出错了'}{!isLoading && !isError && '空闲或成功'}</p>
    </div>
  );
}

function statusReducer(status, action) {
  switch (action.type) {
    case 'started': return 'loading';
    case 'failed': return 'error';
    case 'succeeded': return 'success';
    default: throw new Error('未知的 action: ' + action.type);
  }
}

function WithStatus() {
  const [status, dispatch] = useReducer(statusReducer, 'idle');

  function load(fail) {
    dispatch({ type: 'started' });
    request(fail).then(
      () => dispatch({ type: 'succeeded' }),
      () => dispatch({ type: 'failed' })
    );
  }

  return (
    <div>
      <h4>一个 status</h4>
      <button onClick={() => load(true)}>请求（会失败）</button>{' '}
      <button onClick={() => load(false)}>请求（会成功）</button>
      <p>status = {status}</p>
      <p>界面：{status === 'loading' ? '加载中…' : status === 'error' ? '出错了' : '空闲或成功'}</p>
    </div>
  );
}

function App() {
  return (
    <div>
      <Flags />
      <WithStatus />
    </div>
  );
}
```

## useState 还是 useReducer？

| 场景 | 推荐 |
|---|---|
| 简单的独立值（开关、输入框文本、数字） | useState |
| 多个相互关联的状态需要一起变化 | useReducer |
| 更新逻辑复杂、种类多 | useReducer |
| 需要单独测试状态逻辑 | useReducer（reducer 是纯函数，极易测试） |

<CallBox kind="tip" label="要点">

reducer 必须是**纯函数**。同样的输入必须得到同样的输出。reducer 不发请求，不修改原来的 state，不使用随机数或 Date.now()。所以上例在 dispatch 之前生成 id，再放进 action。

`default` 分支可以返回原 state，也可以抛出错误。抛出错误能尽早发现拼错的 `type`，本课示例用这种写法。

</CallBox>

## 为什么 reducer 必须是纯函数

React 需要在渲染时调用 reducer，算出新 state。它可能调用不止一次。开发环境的严格模式（`<StrictMode>`）会故意把 reducer 调用两次，用来暴露不纯的写法。纯函数调用几次结果都一样，所以不受影响。

```jsx play title="严格模式会把 reducer 调用两次"
import { StrictMode, useReducer } from 'react';

function counterReducer(state, action) {
  console.log('reducer 被调用：' + action.type);
  switch (action.type) {
    case 'increment': return { count: state.count + 1 };
    default: throw new Error('未知的 action: ' + action.type);
  }
}

function Counter() {
  const [state, dispatch] = useReducer(counterReducer, { count: 0 });
  return (
    <button onClick={() => dispatch({ type: 'increment' })}>
      点击次数：{state.count}
    </button>
  );
}

function App() {
  return (
    <StrictMode>
      <Counter />
    </StrictMode>
  );
}
```

控制台里有两行，按钮上的数字却只加了 1。因为这个 reducer 是纯的：两次调用都从同一个旧 state 出发，得到同样的新 state，React 只用其中一个结果。

如果 reducer 直接修改旧 state，例如 `state.count += 1; return { ...state }`，两次调用会改同一个对象，数字就加 2。生产环境不会调用两次，所以这类错误平时看不出来，换到严格模式才暴露。
