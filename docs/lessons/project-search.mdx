# 实战二：异步搜索

<LessonHeader />

<Warmup />

<LessonGoals />

<LessonProse>

几乎每个应用都有搜索框。它看起来简单，却很能检验异步功底。用户每输入一个字，应用就发一次请求。而**响应返回的顺序不一定和请求发出的顺序相同**。

## 需求说明

| 编号 | 需求 | 实现约定 |
|---|---|---|
| 1 | 输入关键词后调用 `searchUsers(q)` 搜索用户（已提供，返回 Promise） | `<input id="search">` |
| 2 | 输入为空时不请求，也不显示任何结果 |  |
| 3 | 请求期间显示加载提示 | `<p id="loading">` |
| 4 | 每个结果显示用户名 | `<li className="user">` |
| 5 | 没有结果时显示提示 | `<p id="empty">没有找到</p>` |
| 6 | 请求失败时显示错误 | `<p id="error">`（搜索“错误”会触发失败） |
| 7 | **快速输入时，只显示最后一次输入的结果** | 模拟接口里，关键词越短返回越慢 |

需求 7 是关键。用户先输入“李”，紧接着输入“李四”。“李”的请求**更慢**，会在“李四”之后才返回。如果不处理，界面会先正确显示“李四”的结果，然后被过期的“李”的结果覆盖。

<CallBox kind="tip" label="要点">

解决办法就是第 14 课的 `ignore` 标记：在 effect 的清理函数里把上一次请求标记为过期。进阶写法可以用 `AbortController` 直接取消请求。

</CallBox>

## 建议的结构

```jsx title="用一个 status 字段代替多个布尔值，状态就不会出现“既在加载又出错”的矛盾"
function useUserSearch(query) {
  const [state, setState] = useState({ status: 'idle', data: [], error: null });
  useEffect(() => {
    if (!query) { setState({ status: 'idle', data: [], error: null }); return; }
    let ignore = false;
    // ……发请求、处理成功和失败，记得检查 ignore
    return () => { ignore = true; };
  }, [query]);
  return state;
}
```

<CallBox kind="deep" label="深入一点">

真实的搜索框通常还会加**防抖**：用户停止输入一段时间后，才发请求。

1. 下面的 Hook 让值在停止变化 300 ms 后才更新：`const q = useDebouncedValue(query, 300);`
2. 防抖只减少请求次数，不能保证返回顺序。所以仍然需要 ignore。
3. 本练习的检查程序按固定时间验收。**做练习时不要加防抖。**

</CallBox>

```jsx title="防抖：减少请求次数，但不能代替 ignore"
function useDebouncedValue(value, delay) {
  const [v, setV] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setV(value), delay);   // 停止变化 delay 毫秒后才更新
    return () => clearTimeout(id);                     // 值又变了：取消上一个计时器
  }, [value, delay]);
  return v;
}
```
