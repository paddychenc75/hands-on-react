## 一个完整的测试文件

```jsx title="运行：npx vitest"
// Counter.test.jsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { describe, it, expect } from 'vitest';
import Counter from './Counter';

describe('Counter', () => {
  it('初始显示 0', () => {
    render(<Counter />);
    expect(screen.getByText('计数：0')).toBeInTheDocument();
  });

  it('点击 +1 后变为 1', async () => {
    const user = userEvent.setup();
    render(<Counter />);
    await user.click(screen.getByRole('button', { name: '+1' }));
    expect(screen.getByText('计数：1')).toBeInTheDocument();
  });
});
```

<CallBox kind="tip" label="要点">

先安装依赖：`npm i -D vitest jsdom @testing-library/react @testing-library/dom @testing-library/user-event @testing-library/jest-dom msw`。Testing Library 的 React 版要求你自己装 `@testing-library/dom`，漏装是最常见的第一个报错。

这个文件需要两项配置才能运行：

1. 在 vitest.config 中设置 `environment: 'jsdom'` 和 `globals: true`。否则 Testing Library 不会在每个测试后自动清理 DOM。
2. 在 setup 文件中写 `import '@testing-library/jest-dom/vitest'`。这样才能用 `toBeInTheDocument`。

在 Vite 项目里，一份可用的配置是：

```ts title="在本机项目里：vitest.config.ts（放在项目根目录）"
import react from '@vitejs/plugin-react';
import { defineConfig } from 'vitest/config';

export default defineConfig({
  plugins: [react()],
  test: {
    environment: 'jsdom',
    globals: true,
    setupFiles: './src/setup.ts',   // 文件里只有上面那一行 import
  },
});
```

`globals: true` 让测试里可以不写 `import { it, expect } from 'vitest'`，直接用 `it`、`expect`、`beforeAll`。这样写的测试文件，TypeScript 会在 `npm run build` 的 `tsc -b` 一步报 `Cannot find name 'it'`。要在 `tsconfig.app.json` 的 `compilerOptions.types` 里加上 `"vitest/globals"`：`"types": ["vite/client", "vitest/globals"]`。已经 `import` 了这些函数的测试文件不受影响。

</CallBox>

## 该用哪种查询？

| 优先级 | 查询 | 说明 |
|---|---|---|
| 1（首选） | `getByRole('button', { name: '提交' })` | 按无障碍角色和名称找，最贴近用户和读屏软件 |
| 2 | `getByLabelText('邮箱')` | 表单字段，通过 label 找 |
| 3 | `getByText('欢迎')` | 非交互内容 |
| 最后 | `getByTestId('cart')` | 实在没办法时才用 |

官方完整顺序：Role → LabelText → PlaceholderText → Text → DisplayValue → AltText → Title → TestId。

| 前缀 | 找不到时 | 用途 |
|---|---|---|
| `getBy…` | 立刻报错 | 断言元素一定存在 |
| `queryBy…` | 返回 null | 断言元素**不存在**：`expect(queryByText('x')).toBeNull()` |
| `findBy…` | 返回 Promise，等待出现 | 异步内容：`await screen.findByText('加载完成')` |

<CallBox kind="warn" label="常见坑">

不要测试实现细节。例如：state 里的 count 是不是 1；组件内部的某个函数或 set 函数被调用了几次。（作为 props 传进来的回调是组件的对外接口，断言 `onSubmit` 收到了什么参数是可以的。）这样的测试在重构时会大面积报错，哪怕功能完全正常。只测试用户能看到的结果。

</CallBox>

下面的代码用 30 行实现了 `render`、`getByText`、`getByRole` 和 `test`。我们用它测试一个真实组件。试着让 Counter 出一个 bug，再运行，看哪些测试变红。

```jsx play title="在浏览器里跑测试"
import { useState } from 'react';

// ===== 被测组件 =====
function Counter() {
  const [n, setN] = useState(0);
  return (
    <div>
      <p>计数：{n}</p>
      <button onClick={() => setN(n + 1)}>+1</button>
      <button onClick={() => setN(0)} disabled={n === 0}>重置</button>
    </div>
  );
}

// ===== 迷你测试库 =====
const ROLES = {          // 角色 → 对应的 HTML 元素。role 不是标签名
  button: 'button', link: 'a[href]', heading: 'h1,h2,h3,h4,h5,h6',
  textbox: 'input:not([type]),input[type=text],textarea', checkbox: 'input[type=checkbox]',
};
let container;
function render(ui) {
  container = document.createElement('div');
  ReactDOM.flushSync(() => ReactDOM.createRoot(container).render(ui));
}
const screen = {
  getByText(text) {
    const el = [...container.querySelectorAll('*')].find(e => e.children.length === 0 && e.textContent === text);
    if (!el) throw new Error('找不到文字：' + text);
    return el;
  },
  // 简化版：只认 5 种角色。名称先看 aria-label，再看文字（真实库还会看 <label>、alt 等）
  getByRole(role, { name }) {
    const el = [...container.querySelectorAll(ROLES[role])].find(e => (e.getAttribute('aria-label') ?? e.textContent) === name);
    if (!el) throw new Error('找不到 ' + role + '：' + name);
    return el;
  },
};
const tick = () => new Promise(r => setTimeout(r, 0));
const user = { async click(el) { el.click(); await tick(); } };
function expect(v) {
  return { toBe(x) { if (v !== x) throw new Error('期望 ' + x + '，实际 ' + v); } };
}
const tests = [];
const test = (name, fn) => tests.push({ name, fn });

// ===== 测试用例 =====
test('初始显示 0，重置按钮不可用', async () => {
  render(<Counter />);
  screen.getByText('计数：0');
  expect(screen.getByRole('button', { name: '重置' }).disabled).toBe(true);
});

test('点击 +1 两次后显示 2', async () => {
  render(<Counter />);
  await user.click(screen.getByRole('button', { name: '+1' }));
  await user.click(screen.getByRole('button', { name: '+1' }));
  screen.getByText('计数：2');
});

test('重置后回到 0', async () => {
  render(<Counter />);
  await user.click(screen.getByRole('button', { name: '+1' }));
  await user.click(screen.getByRole('button', { name: '重置' }));
  screen.getByText('计数：0');
});

(async () => {
  let pass = 0;
  for (const t of tests) {
    try { await t.fn(); pass++; console.log('✅ ' + t.name); }
    catch (e) { console.error('❌ ' + t.name + ' → ' + e.message); }
  }
  console.log(pass + '/' + tests.length + ' 通过');
})();

// 右侧同时显示组件本身
function App() { return <Counter />; }
```

## 异步查询与模拟网络（MSW）

真实组件常常在挂载后请求数据，界面稍后才更新。测试要做两件事：等待内容出现，并让请求不依赖真实的服务器。下面的代码只读，实验台不能运行 Vitest。

```jsx title="被测组件：挂载后请求用户，结果稍后才显示"
function UserProfile({ id }) {
  const { data, isPending, isError } = useQuery({
    queryKey: ['user', id],
    queryFn: () => fetch(`/api/users/${id}`).then(r => {
      if (!r.ok) throw new Error('请求失败');
      return r.json();
    }),
  });
  if (isPending) return <p>加载中…</p>;
  if (isError) return <p role="alert">加载失败</p>;
  return <h2>{data.name}</h2>;
}
```

这个组件有三种状态，测试也应该各写一条。等待的办法是 `findBy…`：它每隔一小段时间重新查一次，默认最多等 1 秒。被测代码的请求交给 **MSW**（Mock Service Worker）：它在网络层拦截请求，组件里的 `fetch` 不用改，换成不同的接口响应就能测不同的状态。


```jsx
// 异步：用 findBy 等待内容出现；网络请求用 MSW 在网络层模拟
it('加载后显示用户名', async () => {
  render(<UserProfile id={1} />);
  expect(screen.getByText('加载中…')).toBeInTheDocument();
  expect(await screen.findByText('张三')).toBeInTheDocument();
});

// 自定义 Hook：用 renderHook
import { renderHook, act } from '@testing-library/react';
it('useToggle 可以切换', () => {
  const { result } = renderHook(() => useToggle(false));
  act(() => result.current[1]());
  expect(result.current[0]).toBe(true);
});
```

## 真实项目：写测试时要包好 Provider

```jsx title="组件用了 Router 或 Query，测试里就要包上对应的 Provider"
import { http, HttpResponse } from 'msw';
import { setupServer } from 'msw/node';

// 1. MSW（2.x 和 3.x 写法相同）：在网络层模拟接口。组件里的 fetch 不用改
const server = setupServer(
  http.get('/api/users/1', () => HttpResponse.json({ name: '张三' })),
);
beforeAll(() => server.listen());
afterEach(() => server.resetHandlers());
afterAll(() => server.close());

// 2. 自定义 render：每个测试新建 QueryClient，并关掉重试
function renderWithProviders(ui, { route = '/' } = {}) {
  const client = new QueryClient({ defaultOptions: { queries: { retry: false } } });
  return render(
    <QueryClientProvider client={client}>
      <MemoryRouter initialEntries={[route]}>{ui}</MemoryRouter>
    </QueryClientProvider>
  );
}

// 3. 错误状态也要测：只在这个测试里让接口返回 500
it('接口失败时显示错误', async () => {
  server.use(http.get('/api/users/1', () => new HttpResponse(null, { status: 500 })));
  renderWithProviders(<UserProfile id={1} />);
  expect(await screen.findByRole('alert')).toBeInTheDocument();
});
```

<CallBox kind="tip" label="要点">

推荐的测试比例叫“测试奖杯”。从底层到顶层有四层：

1. 静态检查：TypeScript 和 ESLint，成本最低，覆盖最广。
2. 少量单元测试：测试纯函数和 reducer。
3. **大量集成测试**：用 Testing Library 测试一个页面或一个功能。
4. 少量端到端测试：用 Playwright 在真实浏览器里走完整流程。

</CallBox>

<details className="optional">
<summary><span className="opt-tag">选读</span>端到端：Playwright 一个最小用例<small>可以先跳过，需要时再展开</small></summary>

Testing Library 在 jsdom 里测试，没有真正的浏览器。端到端测试用 Playwright 启动真实的浏览器，从头走一遍用户流程。它很慢，所以只覆盖最关键的几条路径，比如“搜索一个城市，看到结果”。

```bash title="在本机终端里做：安装"
npm init playwright@latest
```

```ts title="在本机项目里：tests/search.spec.ts"
import { test, expect } from '@playwright/test';

test('搜索城市，看到结果', async ({ page }) => {
  await page.goto('http://localhost:5173/');
  await page.getByRole('textbox', { name: '城市' }).fill('北京');
  await page.getByRole('button', { name: '搜索' }).click();
  await expect(page.getByRole('link', { name: '北京' })).toBeVisible();
});
```

Playwright 的查询和 Testing Library 一样，优先按角色和名称找元素。先用 `npm run dev` 启动应用，再运行 `npx playwright test`。也可以在 `playwright.config.ts` 的 `webServer` 里写上启动命令，让它自动启动。

</details>

## 本机任务

在[《实战四：城市天气应用》](/lessons/project-weather)的里程碑 5 里完成，也可以用任何一个小应用。

1. 安装第一个提示框里的依赖，配好 `environment: 'jsdom'`、`globals: true` 和 setup 文件。
2. 给一个组件写 3 条测试：初始状态、一次点击后的结果、一个异步状态（用 `findBy…` 等待）。
3. 用 MSW 让接口返回 500，写一条“显示错误提示”的测试。

对照下面的表自查：

| 做什么 | 应该看到 |
|---|---|
| 运行 `npx vitest run` | 全部通过，终端显示通过的测试数 |
| 把组件里的 `n + 1` 改成 `n + 2` | 点击相关的测试变红，失败信息是 `Unable to find an element with the text: 计数：1`，后面打印出当前的 DOM，里面显示的是“计数：2”。改回后恢复 |
| 把 `findByText` 换成 `getByText` 测试异步内容 | 测试失败：`Unable to find an element with the text: 张三`，内容还没出现 |
| 测试里去掉 `retry: false` 再测错误状态 | 约 1 秒后失败：`Unable to find role="alert"`。`findBy…` 默认只等 1 秒，而查询要重试 3 次才报错（见项目课里程碑 5 的“常见坑”） |
