# Next.js App Router

Next.js 是使用最广的 React 全栈框架。Server Components 主要就用在 Next.js 中。第 30 课讲了原理，这一课看它在真实项目里怎么组织。

<CallBox kind="tip" label="要点">

Next.js 需要 Node.js 服务器，实验台跑不了，所以本课展示 Next.js 代码的代码块都是只读的。站内的两个示例和练习用普通的 React 与函数模拟它的规则，每个示例开头写明模拟什么、和真实环境差在哪；练习实现的是最核心的一条规则（文件夹就是路由）。课末的“本机任务”带你在自己的电脑上亲手跑一遍。创建项目只需一行：`npx create-next-app@latest my-app`，选 `Yes, use recommended defaults`（推荐的默认设置）即可（需要 Node.js 20.9 以上）。本课的描述按 Next.js 16.4.0 实测。

</CallBox>

## 文件夹就是路由

注意 `loading.tsx` 和 `error.tsx`：它们就是第 24 课学的 Suspense 和错误边界。框架按约定自动帮你加上。

`layout.tsx` 还有一个性质：在共用它的页面之间导航时，layout 不会重新挂载，只有 `children`（页面）被换掉，所以 layout 里客户端组件的 state 会保留。需要每次导航都重置时，用 `template.tsx`。下面的示例模拟这个区别。

```jsx play title="模拟：layout 保留 state，template 重新挂载"
// 模拟：在 /dashboard/a 和 /dashboard/b 之间导航时，layout.tsx 与 template.tsx 里的客户端组件各自怎样变化。
// 与真实环境的差别：真实的 Next.js 由文件夹生成这棵树，导航时请求新的 RSC payload；
// 这里用一个 url 状态当作“当前页面”，用 React 的 key 表示 template “每次导航创建新实例”。
import { useState } from 'react';

function SearchBox({ label }) {
  const [text, setText] = useState('');
  return (
    <p>
      <label>
        {label}：<input value={text} onChange={e => setText(e.target.value)} />
      </label>
    </p>
  );
}

function App() {
  const [url, setUrl] = useState('/dashboard/a');
  return (
    <div>
      <button onClick={() => setUrl('/dashboard/a')}>去 /dashboard/a</button>{' '}
      <button onClick={() => setUrl('/dashboard/b')}>去 /dashboard/b</button>
      <SearchBox label="layout.tsx 里的搜索框" />
      <div key={url}>
        <SearchBox label="template.tsx 里的搜索框" />
      </div>
      <p>page.tsx：当前页面是 <b>{url}</b></p>
    </div>
  );
}
```

## 在页面之间跳转

```jsx
import Link from 'next/link';

<Link href="/blog/hello-world">阅读文章</Link>

// 客户端组件里用代码跳转：
// import { useRouter } from 'next/navigation';   const router = useRouter();   router.push('/blog')
// 服务端组件或 Server Function 里：
// import { redirect } from 'next/navigation';    redirect('/login')
```

它和第 36 课的 `<Link to>` 作用相同，属性名是 `href`。生产环境里，链接进入视口时 Next.js 会预取目标页面（开发模式不预取），点击后几乎立即切换。用普通的 `<a>` 会整页刷新。

## 页面：在服务端直接取数据

```jsx title="没有 useEffect，没有 loading state，没有 API 层"
// app/blog/[slug]/page.tsx  —— 默认是服务端组件
import { notFound } from 'next/navigation';
import { db } from '@/lib/db';
import LikeButton from './LikeButton';   // 'use client' 的交互组件

export default async function PostPage({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  const post = await db.post.findUnique({ where: { slug } });
  if (!post) notFound();                 // 渲染 not-found.tsx

  return (
    <article>
      <h1>{post.title}</h1>
      <div>{post.content}</div>
      <LikeButton postId={post.id} initialLikes={post.likes} />
    </article>
  );
}

// 为 SEO 生成 <title> 和 <meta>
export async function generateMetadata({ params }) {
  const { slug } = await params;
  const post = await db.post.findUnique({ where: { slug } });
  // 页面和这里各查一次。用 React 的 cache() 包住查询函数，同一次请求只查一次
  return { title: post?.title ?? '文章不存在' };
}
```

## 表单：Server Function + 重新验证

用作表单 action 时，Next.js 文档也叫它 Server Action。

```jsx
// app/blog/[slug]/actions.ts
'use server';
import { revalidatePath } from 'next/cache';
import { auth } from '@/lib/auth';
import { db } from '@/lib/db';

export async function addComment(postId: number, formData: FormData) {
  const session = await auth();
  if (!session) throw new Error('请先登录');           // 永远在服务端校验权限
  const text = String(formData.get('text') ?? '').trim();
  if (!text) return;                                   // 直接给 form 的 action，返回值会被丢弃
  await db.comment.create({ data: { postId, text, userId: session.user.id } });
  revalidatePath('/blog/[slug]', 'page');             // 让页面数据刷新
}
// 要把错误信息显示给用户：在客户端组件里用 useActionState，
// 此时函数签名改为 (prevState, formData)

// 在页面里使用（服务端组件中即可，不需要 'use client'）
<form action={addComment.bind(null, post.id)}>
  <textarea name="text" />
  <button>发表</button>
</form>
```

## 数据从哪里来？

| 我要做 | 用 |
|---|---|
| 页面的初始数据 | 服务端组件里直接查库或调用数据层函数 |
| 提交表单、修改数据 | Server Function（`'use server'`） |
| 给第三方或移动端提供接口 | Route Handler（`route.ts`） |
| 客户端高频交互（轮询、无限滚动） | TanStack Query |

<CallBox kind="warn" label="常见坑">

三条规则（后两条关系到安全）：

1. 服务端组件不要 `fetch` 自己的 API 路由。直接调用数据层函数，少一次网络往返。
2. 只能在服务端用的模块，加上 `import 'server-only'`。`NEXT_PUBLIC_` 开头的变量会发到浏览器，不要放密钥。
3. Server Function 收到的 formData 是不可信输入。先用 Zod 等工具校验，再写库。

</CallBox>

**登录与重定向**：会话放在 httpOnly cookie 里，在服务端校验，不要只在客户端判断。Next.js 16 起，原来的 `middleware.ts` 改名为 `proxy.ts`（导出函数 `proxy`），适合做“未登录就重定向”这类粗粒度拦截。但它只是第一道门：Proxy 的 matcher 漏掉某个路径时，该路径上的 Server Function 调用也会被跳过，所以权限仍要在每个 Server Function 里检查。登录本身建议用成熟的库，不要自己写。

缓存提示：在旧模型里，从 Next.js 15 起 `fetch` 默认**不缓存**，需要缓存时要明确写出来。新模型见下一节。

## 渲染策略：两种模型

Next.js 有两套缓存模型。从 16.4 起，`create-next-app` 新建的项目默认使用 **Cache Components**（`next.config.ts` 里的 `cacheComponents: true` 和 `partialPrefetching: true`）。官方文档说，下一个大版本会在所有项目里默认启用这两项功能，开关也会被移除。没开这个开关的老项目用后面的“旧模型”表。

### 新模型：Cache Components

同一页面可以混合三种内容：

| 内容 | 怎样处理 |
|---|---|
| 不依赖请求的内容 | 自动预渲染进静态外壳 |
| 用 `'use cache'` 缓存的内容（配合 `cacheLife('hours')`、`cacheTag('posts')`） | 缓存后进静态外壳 |
| 没缓存的数据，或 `cookies()`、`headers()`、`params`、`searchParams` 这类运行时数据 | 必须包在 `<Suspense>` 里，请求时流式返回 |

在新模型里，数据默认不缓存。在 Suspense 之外读取没缓存的数据，开发时会报错：`fetch(...)` 报 `Next.js encountered uncached data during prerendering`，读 `params`、`cookies()` 这类运行时数据报 `Next.js encountered runtime data during prerendering`。页面仍然能显示，浏览器右下角出现红色的 `1 Issue`。`loading.tsx` 就是一层 Suspense。读取 cookies 只影响它所在的 Suspense 区域，不会让整页变成动态。

### 缓存条目的生命周期

`'use cache'` 缓存的内容有三个时间（`cacheLife` 的 `stale`、`revalidate`、`expire`）。`stale` 管浏览器端的路由缓存，本课不展开。服务器上的数据缓存用另外两个：

- `revalidate`：条目的新鲜时长。超过它，条目就算过时。过时以后，下一个请求怎样拿到新内容，取决于缓存处理器。官方文档描述的是先给旧内容、后台重新生成（stale-while-revalidate）。但实测 Next.js 16.4.0 默认的内存缓存处理器不这样做：它把过了 `revalidate` 的条目当作不存在，下一个请求要等新内容生成。自己用 `next start` 部署时，用的就是这个默认处理器。
- `expire`：最长保留时间，必须比 `revalidate` 长。超过它，下一个请求要等新内容生成。

<CallBox kind="warn" label="常见坑">

`next dev` 的行为和上面不同：为了刷新快，开发服务器会一直把旧内容给出去，直到 `expire`，同时在后台重新生成。想验证缓存的时间线，要先 `npm run build`，再 `npm run start`。

</CallBox>

数据被改动后，可以按标签（`cacheTag('posts')`）让缓存过期。按 Next.js 16.4 的文档：

- `revalidateTag('posts', 'max')`：把带标签的内容标记为过期。下一个请求先拿到旧内容，同时后台重新生成。它能用在 Server Function 和 Route Handler 里。
- `updateTag('posts')`：只能用在 Server Function 里。内容立刻失效，下一个请求等待新内容，不会拿到旧内容。适合用户刚提交完、马上要看到自己的修改的场景。

```jsx play title="模拟：缓存、过期与重新验证"
// 模拟：一个 'use cache' 条目（cacheLife：revalidate 60 秒）的生命周期。时间靠手动拨快。
// 依据 Next.js 16.4.0 实测（next build + next start，默认的内存缓存处理器）：
// 过了 revalidate 的条目当作不存在，下一个请求等待新内容；
// revalidateTag(tag, 'max') 标记过期，下一个请求先拿旧内容，后台重新生成；updateTag(tag) 立即失效，下一个请求等待新内容。
// 与真实环境的差别：没有真实的服务器和渲染；只模拟服务器上的数据缓存，不含浏览器端路由缓存；
// 后台重新生成瞬间完成，新内容从下一次请求起可见；expire 在这里用不到（默认处理器在 revalidate 时就丢掉条目）。
import { useState } from 'react';

const REVALIDATE = 60;

function makeServer() {
  const s = { now: 0, version: 1, entry: null };
  s.request = () => {
    const e = s.entry;
    if (!e || s.now - e.createdAt >= REVALIDATE) {
      s.entry = { value: 'v' + s.version, createdAt: s.now, stale: false };
      return { shown: s.entry.value, how: '没有可用的缓存，等待新内容' };
    }
    if (e.stale) {
      s.entry = { value: 'v' + s.version, createdAt: s.now, stale: false };
      return { shown: e.value, how: '先返回旧内容，后台重新生成' };
    }
    return { shown: e.value, how: '命中缓存' };
  };
  s.revalidateTag = () => {
    if (s.entry) s.entry.stale = true;
  };
  s.updateTag = () => {
    s.entry = null;
  };
  s.editDatabase = () => {
    s.version += 1;
  };
  s.wait = seconds => {
    s.now += seconds;
  };
  return s;
}

// 一段脚本化的时间线
const s = makeServer();
const visit = () => {
  const r = s.request();
  console.log('第 ' + s.now + ' 秒，访问：显示 ' + r.shown + '（' + r.how + '）');
};
visit();
s.editDatabase(); // 数据库改成 v2
s.wait(30);
visit();
s.wait(40);
visit();
s.wait(10);
visit();
s.editDatabase(); // 数据库改成 v3
s.revalidateTag();
console.log('Server Function 调用了 revalidateTag');
visit();
visit();
s.editDatabase(); // 数据库改成 v4
s.updateTag();
console.log('Server Function 调用了 updateTag');
visit();

function App() {
  const [srv] = useState(makeServer);
  const [lines, setLines] = useState([]);
  const [, rerender] = useState(0);
  const act = (text, fn) => {
    const r = fn();
    setLines(l => [...l, r ? text + '：显示 ' + r.shown + '（' + r.how + '）' : text]);
    rerender(n => n + 1);
  };
  return (
    <div>
      <p>
        现在是第 {srv.now} 秒　数据库：v{srv.version}　缓存：{srv.entry ? srv.entry.value + (srv.entry.stale ? '（已标记过期）' : '') : '（空）'}
      </p>
      <button onClick={() => act('访问页面', () => srv.request())}>访问页面</button>{' '}
      <button onClick={() => act('过了 30 秒', () => srv.wait(30))}>过 30 秒</button>{' '}
      <button onClick={() => act('数据库被改动', () => srv.editDatabase())}>改数据库</button>{' '}
      <button onClick={() => act('revalidateTag', () => srv.revalidateTag())}>revalidateTag</button>{' '}
      <button onClick={() => act('updateTag', () => srv.updateTag())}>updateTag</button>
      <ul>{lines.map((l, i) => <li key={i}>{l}</li>)}</ul>
    </div>
  );
}
```

### 旧模型（没有开启 Cache Components 的项目）

| 策略 | 何时生成 HTML | 适合 |
|---|---|---|
| 静态（默认尽量静态） | 构建时 | 文档、博客、营销页 |
| 动态 | 每次请求时（读取了 cookies、headers、searchParams 等） | 个性化页面、仪表盘 |
| 增量更新 | 静态生成，过期或 revalidate 后重新生成 | 商品页、新闻 |
| 流式渲染 | 先发外壳，慢的部分通过 Suspense 稍后流入 | 有慢查询的页面 |

<CallBox kind="warn" label="常见坑">

最常见的错误是把整个页面都标成 `'use client'`。这样等于退回传统 SPA，服务端组件的好处全部失去。正确做法：页面和布局保持为服务端组件。只把需要交互的小部件拆成客户端组件，例如按钮、表单、下拉菜单。

</CallBox>

<CallBox kind="deep" label="深入一点">

你也可以选择其他框架。例如 React Router（框架模式）和 TanStack Start。它们的核心概念相同：**按路由组织代码；在服务端或路由层加载数据；用 action 提交表单**。学会一个，迁移到另一个很快。

</CallBox>

## 本机任务：跑一个 Next.js 项目

在你的电脑上做下面四步。照着做，对照表格自查。

1. 运行 `npx create-next-app@latest my-shop`，选择 `Yes, use recommended defaults`，再 `cd my-shop && npm run dev`，打开 `http://localhost:3000`。创建好的项目里，`next.config.ts` 已经有 `cacheComponents: true` 和 `partialPrefetching: true`，开发服务器启动时会打印 `Cache Components enabled`。
2. **动态路由**：新建 `app/shop/[id]/page.tsx`，用 `const { id } = await params` 读出 id 并显示。再新建 `app/shop/layout.tsx`，在 `{children}` 上方放一个标题。`params` 是运行时数据，直接在页面组件里 `await` 它，开发时浏览器右下角会出现红色的 `1 Issue`（`Route "/shop/[id]": Next.js encountered runtime data during prerendering`）。把读取 `params` 的部分拆成一个子组件，页面里用 `<Suspense fallback={<p>加载中…</p>}>` 包住它，问题就消失了。（想让一个页面整体阻塞渲染，可以加 `export const instant = false;`，这样同样不再报错。）
3. **Server Function 表单**：新建 `app/shop/[id]/actions.ts`（第一行 `'use server'`），导出一个函数，用 `formData.get('text')` 读出文字并 `console.log`。在页面里用 `<form action={…}>` 调用它。
4. **看 RSC payload**：在首页放一个 `<Link href="/shop/42">`，打开浏览器开发者工具的 Network 面板，点这个链接。

| 做什么 | 应该看到 |
|---|---|
| 访问 `/shop/42` | 页面显示 42；页面外面套着根布局和 `shop` 布局两层 |
| 在 `shop/layout.tsx` 里加一行 `console.log('layout')`，刷新页面 | 输出出现在运行 `npm run dev` 的终端：服务端组件在服务器上运行。开发模式还会把这条服务端日志转发到浏览器控制台，带着一个标签（例如 `Prerender`），它不是浏览器里的组件打印的 |
| 在 `page.tsx` 里写 `useState`，不加 `'use client'` | 页面报错，提示在服务端组件里不能使用。加上 `'use client'` 后恢复，再把它删掉（更好的做法是只拆出小的客户端组件） |
| 提交表单 | 终端输出你填的文字；页面没有整页刷新，Network 里多了一个发到当前页面地址的 POST 请求 |
| 点首页的 `Link` 去 `/shop/42` | Network 里出现一个 `/shop/42?_rsc=…` 的 `fetch` 请求，请求头里有 `rsc: 1`，返回的是文本格式的 RSC payload，不是整页 HTML。开发模式只有点击时这一个请求；`npm run build` 后用 `npm run start` 运行，页面一加载就会先出现带 `Next-Router-Prefetch` 头的预取请求。具体的请求形式随 Next.js 版本变化，以所用版本为准 |
