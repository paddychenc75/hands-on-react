# 实战一：完整的待办应用

<Warmup />

<LessonGoals />

<LessonProse>

这是课程的第一个实战项目，只用到本阶段学过的 state、事件、条件渲染、列表和表单。每个实战项目都有一份明确的**需求说明**，就像工作中产品经理给你的需求。检查程序会按需求逐条验收，就像测试同学一样操作你的应用。

## 需求说明

| 编号 | 需求 | 实现约定 |
|---|---|---|
| 1 | 输入框输入内容，点“添加”后新增一条待办，并清空输入框 | `<input id="new-todo">` 和文字为 **添加** 的按钮 |
| 2 | 输入为空或只有空格时不添加 |  |
| 3 | 每条待办有复选框，勾选后标记为完成，再点一次取消 | 每条是 `<li className="todo">`，完成时再加上 `done` 类名。用 `<label>` 包住复选框和文字 |
| 4 | 每条待办可以删除 | 每条里有文字为 **删除** 的按钮 |
| 5 | 可以按“全部 / 未完成 / 已完成”筛选 | 三个按钮，文字分别是 **全部**、**未完成**、**已完成** |
| 6 | 显示剩余未完成的数量 | `<p id="left">剩余 N 项</p>` |

## 动手前先设计

第 0 步：先把界面拆成组件。从需求表里画出一棵组件树，每个组件只做一件事：

```text
App                  持有 todos、text、filter 三个 state
├─ 输入区            输入框 + “添加”按钮
├─ 筛选按钮           全部 / 未完成 / 已完成
├─ 待办列表
│  └─ 待办项（每条）   复选框 + 文字 + “删除”按钮
└─ 剩余数量
```

本课的验收只检查页面，所以你可以把全部代码写在 `App` 里，也可以按这棵树拆成小组件。拆开时，哪个组件需要某个 state，就由它们的共同父组件持有，再用 props 传下去。

接着，先想清楚**最少需要哪些 state**，其余一切都应该是计算出来的：

- `todos`：数组，每项 `{ id, text, done }`
- `text`：输入框的内容
- `filter`：`'all' | 'active' | 'done'`
- **不需要**存“剩余数量”和“筛选后的列表”，它们都能由 todos 和 filter 算出来
