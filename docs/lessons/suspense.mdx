# Suspense、懒加载与错误边界

<LessonHeader />

<Warmup />

<LessonGoals />

<LessonProse>

真实应用总有“等待”和“失败”。React 提供了两个**声明式**工具：`Suspense` 处理等待，**错误边界**处理失败。它们都像 try/catch 一样作用于整棵子树。

## lazy + Suspense：按需加载组件

应用越大，打包出的 JS 越大，首屏越慢。`lazy` 让组件在**第一次被渲染时才去加载代码**。加载期间，最近的 `Suspense` 会显示 `fallback`。

```jsx
import { lazy, Suspense } from 'react';

// 构建工具会把 Chart 打包成单独的文件
const Chart = lazy(() => import('./Chart.js'));

function Dashboard() {
  return (
    <Suspense fallback={<p>图表加载中…</p>}>
      <Chart />
    </Suspense>
  );
}
```

```jsx play title="懒加载组件"
import { lazy, Suspense, useState } from 'react';

// 用延迟模拟网络加载一个组件文件
const HeavyChart = lazy(() => new Promise(resolve => {
  setTimeout(() => resolve({
    default: function HeavyChart() {
      return <div style={{ fontSize: 30 }}>📊📈📉 图表组件加载完成！</div>;
    }
  }), 1500);
}));

function App() {
  const [show, setShow] = useState(false);
  return (
    <div>
      <button onClick={() => setShow(true)}>显示图表</button>
      {show && (
        <Suspense fallback={<p>⏳ 正在加载图表代码…</p>}>
          <HeavyChart />
        </Suspense>
      )}
    </div>
  );
}
```

<CallBox kind="tip" label="要点">

Suspense 也可以用于**数据加载**。支持 Suspense 的工具有 Next.js、Relay、TanStack Query 和 React 19 的 `use()`。使用它们时，组件会“暂停”，直到数据准备好。你不需要在每个组件里写 `if (loading)`。注意：在 effect 或事件处理函数里请求数据，不会触发 Suspense。传给 `use()` 的 Promise 要缓存，不能在渲染时新建。

</CallBox>

<CallBox kind="deep" label="深入一点">

已经显示的内容再次挂起时（例如切换到一个还没加载的懒加载标签页），默认会被 fallback 替换。把这次 set 函数调用放进 `startTransition`，React 会保留旧界面，等新内容准备好再切换。下一课会讲 startTransition。

</CallBox>

## 错误边界：防止一个组件崩溃拖垮整个页面

如果某个组件在渲染时抛出错误，默认情况下**整个应用都会白屏**。错误边界可以捕获子树中的渲染错误，显示一个备用界面。目前错误边界**只能用 class 组件**编写。你也可以使用 react-error-boundary 库。

```jsx play title="错误边界隔离故障"
import { Component, useState } from 'react';

class ErrorBoundary extends Component {
  state = { error: null };

  static getDerivedStateFromError(error) {
    return { error };            // 更新 state，下次渲染显示备用界面
  }

  componentDidCatch(error, info) {
    console.log('上报错误：', error.message); // 可以发送到监控服务
  }

  render() {
    if (this.state.error) {
      return (
        <div style={{ background: '#fde8e8', padding: 10, borderRadius: 8 }}>
          😵 这个模块出错了：{this.state.error.message}
          <button onClick={() => this.setState({ error: null })}>重试</button>
        </div>
      );
    }
    return this.props.children;
  }
}

function BuggyCounter() {
  const [n, setN] = useState(0);
  if (n === 3) throw new Error('计数到 3 就崩溃了');
  return <button onClick={() => setN(n + 1)}>点到 3 会崩溃：{n}</button>;
}

function App() {
  return (
    <div>
      <ErrorBoundary><BuggyCounter /></ErrorBoundary>
      <ErrorBoundary><BuggyCounter /></ErrorBoundary>
    </div>
  );
}
```

<CallBox kind="warn" label="常见坑">

错误边界**不能**捕获以下错误：

1. 事件处理函数中的错误。用普通的 try/catch 处理。
2. 异步代码中的错误，例如 setTimeout 和普通的 Promise。
3. 服务端渲染中的错误。
4. 错误边界自身的错误。

它捕获**渲染期间**、生命周期和 effect 中的错误。React 19 中有两个例外：`startTransition` 里抛出的错误，以及 `use()` 读取的被拒绝的 Promise，也会被错误边界捕获。

</CallBox>

<CallBox kind="like" label="打个比方">

错误边界像电路里的保险丝。某个房间短路了，只有这个房间断电，整栋楼依然灯火通明。
