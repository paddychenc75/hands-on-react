# Suspense、懒加载与错误边界

<LessonHeader />

<Warmup />

<LessonGoals />

<LessonProse>

真实应用总有“等待”和“失败”。React 提供了两个**声明式**工具：`Suspense` 处理等待，**错误边界**处理失败。它们都像 try/catch 一样作用于整棵子树。

## lazy + Suspense：按需加载组件

应用越大，打包出的 JS 越大，首屏越慢。`lazy` 让组件在**第一次被渲染时才去加载代码**。加载期间，最近的 `Suspense` 会显示 `fallback`。

```jsx
import { lazy, Suspense } from 'react';

// 构建工具会把 Chart 打包成单独的文件
const Chart = lazy(() => import('./Chart.js'));

function Dashboard() {
  return (
    <Suspense fallback={<p>图表加载中…</p>}>
      <Chart />
    </Suspense>
  );
}
```

```jsx play title="懒加载组件"
import { lazy, Suspense, useState } from 'react';

// 用延迟模拟网络加载一个组件文件
const HeavyChart = lazy(() => new Promise(resolve => {
  setTimeout(() => resolve({
    default: function HeavyChart() {
      return <div style={{ fontSize: 30 }}>📊📈📉 图表组件加载完成！</div>;
    }
  }), 1500);
}));

function App() {
  const [show, setShow] = useState(false);
  return (
    <div>
      <button onClick={() => setShow(s => !s)}>显示/隐藏图表</button>
      {show && (
        <Suspense fallback={<p>⏳ 正在加载图表代码…</p>}>
          <HeavyChart />
        </Suspense>
      )}
    </div>
  );
}
```

<CallBox kind="tip" label="要点">

Suspense 也可以用于**数据加载**。支持 Suspense 的工具有 Next.js、Relay、TanStack Query 和 React 19 的 `use()`。使用它们时，组件会“暂停”，直到数据准备好，所以你不需要在每个组件里写 `if (loading)`。注意：在 effect 或事件处理函数里请求数据，不会触发 Suspense。

</CallBox>

## 用 use() 读取数据

`lazy` 等待的是组件的代码，而 `use()` 让组件等待数据。`use(promise)` 读取一个 Promise：没完成时，组件挂起，最近的 Suspense 显示 fallback。完成后，组件拿到结果，继续渲染。先看代码，再预测：

```jsx play title="use() 读取 Promise"
import { Suspense, use, useState } from 'react';

// 模拟网络请求：1 秒后返回。同一个 id 只创建一次 Promise
const cache = new Map();
function loadUser(id) {
  if (!cache.has(id)) {
    console.log('请求用户 ' + id);
    cache.set(id, new Promise(resolve => setTimeout(() => resolve('用户 ' + id + ' 的资料'), 1000)));
  }
  return cache.get(id);
}

function Profile({ id }) {
  const info = use(loadUser(id)); // Promise 没完成时，组件在这里挂起
  return <p>{info}</p>;
}

function App() {
  const [id, setId] = useState(1);
  return (
    <div>
      {[1, 2].map(n => <button key={n} onClick={() => setId(n)}>用户 {n}</button>)}
      <Suspense fallback={<p>⏳ 加载中…</p>}>
        <Profile id={id} />
      </Suspense>
    </div>
  );
}
```

`use()` 要求 Promise 在多次渲染之间是**同一个对象**。示例用 `Map` 缓存，同一个 id 只创建一次 Promise。如果在组件里直接写 `use(new Promise(…))` 或 `use(fetch(…))`，每次渲染都会得到新的 Promise，组件会一直挂起。

缓存的 Promise 完成以后，再读它不会挂起，所以点回“用户 1”能立刻显示。缓存怎么设计、出错怎么重试、怎样避免请求排成瀑布，见[Suspense 数据获取](/lessons/suspense-data)一课。

## 边界包在哪一层

Suspense 边界的位置，决定了页面怎样分批出现。下面的示例有两个组件，分别要 1 秒和 3 秒加载。勾选后，它们各包一个 Suspense。先预测，再对比两种情况：

```jsx play title="一个边界还是两个边界"
import { lazy, Suspense, useState, useMemo, useEffect } from 'react';

// 用延迟模拟网络加载一个组件文件
function makeLazy(name, ms) {
  return lazy(() => new Promise(resolve => {
    setTimeout(() => resolve({ default: () => <p>✅ {name} 已就绪</p> }), ms);
  }));
}

function App() {
  const [run, setRun] = useState(0);
  const [split, setSplit] = useState(false);
  const [sec, setSec] = useState('0.0');
  const [Fast, Slow] = useMemo(() => [makeLazy('文章（1 秒）', 1000), makeLazy('评论（3 秒）', 3000)], [run]);

  useEffect(() => {
    const t0 = Date.now();
    setSec('0.0');
    const id = setInterval(() => {
      const s = (Date.now() - t0) / 1000;
      setSec(s.toFixed(1));
      if (s >= 4) clearInterval(id);
    }, 100);
    return () => clearInterval(id);
  }, [run]);

  return (
    <div>
      <label><input type="checkbox" checked={split} onChange={e => setSplit(e.target.checked)} /> 各包一个 Suspense</label>
      <button onClick={() => setRun(run + 1)}>重新加载</button>
      <p>已过去 {sec} 秒</p>
      <div key={run}>
        {split ? (
          <>
            <Suspense fallback={<p>⏳ 文章加载中…</p>}><Fast /></Suspense>
            <Suspense fallback={<p>⏳ 评论加载中…</p>}><Slow /></Suspense>
          </>
        ) : (
          <Suspense fallback={<p>⏳ 加载中…</p>}>
            <Fast />
            <Slow />
          </Suspense>
        )}
      </div>
    </div>
  );
}
```

从示例可以总结出两条规则：

1. **同一个 Suspense 里的内容一起出现**，等最慢的那个。
2. 组件挂起时，**只有离它最近的 Suspense 显示 fallback**，外层不受影响。

怎样选边界：

- 应该一起出现的内容（标题和正文）放在同一个边界。
- 可以晚到的内容（评论、推荐）单独包一层。
- 错误边界同理：一个模块坏了，不该影响的部分，就不要和它放在同一个边界里。

在 React 19 中，组件挂起时，React 先让这个边界显示 fallback，再回头渲染同一边界里的兄弟组件，提前发起它们的加载。所以共用一个边界时，是同时开始加载，共等 3 秒，不是 4 秒。

<CallBox kind="tip" label="维护 React 18 项目时">

React 18 的顺序相反：先把同一边界里的兄弟组件都渲染一遍，再显示 fallback。加载也是同时开始的，所以等待时间相同，区别只在组件函数被调用的先后。

</CallBox>

## 挂起时用户看到什么

边界决定“哪一块显示 fallback”。这一节看三个细节：没有边界会怎样，fallback 显示多久，已经显示的内容再次挂起时怎样保持旧界面。

### 没有 Suspense 边界时

下面的 `Chart` 要 1.5 秒才加载完，它外面**没有** Suspense。先预测，再点“显示图表”：

```jsx play title="没有 Suspense 边界"
import { lazy, useState } from 'react';

// 模拟网络加载：1.5 秒后组件才到
const Chart = lazy(() => new Promise(resolve => {
  setTimeout(() => resolve({ default: () => <p>📊 图表加载完成</p> }), 1500);
}));

function App() {
  const [show, setShow] = useState(false);
  return (
    <div>
      <button onClick={() => setShow(true)}>显示图表</button>
      <p>页面的其他内容</p>
      {show && <Chart />}
    </div>
  );
}
```

在 React 19 中，点击引起的更新挂起，又找不到 Suspense 时，React 保持旧界面不变，等组件加载完再更新。用户在这 1.5 秒里看不到任何反馈，会以为点击没有反应。

如果是**首次挂载**时挂起，又没有 Suspense，整棵树什么也不显示，直到加载完成。所以懒加载组件外面总要包一个 Suspense，给用户一个等待提示。

<CallBox kind="tip" label="维护 React 18 项目时">

React 18 中，点击这类同步更新引起的挂起，如果没有 Suspense，会报错 “A component suspended while responding to synchronous input”，并清空界面。

</CallBox>

### fallback 至少显示约 300 毫秒

数据很快就到了，fallback 是不是一闪而过？先看代码：数据 50 毫秒就返回。控制台会打印每个阶段的时刻。

```jsx play title="fallback 的最短显示时间"
import { Suspense, use, useEffect } from 'react';

const t0 = performance.now();
const ms = () => Math.round(performance.now() - t0);

// 模拟请求：50 毫秒就返回
const promise = new Promise(resolve => setTimeout(() => resolve('数据到了'), 50));

function Loading() {
  useEffect(() => {
    console.log('fallback 显示出来 @' + ms() + ' ms');
    return () => console.log('fallback 被替换 @' + ms() + ' ms');
  }, []);
  return <p>⏳ 加载中…</p>;
}

function Content() {
  const text = use(promise);
  useEffect(() => { console.log('内容显示出来 @' + ms() + ' ms'); }, []);
  return <p>{text}</p>;
}

function App() {
  return (
    <Suspense fallback={<Loading />}>
      <Content />
    </Suspense>
  );
}
```

fallback 一旦显示出来，React 会让它至少停留约 300 毫秒，再换成内容。这是为了避免界面一闪而过。数据到得更晚时，一到就显示。

### 切换时保留旧界面：startTransition

已经显示的内容再次挂起时（例如切到一个还没加载的页面），默认会被 fallback 替换。把这次 set 函数调用放进 `startTransition`，React 会保留旧界面，等新内容准备好再切换，同时 `isPending` 为 true。`startTransition` 在[并发特性](/lessons/concurrent)一课学过，这里用它解决 Suspense 的一个具体问题。

```jsx play title="切换时保留旧界面"
import { Suspense, use, useState, useTransition } from 'react';

// 模拟请求：每页 1 秒，同一页只请求一次
const cache = new Map();
function loadPage(id) {
  if (!cache.has(id)) {
    cache.set(id, new Promise(resolve => setTimeout(() => resolve('第 ' + id + ' 页的内容'), 1000)));
  }
  return cache.get(id);
}

function Page({ id }) {
  return <p>{use(loadPage(id))}</p>;
}

function App() {
  const [id, setId] = useState(1);
  const [useT, setUseT] = useState(true);
  const [isPending, startTransition] = useTransition();

  function next() {
    if (useT) startTransition(() => setId(id + 1));
    else setId(id + 1);
  }

  return (
    <div>
      <label><input type="checkbox" checked={useT} onChange={e => setUseT(e.target.checked)} /> 用 startTransition 切换</label>
      <p><button onClick={next}>下一页</button> {isPending && <small>切换中…</small>}</p>
      <Suspense fallback={<p>⏳ 加载中…</p>}>
        <Page id={id} />
      </Suspense>
    </div>
  );
}
```

## 错误边界：防止一个组件崩溃拖垮整个页面

如果某个组件在渲染时抛出错误，默认情况下**整个应用都会白屏**。错误边界可以捕获子树中的渲染错误，显示一个备用界面。目前错误边界**只能用 class 组件**编写，你也可以使用 react-error-boundary 库。

<CallBox kind="deep" label="五分钟读懂 class 组件">

新代码不写 class。错误边界是唯一的例外，所以先看懂它的语法。class 组件和函数组件对照如下：

| class 组件 | 函数组件里的对应 |
|---|---|
| `this.props` | 函数的参数 `props` |
| `state = { … }` 和 `this.state` | `useState` 的值 |
| `this.setState({ … })` | set 函数 |
| `render()` 的返回值 | 函数体的返回值 |
| `componentDidMount`、`componentDidUpdate`、`componentWillUnmount` | effect 的开始、更新和清理 |
| `static getDerivedStateFromError(error)` | 没有对应的 Hook：只有 class 能写 |

`static` 方法属于类本身，不属于实例，所以它读不到 `this.props` 和 `this.state`。React 在子树抛出错误时调用它，用它返回的对象更新 state。

</CallBox>

```jsx play title="错误边界隔离故障"
import { Component, useState } from 'react';

class ErrorBoundary extends Component {
  state = { error: null };

  static getDerivedStateFromError(error) {
    return { error };            // 更新 state，下次渲染显示备用界面
  }

  componentDidCatch(error, info) {
    console.log('上报错误：', error.message); // 可以发送到监控服务
  }

  render() {
    if (this.state.error) {
      return (
        <div style={{ background: '#fde8e8', padding: 10, borderRadius: 8 }}>
          😵 这个模块出错了：{this.state.error.message}
          <button onClick={() => this.setState({ error: null })}>重试</button>
        </div>
      );
    }
    return this.props.children;
  }
}

function BuggyCounter() {
  const [n, setN] = useState(0);
  if (n === 3) throw new Error('计数到 3 就崩溃了');
  return <button onClick={() => setN(n + 1)}>点到 3 会崩溃：{n}</button>;
}

function App() {
  return (
    <div>
      <ErrorBoundary><BuggyCounter /></ErrorBoundary>
      <ErrorBoundary><BuggyCounter /></ErrorBoundary>
    </div>
  );
}
```

<CallBox kind="warn" label="常见坑">

错误边界**不能**捕获以下错误：

1. 事件处理函数中的错误。用普通的 try/catch 处理。
2. 异步代码中的错误，例如 setTimeout 和普通的 Promise。
3. 服务端渲染中的错误。
4. 错误边界自身的错误。

错误边界捕获**渲染期间**、生命周期和 effect 中的错误。React 19 中有两个例外：传给 `useTransition` 返回的 `startTransition` 的函数抛出的错误（包括它返回的 Promise 被拒绝），以及 `use()` 读取的被拒绝的 Promise，会被错误边界捕获。从 react 直接导入的 `startTransition` 没有这个行为：错误成为未捕获的错误。下面的示例对比这两种写法。

</CallBox>

```jsx play title="过渡里抛出的错误"
import { Component, useTransition, startTransition } from 'react';

class ErrorBoundary extends Component {
  state = { error: null };
  static getDerivedStateFromError(error) {
    return { error };
  }
  render() {
    if (this.state.error) return <p>🛟 边界接住了：{this.state.error.message}</p>;
    return this.props.children;
  }
}

function Actions() {
  const [isPending, start] = useTransition();
  return (
    <p>
      <button onClick={() => start(() => { throw new Error('来自 Hook 的 start'); })}>按钮 A：Hook 返回的 start</button>
      <button onClick={() => startTransition(() => { throw new Error('来自直接导入的 startTransition'); })}>按钮 B：直接导入的</button>
    </p>
  );
}

function App() {
  return (
    <ErrorBoundary>
      <Actions />
    </ErrorBoundary>
  );
}
```

用 `use()` 读取的 Promise 被拒绝时，错误同样交给最近的错误边界。所以“请求失败”也可以和渲染错误一样，用一个边界统一处理。

<CallBox kind="like" label="打个比方">

错误边界像电路里的保险丝。某个房间短路了，只有这个房间断电，整栋楼依然灯火通明。

</CallBox>
