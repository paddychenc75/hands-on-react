# 实战三：看板应用

看板（Kanban）把任务分成三列：待办、进行中、已完成。卡片可以在列之间移动。Trello、Jira、飞书项目都是这种形态。

这个项目的界面已经写好了，你的任务是实现最核心的**状态逻辑**：一个 reducer。真实团队经常这样分工：组件只负责显示和派发 action，所有规则集中在 reducer 里，可以单独测试。

## 状态设计

```jsx
const initialState = {
  columns: ['todo', 'doing', 'done'],
  cards: [
    { id: 1, title: '设计数据结构', col: 'todo' },
    { id: 2, title: '写 reducer', col: 'todo' },
  ],
  nextId: 3,
};
// 每张卡片只记录它在哪一列（col），列里有哪些卡片由 filter 计算得出
```

## 需要实现的 action

| action | 效果 |
|---|---|
| `{ type: 'add', title }` | 在“待办”列新增一张卡片。title 去掉首尾空格后为空则忽略 |
| `{ type: 'move', id, dir: 1 }` | 把卡片移到右边一列；已在最右列则不变 |
| `{ type: 'move', id, dir: -1 }` | 把卡片移到左边一列；已在最左列则不变 |
| `{ type: 'remove', id }` | 删除卡片 |

## 界面怎样拿到 dispatch

App 用 `useReducer` 得到 `state` 和 `dispatch`。界面有三层：App → Column → Card。派发 action 的按钮在最里面的 Card 上。

不用 Context 时，App 要把回调传给 Column，Column 再原样转发给 Card。移动、删除各一个回调，每一层都要多写几个 props。

用 Context，只要三步：

1. 创建 `DispatchCtx`。
2. App 把 `dispatch` 放进 `<DispatchCtx value={dispatch}>`。
3. Card 调用 `useContext(DispatchCtx)`，直接得到 `dispatch`。中间的 Column 不需要知道它。

```jsx title="界面代码里已经写好的接线（只读）"
const DispatchCtx = createContext(null);

// App 里
<DispatchCtx value={dispatch}>{/* …列和卡片… */}</DispatchCtx>

// Card 里
const dispatch = useContext(DispatchCtx);
dispatch({ type: 'remove', id: card.id });
```

`dispatch` 的引用在组件的整个生命周期内不变，所以这个 Context 的 value 不会变，读取者不会因此重新渲染。这是把 `dispatch` 放进 Context 比较安全的原因。第 12 课说过 reducer 可以和 Context 组合，这里就是一个完整的例子。

<CallBox kind="tip" label="要点">

移动卡片的步骤：

1. 找到卡片当前列在 `columns` 中的下标。
2. 下标加上 `dir`。
3. 新下标在 0 到 2 之间时，更新 `col`。

</CallBox>

<CallBox kind="deep" label="深入一点">

应用变大后，这个 reducer 几乎不用修改，可以直接迁移到 Zustand 或 Redux Toolkit。这说明一个观点：**先把状态逻辑写成纯函数，用什么库只是“接线”问题**。第 29 课《状态管理架构》和第 45 课会展开讲。<br />严格模式（`<StrictMode>`）是 React 提供的开发环境检查工具。开启后，React 会把 reducer 这类应该是纯函数的代码调用两次，用来暴露副作用。如果 reducer 修改了原 state，卡片就会被加两次。生产环境不会这样。

</CallBox>

想在自己电脑上跑这个应用？可以先跳到《[项目搭建与工具链](/lessons/engineering)》的前三节（创建项目、目录结构、拆成多个文件），把代码搬到本地的 Vite 项目里，做完再回来。这是可选的，不影响本课的验收。

<CallBox kind="tip" label="维护 React 18 项目时">

React 18 及更早的版本里，要写 `<DispatchCtx.Provider value={dispatch}>`。React 19 仍然支持这种写法。

</CallBox>
