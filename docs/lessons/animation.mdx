# 动画与过渡

<LessonHeader />

<Warmup />

<LessonGoals />

<LessonProse>

界面变化时，元素凭空出现或消失，用户很难看出“发生了什么”。适度的动画能说明变化的来龙去脉：这张卡片从哪里来，那个按钮去了哪里。

这一课主要用浏览器自带的能力加 React 自带的能力。React 的任务只有一件：**在正确的时刻，让正确的元素处在正确的状态**。动画本身由浏览器执行。

<CallBox kind="tip" label="这一课用到的浏览器能力（截至 2026 年 10 月）">

| 能力 | 支持情况 |
|---|---|
| CSS 过渡、`transform`、`opacity` | 所有浏览器 |
| `@starting-style` | 2024 年 8 月起，所有主流浏览器的最新版本都支持（MDN 标为 Baseline 2024） |
| View Transition API（同一文档内） | Chrome / Edge 111、Safari 18、Firefox 144（2025 年 10 月 14 日起）。MDN 和 web-features 标为“新近可用”（Baseline 2025） |

`<ViewTransition>` 从 React 19.3 起是稳定 API，本站的实验台就是 19.3.0。浏览器版本更旧时，动画不会出现，界面照常更新（第 3 节会实测）。

</CallBox>

## 1. 状态驱动的 CSS 过渡

**CSS 过渡**（transition）：某个 CSS 属性的值变了，浏览器在一段时间里逐帧补出中间值。你只写“哪个属性、多久”，不写每一帧。

React 里的做法很直接：让 state 决定类名（或内联 `style`），过渡由浏览器完成。

```jsx
// 抽屉一直在 DOM 里，open 只改类名
<aside className={open ? 'drawer open' : 'drawer'} />
```

```css
.drawer { transform: translateX(-100%); transition: transform 300ms; }
.drawer.open { transform: none; }
```

过渡需要两个值：变化**前**的值和变化**后**的值。所以元素必须在两次渲染之间一直留在 DOM 里。条件渲染破坏了这一点：

- **离场**：`{open && <Card />}` 变成 `false` 时，React 马上把节点从 DOM 里删掉。没有“变化后”的值，过渡无从开始。
- **入场**：新挂载的节点第一次计算样式，没有“变化前”的值，也不会播放过渡。

下面的卡片设置了 `transition: opacity 400ms`，并用 `@starting-style` 指定“刚挂载时的样式”。`@starting-style` 是 CSS 规则：元素第一次出现时，浏览器先用这里的值作为起点，再过渡到正常样式。

```jsx play title="条件渲染：入场有动画，离场没有"
import { useState } from 'react';

function App() {
  const [open, setOpen] = useState(false);

  function toggle() {
    setOpen(!open);
    // 下一帧时，卡片还在不在 DOM 里？
    requestAnimationFrame(() => {
      console.log('下一帧：卡片' + (document.querySelector('.card') ? '还在 DOM 里' : '已经不在 DOM 里'));
    });
  }

  return (
    <div>
      <style>{`
        .card { padding: 12px; background: #cfe8f3; color: #0f1d24; border-radius: 6px; transition: opacity 400ms; }
        @starting-style { .card { opacity: 0; } }
      `}</style>
      <button onClick={toggle}>{open ? '关闭' : '打开'}</button>
      {open && <p className="card">我是一张卡片</p>}
    </div>
  );
}
```

## 2. 入场与离场

**入场**有两种常用写法：

1. `@starting-style`：上面用的就是它。最简单，不需要 JS。
2. 挂载后再改类名：先用“隐藏”样式渲染，等浏览器真的画过一帧，再把类名换成“显示”。只在一次 effect 里立刻改类名**不够**，浏览器还没算过初始样式。实测中，只等一层 `requestAnimationFrame` 时，第一次打开没有动画；等两层才稳定。

**离场**要换思路：React 不能立刻卸载，要先让元素留在 DOM 里播放动画，播完再卸载。三种办法：

| 办法 | 做法 | 适合 | 边界 |
|---|---|---|---|
| 先播放再卸载 | 用状态机延后卸载，离场期间加“离场类名” | 单个元素的显隐，弹窗、提示条 | 要自己处理打断和兜底 |
| `<Activity>` 加 CSS | `mode="hidden"` 隐藏界面并保留 state | 需要保留输入内容的标签页 | `hidden` 会立刻给子树加 `display: none !important`，CSS 过渡来不及播放。要动画得再配合状态机或 `<ViewTransition>` |
| `<ViewTransition>` | 浏览器给新旧界面截图并做动画（第 3 节） | 页面、列表、共享元素 | 必须放进过渡更新 |

先看状态机。**状态机**：用一个有限的状态集合描述“现在处在哪一步”，每个事件只允许某几种转换。这里有四个状态：

```text
gone ──show──▶ entering ──下一帧──▶ entered
                              │  ▲
                         hide │  │ show（打断，取消离场）
                              ▼  │
gone ◀─动画结束或超时─ leaving ──┘
```

```jsx play title="先播放离场动画，再卸载"
import { useState, useEffect } from 'react';

function usePresence(show, fallbackMs = 500) {
  const [phase, setPhase] = useState('gone'); // gone | entering | entered | leaving

  // 根据 show 推进状态（在渲染中调整自己的 state）
  if (show && phase === 'gone') setPhase('entering');
  else if (show && phase === 'leaving') setPhase('entered');
  else if (!show && (phase === 'entering' || phase === 'entered')) setPhase('leaving');

  useEffect(() => {
    console.log('阶段：' + phase);
  }, [phase]);

  // 入场：渲染出“隐藏”样式，等两帧后再切到“显示”
  useEffect(() => {
    if (phase !== 'entering') return;
    let id = requestAnimationFrame(() => {
      id = requestAnimationFrame(() => setPhase('entered'));
    });
    return () => cancelAnimationFrame(id);
  }, [phase]);

  // 离场兜底：过渡事件没来，也要卸载
  useEffect(() => {
    if (phase !== 'leaving') return;
    const timer = setTimeout(() => setPhase('gone'), fallbackMs);
    return () => clearTimeout(timer);
  }, [phase, fallbackMs]);

  // 过渡事件会从子元素冒泡上来，只认自己
  function onTransitionEnd(e) {
    if (e.target === e.currentTarget && phase === 'leaving') setPhase('gone');
  }

  return { mounted: phase !== 'gone', phase, onTransitionEnd };
}

function App() {
  const [show, setShow] = useState(false);
  const { mounted, phase, onTransitionEnd } = usePresence(show);
  return (
    <div>
      <style>{`
        .sheet { padding: 12px; background: #cfe8f3; color: #0f1d24; border-radius: 6px;
               opacity: 0; transform: translateY(-8px); transition: opacity 600ms, transform 600ms; }
        .sheet[data-phase='entered'] { opacity: 1; transform: none; }
      `}</style>
      <button onClick={() => setShow(!show)}>{show ? '关闭' : '打开'}</button>
      {mounted && (
        <p className="sheet" data-phase={phase} onTransitionEnd={onTransitionEnd}>
          当前阶段：{phase}
        </p>
      )}
    </div>
  );
}
```

这个写法要处理三个边界：

- **被打断**：离场到一半时用户又点“打开”。状态机从 `leaving` 回到 `entered`，兜底定时器随 effect 清理而取消。如果漏了清理，旧定时器会在“已经重新打开”之后把元素卸载。
- **快速连点**：每次点击只是改 `show`，状态由上面三条规则决定，不会停在不存在的状态。
- **`transitionend` 不触发**：属性值没有真的变化、元素被 `display: none`、标签页在后台、用户设置了“减少动画”而你把时长改成 0，都会这样。没有兜底，元素会永远留在 DOM 里。兜底时间取比动画稍长即可。

## 3. `<ViewTransition>`

**View Transition API** 是浏览器的功能：先给旧界面截一张图，再让页面更新到新界面，然后在两张图之间做动画。**`<ViewTransition>`** 是 React 对它的封装：你标出哪些部分要动，React 在合适的时机调用浏览器 API。

React 根据这次更新里这块内容发生了什么，自动选一种动画：

| 类型 | 什么时候 |
|---|---|
| enter | `<ViewTransition>` 在这次更新里被插入 |
| exit | `<ViewTransition>` 在这次更新里被移除 |
| update | 它里面的内容、大小或位置变了 |
| share | 一个有 `name` 的在被移除的内容里，另一个同名的在被插入的内容里：元素从旧位置移到新位置 |

关键规则：**只有过渡更新会触发动画**。`startTransition`、`useDeferredValue` 引发的更新，以及 Suspense 揭示内容，才会动。直接 `setShow(...)` 是紧急更新，界面要立刻反映，所以没有动画。`onEnter`、`onExit` 在 React 真的为这次更新启动动画时才会调用，下面用它们来观察。

```jsx play title="ViewTransition：放不放进 startTransition"
import { ViewTransition, startTransition, useState } from 'react';

function App() {
  const [show, setShow] = useState(false);
  return (
    <div>
      <button onClick={() => setShow(!show)}>普通 setState 切换</button>
      <button onClick={() => startTransition(() => setShow(!show))}>startTransition 切换</button>
      {show && (
        <ViewTransition
          onEnter={() => console.log('动画开始：进入')}
          onExit={() => console.log('动画开始：离开')}
        >
          <p style={{ padding: 12, background: '#cfe8f3', color: '#0f1d24', borderRadius: 6 }}>我会淡入淡出吗？</p>
        </ViewTransition>
      )}
    </div>
  );
}
```

用法上还有四条规则：

1. `<ViewTransition>` 要放在被插入或移除的内容的**最外层**，它上面不能再有 DOM 节点。`{show && <div><ViewTransition>…</ViewTransition></div>}` 里，进入的是外层 `div`，里面的 `<ViewTransition>` 不会触发 enter 或 exit（实测）。
2. 动画以**截图**为单位：整块内容一起淡入淡出或移动，不是里面每个子元素各自动。
3. `name` 在同一时刻必须唯一。两个同名的同时挂载，浏览器放弃整次动画。
4. 不要自己调用 `document.startViewTransition`，React 会调用它；`flushSync` 会取消当次过渡动画。

用 CSS 定制动画：给 `enter`、`exit`、`update`、`share` 传一个类名，React 把它加到浏览器的伪元素上，你用 `::view-transition-old(.类名)` 和 `::view-transition-new(.类名)` 写动画。旧内容是 `old`，新内容是 `new`。

```jsx
<ViewTransition enter="slide-in" exit="fade-out">
  <Panel />
</ViewTransition>
```

```css
::view-transition-old(.fade-out) { animation: 200ms ease-out fade-out; }
::view-transition-new(.slide-in) { animation: 300ms ease-out slide-in; }
```

`default="none"` 表示没有列出的触发方式都不动。需要在 JS 里控制动画时，用 `onEnter`、`onExit`、`onUpdate`、`onShare`，它们拿到旧、新伪元素，用 Web Animations API 自己播放，并返回清理函数。

**浏览器不支持时**：React 检测到没有 `document.startViewTransition`，更新照常发生，只是没有动画，也不报错（我们在实验台里删掉这个函数实测过）。所以动画只能当作“锦上添花”，不能承载信息。

同一个状态变化，有时需要不同的动画，例如轮播的“下一张”和“上一张”。在过渡里调用 `addTransitionType` 标明原因，再让 `enter`、`exit` 按类型选类名：

```jsx
import { ViewTransition, addTransitionType, startTransition } from 'react';

function next() {
  startTransition(() => {
    addTransitionType('next');
    setIndex(i => i + 1);
  });
}

<ViewTransition enter={{ next: 'from-right', previous: 'from-left', default: 'auto' }}>
  <Slide />
</ViewTransition>;
```

## 4. 列表与布局动画

列表增删、排序时，元素要“滑”到新位置，而不是跳过去。

**用 `<ViewTransition>`**：给列表里**每一项**包一个带 `key` 的 `<ViewTransition>`，重排时每项是一次 update 动画。如果只在整个列表外面包一层，整个列表会作为一个整体淡入淡出。图片这类要在两个页面之间“变形”的元素，给两端的 `<ViewTransition>` 同一个 `name`，就是共享元素。

```jsx play title="相册：共享元素与列表重排"
import { ViewTransition, startTransition, useState } from 'react';

const PICS = [
  { id: 1, color: '#e8a087' },
  { id: 2, color: '#87b8e8' },
  { id: 3, color: '#a6d49f' },
  { id: 4, color: '#e8d487' },
];

function App() {
  const [pics, setPics] = useState(PICS);
  const [openId, setOpenId] = useState(null);
  const open = pics.find(p => p.id === openId);
  // 所有更新都放进过渡更新
  const go = fn => startTransition(fn);

  return (
    <div>
      <style>{`
        ::view-transition-group(.slow) { animation-duration: 600ms; }
        .grid { display: flex; gap: 8px; margin-top: 8px; }
        .thumb, .big { border: 0; border-radius: 8px; cursor: pointer; color: #0f1d24; }
        .thumb { width: 70px; height: 70px; }
        .big { display: block; width: 100%; height: 180px; }
      `}</style>
      {open ? (
        <ViewTransition name={'pic-' + open.id} share="slow">
          <button className="big" style={{ background: open.color }} onClick={() => go(() => setOpenId(null))}>
            点我返回
          </button>
        </ViewTransition>
      ) : (
        <div>
          <button onClick={() => go(() => setPics(list => [...list].reverse()))}>反转顺序</button>
          <div className="grid">
            {pics.map(p => (
              <ViewTransition key={p.id} name={'pic-' + p.id} update="slow" share="slow">
                <button className="thumb" style={{ background: p.color }} onClick={() => go(() => setOpenId(p.id))}>
                  {p.id}
                </button>
              </ViewTransition>
            ))}
          </div>
        </div>
      )}
    </div>
  );
}
```

**FLIP**：`<ViewTransition>` 之前，业界用 FLIP 手写位移动画。四步：

1. **F**irst：更新前，量每个元素的位置。
2. **L**ast：更新后（DOM 已变，浏览器还没画），再量一次。
3. **I**nvert：算出差值，先用 `transform` 把元素“反向推回”旧位置，看起来没动。
4. **P**lay：去掉 `transform` 并加过渡，元素就滑向新位置。

React 里，第 2 步必须在 `useLayoutEffect` 里做，它在浏览器绘制前运行，用户看不到“先跳一下”。下面用 Web Animations API 把第 3、4 步合成一次 `animate`：

```jsx play title="FLIP：自己量位置，再反向变换"
import { useState, useRef, useLayoutEffect } from 'react';

function FlipList({ items }) {
  const nodes = useRef(new Map()); // key -> DOM 节点
  const lastTop = useRef(new Map()); // key -> 上一次的 offsetTop

  useLayoutEffect(() => {
    nodes.current.forEach((el, key) => {
      const top = el.offsetTop; // Last：布局位置，不受 transform 和页面滚动影响
      const before = lastTop.current.get(key); // First：上一次记下的
      if (before !== undefined && before !== top) {
        // Invert + Play：从“旧位置的偏移”播放到“没有偏移”
        el.animate([{ transform: `translateY(${before - top}px)` }, { transform: 'none' }], { duration: 400, easing: 'ease' });
      }
      lastTop.current.set(key, top);
    });
    for (const key of lastTop.current.keys()) {
      if (!nodes.current.has(key)) lastTop.current.delete(key);
    }
  });

  return (
    <ul style={{ position: 'relative', padding: 0, margin: '8px 0' }}>
      {items.map(x => (
        <li
          key={x}
          ref={el => {
            if (el) nodes.current.set(x, el);
            else nodes.current.delete(x);
          }}
          style={{ listStyle: 'none', padding: 8, marginBottom: 4, background: '#cfe8f3', color: '#0f1d24', borderRadius: 6 }}
        >
          条目 {x}
        </li>
      ))}
    </ul>
  );
}

function App() {
  const [items, setItems] = useState(['A', 'B', 'C', 'D']);
  return (
    <div>
      <button onClick={() => setItems(list => [...list].reverse())}>反转</button>
      <button onClick={() => setItems(list => list.slice(1))}>删除第一项</button>
      <button onClick={() => setItems(list => [String.fromCharCode(65 + list.length + Math.floor(Math.random() * 20)), ...list])}>在前面加一项</button>
      <FlipList items={items} />
    </div>
  );
}
```

这个最小实现只处理垂直位移，被删除的项没有离场动画，动画被打断时会从旧位置“跳”一下重新开始。所以**多数情况不值得自己写**：支持 View Transition 的浏览器用 `<ViewTransition>`；要处理拖拽排序、离场和中途打断，用动画库（第 6 节）。FLIP 值得懂，是因为 `<ViewTransition>` 和动画库的布局动画，底层也是同一个思路：先量，再反向推，再放开。

## 5. 性能与无障碍

**只动 `transform` 和 `opacity`。** 浏览器渲染一帧要经过样式、布局、绘制、合成几步。改 `transform` 和 `opacity` 只影响最后的合成，可以交给合成器（独立于主线程）处理。改 `width`、`height`、`top`、`margin` 会让浏览器重新计算布局，可能连带整个页面的元素，每一帧都在主线程上做。

下面的页面有 8000 个元素。示例分别用 `transform` 和 `margin-left` 动画同一个方块，每一帧读一次 `offsetHeight`（读它会强制浏览器先算完布局），统计每帧耗时的中位数。比较时看**相对差距**，绝对毫秒数因设备而异。

```jsx play title="只动 transform：每帧的布局代价"
import { useState, useRef } from 'react';

const CELLS = Array.from({ length: 8000 }, (_, i) => i);

// 用 Web Animations API 播放 ms 毫秒，每帧强制一次布局，返回耗时中位数
function measure(box, grid, keyframes, ms) {
  return new Promise(resolve => {
    const anim = box.animate(keyframes, { duration: ms, iterations: Infinity, direction: 'alternate' });
    const costs = [];
    const start = performance.now();
    function tick() {
      const t0 = performance.now();
      grid.offsetHeight; // 读取会强制布局
      costs.push(performance.now() - t0);
      if (performance.now() - start < ms) requestAnimationFrame(tick);
      else {
        anim.cancel();
        const sorted = costs.slice(5).sort((a, b) => a - b);
        resolve(sorted[sorted.length >> 1]);
      }
    }
    requestAnimationFrame(tick);
  });
}

function App() {
  const [result, setResult] = useState(null);
  const [busy, setBusy] = useState(false);
  const boxRef = useRef(null);
  const gridRef = useRef(null);

  async function run() {
    setBusy(true);
    const box = boxRef.current;
    const grid = gridRef.current;
    const a = await measure(box, grid, [{ transform: 'translateX(0)' }, { transform: 'translateX(40px)' }], 1000);
    const b = await measure(box, grid, [{ marginLeft: '0px' }, { marginLeft: '40px' }], 1000);
    setResult({ a, b });
    setBusy(false);
  }

  return (
    <div>
      <button onClick={run} disabled={busy}>{busy ? '测量中，约 2 秒…' : '开始测量'}</button>
      {result && (
        <p>
          每帧强制布局的耗时中位数：transform {result.a.toFixed(2)} ms；margin-left {result.b.toFixed(2)} ms
        </p>
      )}
      <div ref={gridRef} style={{ display: 'flex', flexWrap: 'wrap', overflow: 'hidden', height: 60 }}>
        <div ref={boxRef} style={{ width: 30, height: 30, background: 'coral' }} />
        {CELLS.map(i => <span key={i} style={{ width: 20, height: 10, flex: '1 0 20px' }} />)}
      </div>
    </div>
  );
}
```

另外三条性能规则：

- **不要每帧调用 set 函数来做动画。** 用 `setState` 逐帧更新位置，每一帧都要重新渲染，会和用户交互抢主线程。让浏览器的 CSS 过渡或 Web Animations API 去动，React 只管开始和结束。
- **动画期间不要锁住交互。** 不要在动画结束前禁用按钮或忽略点击。`<ViewTransition>` 播放时，点击仍会落到下面真实的元素上（在 Chromium 里实测），用户可以在动画中继续操作。动画要短，一般 200–500 毫秒；用户连续操作时，让新的动画接管旧的，不要排队等。

**无障碍**要在[无障碍](/lessons/accessibility)一课的基础上多注意三件事。

**第一，尊重“减少动画”。** 用户在系统里打开“减少动态效果”后，浏览器的媒体查询 `prefers-reduced-motion: reduce` 为真。React **不会**自动关掉你的动画（实测：打开这个设置后，`<ViewTransition>` 的动画照常播放），要自己处理。CSS 动画用媒体查询；`<ViewTransition>` 的伪元素也一样：

```css
@media (prefers-reduced-motion: reduce) {
  ::view-transition-group(*),
  ::view-transition-old(*),
  ::view-transition-new(*) {
    animation: none !important;
  }
}
```

JS 里决定“要不要播”（例如上面的 `usePresence` 要不要延后卸载）时，需要读这个设置，并在用户中途改设置时更新。`matchMedia` 的结果会变化，是一个“外部存储”，正好用 `useSyncExternalStore` 订阅：

```jsx
import { useSyncExternalStore } from 'react';

const QUERY = '(prefers-reduced-motion: reduce)';

function subscribe(onChange) {
  const media = window.matchMedia(QUERY);
  media.addEventListener('change', onChange);
  return () => media.removeEventListener('change', onChange);
}

export function usePrefersReducedMotion() {
  return useSyncExternalStore(
    subscribe,
    () => window.matchMedia(QUERY).matches, // 浏览器里的值
    () => false, // 服务端渲染时没有 window，先当作“没有设置”
  );
}
```

“减少动画”不等于“没有动画”。大幅的位移、缩放和视差会引发不适，要去掉；短暂的淡入淡出一般可以保留。

**第二，焦点和朗读不依赖动画是否播完。** 离场的元素在动画期间仍在 DOM 里，键盘焦点还可能停在里面，读屏软件也还能读到它。离场开始就给它加 `inert` 属性（React 里写 `inert={leaving}`）：它不再能被聚焦、点击或朗读。需要的话，把焦点同时移回触发它的按钮。

**第三，信息不要只靠动画传达。** 不支持动画的浏览器、关闭了动画的用户，看到的是最终状态，状态本身必须清楚。

## 6. 怎样选

| 你要做的事 | 用什么 |
|---|---|
| 简单的显隐、展开、悬停变色 | CSS 过渡，元素一直在 DOM 里 |
| 元素入场 | `@starting-style` |
| 元素离场，且只有这一处 | 状态机（`usePresence`），带超时兜底 |
| 离场，且要保留 state | `<Activity>` 配合 `<ViewTransition>`（`visible` 时播 enter，`hidden` 时播 exit） |
| 页面或路由切换、共享元素、列表重排 | `<ViewTransition>`，更新放进过渡更新 |
| 拖拽、手势、弹簧物理、复杂编排、大量的离场动画 | 动画库 |

动画库里有代表性的是 Motion（原名 Framer Motion，npm 包名 `motion`，React 版从 `motion/react` 导入）。官方文档把它描述为声明式的动画工具：提供弹簧物理、悬停、点按和拖拽手势、元素大小位置变化时的布局过渡，以及用 `AnimatePresence` 实现的离场动画。

值得引入它的信号：你在手写第三个 `usePresence`；需要手势跟手并带速度的回弹；需要多个元素按时间轴编排。**还不值得**的信号：只有淡入淡出、展开收起、简单的列表位移。浏览器和 React 已经够用，而且不增加包体积。
