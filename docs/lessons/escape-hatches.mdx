# DOM 逃生舱：Portal、useLayoutEffect 与 useId

<LessonHeader />

<Warmup />

<LessonGoals />

<LessonProse>

React 推荐声明式写法：用 state 描述界面。但有些事无法用 props 和 state 表达。例如：让输入框获得焦点、测量元素尺寸、把弹窗放到页面最外层。

本课的 5 组 API 就是为这些情况准备的“逃生舱”。逃生舱很有用，但只在需要时打开。每一节最后都会说明**什么时候不要用**。

## 一、把 ref 传给自己的组件

你写 `<FancyInput ref={r} />`，想让父组件拿到子组件里的 input。在 React 19 里，`ref` 是普通 prop：函数组件直接从 props 里取出它，再交给里面的 DOM 元素。

```jsx title="ref 是普通 prop"
function FancyInput({ ref, ...props }) {
  return <input ref={ref} {...props} />;
}
```

<CallBox kind="tip" label="维护 React 18 项目时">

React 18 及更早的版本里，函数组件**收不到** `ref` 这个 prop，要用 `forwardRef` 包装，ref 是第二个参数：

```jsx title="React 18：用 forwardRef 接收 ref"
import { forwardRef } from 'react';

const FancyInput = forwardRef(function FancyInput(props, ref) {
  return <input ref={ref} {...props} />;
});
```

React 19 仍然支持 `forwardRef`，官方说明以后会弃用它。读到旧项目里的 `forwardRef` 时，把它看成“让函数组件收到 ref 的包装”即可。

</CallBox>

两种写法下，父组件拿到的都是**整个 input DOM 节点**。父组件可以改它的样式、内容，甚至删除它。这暴露得太多了。

`ref` 属性也可以接收函数，并在函数里返回清理函数，见 [useRef](/lessons/use-ref) 一课的“ref 回调”一节。

## 二、只暴露几个方法：useImperativeHandle

`useImperativeHandle(ref, createHandle, 依赖数组)` 让你自己决定 ref.current 里放什么。按下面 3 步做：

1. 在组件内部用 `useRef` 拿到真正的 DOM 节点。
2. 调用 `useImperativeHandle`，返回一个只含少数方法的对象。
3. 父组件的 `ref.current` 就是这个对象，而不是 DOM 节点。

```jsx play title="只暴露 focus() 和 clear()"
import { useRef, useImperativeHandle } from 'react';

function FancyInput({ label, ref }) {
  const inputRef = useRef(null); // 真正的 DOM 节点，只在组件内部使用

  useImperativeHandle(ref, () => ({
    focus() {
      inputRef.current.focus();
    },
    clear() {
      inputRef.current.value = '';
      inputRef.current.focus();
    },
  }), []);

  return (
    <label>
      {label} <input ref={inputRef} defaultValue="一些文字" />
    </label>
  );
}

function App() {
  const ref = useRef(null);
  return (
    <div>
      <FancyInput label="名字" ref={ref} />
      <p>
        <button onClick={() => ref.current.focus()}>聚焦</button>{' '}
        <button onClick={() => ref.current.clear()}>清空</button>{' '}
        <button onClick={() => console.log(Object.keys(ref.current))}>
          ref.current 里有什么？
        </button>
      </p>
    </div>
  );
}
```

<CallBox kind="like" label="打个比方">

useImperativeHandle 像自动售货机。机器外面只有几个按钮：选商品、投币、退币。机器里的货架和电机，你看不到也碰不到。厂家换了内部零件，按钮的用法也不变。

</CallBox>

<CallBox kind="warn" label="常见坑">

<strong>能用 props 表达的，就不要用 ref。</strong>例如弹窗不要暴露 `open()` 和 `close()`，而应该接收 `isOpen` prop。ref 只用于命令式的操作：聚焦、滚动、选中文字、触发动画。

</CallBox>

## 三、先测量，再绘制：useLayoutEffect

一次更新分为几步。“渲染”和“提交”在[渲染机制](/lessons/rendering)一课讲过，这里把 `useLayoutEffect` 和 `useEffect` 放进同一条顺序里。注意 3 和 5 的位置：

1. **渲染**：React 调用组件函数。
2. **提交**：React 修改真实 DOM。
3. **useLayoutEffect** 执行。此时 DOM 已更新，但屏幕还没变。
4. 浏览器绘制屏幕。用户看到新界面。
5. **useEffect** 执行（通常在绘制之后）。

如果你在 effect 里测量 DOM，再用测量结果修改位置，用户可能先看到错误的位置，再看到正确的位置。这就是“闪一下”。把测量放进 `useLayoutEffect`，修改会在绘制前完成。

```jsx play title="提示框会不会闪一下？"
import { useState, useEffect, useLayoutEffect, useRef } from 'react';

// 模拟一台慢设备：让 JS 忙 ms 毫秒
function slow(ms) {
  const start = performance.now();
  while (performance.now() - start < ms) {}
}

function Tooltip({ layout }) {
  const ref = useRef(null);
  const [y, setY] = useState(null); // null 表示“还没测量”

  function measure() {
    slow(300);
    setY(-(ref.current.offsetHeight + 6)); // 放到按钮上方
  }
  // 两个 Hook 每次都调用，只有一个真正测量。这样 Hook 的顺序不会变。
  useEffect(() => { if (!layout) measure(); }, []);
  useLayoutEffect(() => { if (layout) measure(); }, []);

  return (
    <div ref={ref} style={{
      position: 'absolute', left: 0, top: y === null ? 0 : y,
      background: y === null ? '#e74c3c' : '#2d3436',
      color: '#fff', padding: '6px 10px', borderRadius: 6, whiteSpace: 'nowrap',
      pointerEvents: 'none', // 不挡住鼠标，否则会反复触发 enter/leave
    }}>
      {y === null ? '还没测量（错误位置）' : '我是提示框'}
    </div>
  );
}

function HoverButton({ layout, children }) {
  const [show, setShow] = useState(false);
  return (
    <span style={{ position: 'relative', display: 'inline-block', margin: '48px 12px 8px 0' }}>
      <button onPointerEnter={() => setShow(true)} onPointerLeave={() => setShow(false)}>
        {children}
      </button>
      {show && <Tooltip layout={layout} />}
    </span>
  );
}

function App() {
  return (
    <div>
      <HoverButton layout={false}>悬停：useEffect</HoverButton>
      <HoverButton layout={true}>悬停：useLayoutEffect</HoverButton>
    </div>
  );
}
```

<CallBox kind="deep" label="深入一点">

有一个细节：如果更新由点击、按键等离散事件触发，useEffect 也会在绘制前同步执行。所以本演示用了鼠标悬停。不要依赖这个细节。需要在绘制前测量时，就明确使用 useLayoutEffect。

</CallBox>

<CallBox kind="warn" label="常见坑">

<strong>默认用 useEffect。</strong>useLayoutEffect 会阻塞绘制。代码慢，整个页面就卡住（上面右边按钮的延迟就是这样来的）。只有“读布局，再同步修改 DOM 或 state”时才用它。另外，useLayoutEffect 不会在服务端执行。React 18 及更早的版本在服务端渲染时会为此打印警告，React 19 不再警告。

</CallBox>

## 四、把 DOM 放到别处：createPortal

弹窗、下拉菜单、提示框常常要显示在所有内容的上方。如果它们渲染在一个带 `overflow: hidden` 或 `z-index` 的容器里，就可能被裁掉或被遮住。

`createPortal(children, domNode)` 把 children 的 DOM 放进另一个 DOM 节点，通常是 `document.body`。

```jsx title="createPortal 来自 react-dom，不是 react"
import { createPortal } from 'react-dom';

function Modal({ children }) {
  return createPortal(
    <div className="modal">{children}</div>,
    document.body
  );
}
```

Portal 改变了 DOM 的位置。下面的示例里，外层 div 有一个 onClick。弹窗渲染到了 body 里。先预测，再运行。

```jsx play title="Portal 里的点击会冒泡到哪里？"
import { useState } from 'react';
import * as ReactDOM from 'react-dom'; // 等价于 import { createPortal } from 'react-dom'

function Modal({ children }) {
  return ReactDOM.createPortal(
    <div style={{
      position: 'fixed', right: 16, bottom: 16, zIndex: 1000,
      padding: 16, background: '#fff', border: '2px solid #e67e22',
      borderRadius: 8, boxShadow: '0 6px 24px rgba(0,0,0,.25)',
    }}>
      {children}
    </div>,
    document.body
  );
}

function App() {
  const [open, setOpen] = useState(false);
  return (
    <div
      onClick={(e) => console.log('外层 div 收到点击，来自：' + e.target.textContent)}
      style={{ height: 80, overflow: 'hidden', border: '1px dashed gray', padding: 8 }}
    >
      <button onClick={() => setOpen(true)}>打开弹窗</button>
      {open && (
        <Modal>
          <p style={{ margin: '0 0 8px' }}>我在 document.body 里。</p>
          <button>点我</button>{' '}
          <button onClick={() => setOpen(false)}>关闭</button>
        </Modal>
      )}
    </div>
  );
}
```

<CallBox kind="tip" label="要点">

Portal 解决的是**位置**问题，不解决**无障碍**问题。一个合格的弹窗还需要：`role="dialog"`、用 `aria-labelledby` 指向标题、按 Esc 关闭、打开时移动焦点、关闭后把焦点还给按钮。本课练习会做前三项。

</CallBox>

<CallBox kind="warn" label="常见坑">

<strong>普通内容不要用 Portal。</strong>它让 DOM 结构和组件结构不一致，CSS 和调试都更难。只有内容必须“跳出”父容器时才用，例如弹窗、提示框、全局通知。

</CallBox>

## 五、生成稳定的 id：useId

`<label htmlFor>` 和 `aria-labelledby`、`aria-describedby` 都需要一个 id。同一个组件可能在页面上出现多次，所以 id 不能写死。

`useId()` 为每个组件实例返回一个唯一的字符串。这个字符串在组件的整个生命周期内不变。

```jsx play title="useId 与 Math.random 对比"
import { useState, useId } from 'react';

function Field({ label }) {
  const id = useId();
  const randomId = 'f' + Math.random().toString(36).slice(2, 7); // 反例

  return (
    <p>
      <label htmlFor={id}>{label}</label>{' '}
      <input id={id} aria-describedby={id + '-hint'} />
      <br />
      <small id={id + '-hint'}>
        useId：<code>{id}</code>　Math.random：<code>{randomId}</code>
      </small>
    </p>
  );
}

function App() {
  const [n, setN] = useState(0);
  return (
    <div>
      <Field label="邮箱" />
      <Field label="电话" />
      <button onClick={() => setN(n + 1)}>让 App 重新渲染（{n}）</button>
    </div>
  );
}
```

为什么不用 Math.random 或自增计数器？有两个原因：

1. Math.random 每次渲染都产生新值。id 一直在变，读屏软件和测试都难以依赖它。
2. 使用服务端渲染时，服务器和浏览器各生成一次 id。两边的值不同，**水合**就会出错。useId 根据组件在树中的位置生成 id，两边结果一致。

<CallBox kind="warn" label="常见坑">

<strong>不要用 useId 生成列表的 key。</strong>key 应该来自数据，例如数据库 id。一个组件需要多个 id 时，只调用一次 useId，再加后缀：`id + '-hint'`。useId 返回的字符串格式会随版本变化（React 18 里形如 `:r1:`，React 19.2 起形如 `_r_1_`），不要解析或依赖它。

</CallBox>

<details className="optional">
<summary><span className="opt-tag">选读</span>六、立刻更新 DOM：flushSync<small>可以先跳过，需要时再展开</small></summary>

React 会把 set 函数的调用攒在一起，稍后统一渲染。所以调用 set 函数后的下一行，DOM 还没变。

`flushSync(fn)` 让 React 在 fn 执行完后**立刻**渲染并提交。下一行代码就能读到新的 DOM。

```jsx title="添加一项后，立刻滚动到它"
import { flushSync } from 'react-dom';

function handleAdd() {
  flushSync(() => {
    setTodos([...todos, newTodo]);
  });
  // 此时新的 <li> 已经在 DOM 中
  listRef.current.lastChild.scrollIntoView({ behavior: 'smooth' });
}
```

<CallBox kind="warn" label="常见坑">

<strong>flushSync 很少需要。</strong>它会打断 React 的批量更新，可能明显降低性能。只能在事件处理函数等地方调用，不能在渲染期间或 effect 里调用。上面的例子也可以改成：在 effect 里根据 todos 的变化滚动。先考虑这种写法。

</CallBox>

</details>

## 速查：什么时候用，什么时候不用

| API | 用来做什么 | 什么时候不要用 |
|---|---|---|
| ref 作为 prop（旧项目里是 `forwardRef`） | 把 ref 传进自己的组件 | 父组件只需要传数据时 |
| `useImperativeHandle` | 只暴露 focus() 等少数方法 | 能用 props 表达时（例如 isOpen） |
| `useLayoutEffect` | 绘制前测量布局，避免闪烁 | 其他所有情况，默认用 useEffect |
| `createPortal` | 弹窗、提示框跳出父容器 | 普通内容；它也不会自动处理焦点 |
| `useId` | label、aria 属性的 id | 列表的 key、缓存的 key |
| `flushSync` | 下一行代码必须读到新 DOM | 几乎所有情况 |
