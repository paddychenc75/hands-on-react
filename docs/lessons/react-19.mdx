React 19（2024 年 12 月发布）带来了一批围绕**异步操作和表单**的新特性。**本课的 React 19 代码只能阅读**：本应用的运行环境是 React 18，运行不了 19 的 API。可运行的演示和练习用 React 18 模拟同样的思路。想亲手运行 React 19 的代码，请在本机建一个项目，步骤见[项目搭建与交付](/lessons/engineering)：用 Vite 创建的新项目默认就是 React 19。

一次异步提交（例如“修改用户名”）要管理 4 件事。React 18 中，每一件都要自己写 state。React 19 为每一件提供了现成的 API：

| 要管的事 | React 18 | React 19 |
|---|---|---|
| 提交中（pending） | `useState(false)`，提交前设为 true，结束后设回 false | 异步 `startTransition`、`useActionState`、`useFormStatus` |
| 错误和结果 | 再加一个 `useState(null)`，在 try/catch 里设置 | `useActionState` 的返回值 |
| 成功后重置表单 | 手动清空每个受控字段的 state | `<form action>` 自动重置非受控字段 |
| 乐观值 | 再加一个临时 state，失败时手动回滚 | `useOptimistic` |

## Actions：异步函数直接作为 transition

React 19 允许在 `startTransition` 中使用**异步函数**。这类函数叫 **Action**。React 会自动追踪它的 pending 状态。

<strong>它解决了 React 18 中的什么麻烦：</strong>每次提交都要成对地设置 isPending。中途 return 或抛错时，很容易忘了设回 false，按钮就一直显示“提交中”。

```jsx
// React 18：手动管理一切
const [isPending, setIsPending] = useState(false);
const [error, setError] = useState(null);
async function handleSubmit() {
  setIsPending(true);
  const err = await updateName(name);
  setIsPending(false);
  if (err) setError(err); else redirect('/profile');
}

// React 19：异步 transition 自动处理 pending
const [isPending, startTransition] = useTransition();
function handleSubmit() {
  startTransition(async () => {
    const err = await updateName(name);
    if (err) { setError(err); return; }
    redirect('/profile');
  });
}
```

## \&lt;form action\&gt; 与 useActionState

<strong>它解决了 React 18 中的什么麻烦：</strong>表单要写 onSubmit 和 `e.preventDefault()`，每个字段还要一个受控 state。结果和错误又各占一个 state。

`<form>` 的 `action` 属性可以直接接收函数。提交时，React 调用它并传入 `FormData`，成功后自动重置非受控字段。`useActionState` 把 Action 的返回值和 pending 打包给你。Action 的第一个参数是上一次的 state：

```jsx
import { useActionState } from 'react';

async function subscribe(prevState, formData) {
  const email = formData.get('email');
  if (!email.includes('@')) return { error: '邮箱格式不对' };
  await api.subscribe(email);
  return { ok: true };
}

function Newsletter() {
  const [state, formAction, isPending] = useActionState(subscribe, {});
  return (
    <form action={formAction}>
      <input name="email" />
      <button disabled={isPending}>{isPending ? '提交中…' : '订阅'}</button>
      {state.error && <p>{state.error}</p>}
      {state.ok && <p>订阅成功 🎉</p>}
    </form>
  );
}
```

<CallBox kind="tip" label="要点">

深层的提交按钮可以调用 react-dom 的 `useFormStatus()`，读取所在表单的 pending。这样 isPending 就不用一层层传下去。注意：它必须在 form **内部**的子组件中调用。

</CallBox>

```jsx title="useFormStatus 要放在 form 里面的子组件（只能阅读）"
import { useFormStatus } from 'react-dom';

function SubmitButton() {              // ✅ 它被渲染在 <form> 里面
  const { pending } = useFormStatus();
  return <button disabled={pending}>{pending ? '提交中…' : '订阅'}</button>;
}

function Newsletter() {
  // ❌ 如果在这里调用 useFormStatus()：Newsletter 的上层没有 form，pending 永远是 false
  return <form action={subscribe}><input name="email" /><SubmitButton /></form>;
}
```

## useOptimistic：乐观更新

点赞、发消息时，先**立刻**显示结果，再等服务器确认。失败时自动回滚。

<strong>它解决了 React 18 中的什么麻烦：</strong>你要自己多存一个“临时值”，成功时替换，失败时回滚，连续点击时还要处理多个临时值。

```jsx
function Chat({ messages, sendMessage }) {
  const [optimistic, addOptimistic] = useOptimistic(
    messages,
    (current, newText) => [...current, { id: 'tmp-' + Date.now(), text: newText, sending: true }]
  );

  async function action(formData) {
    const text = formData.get('text');
    addOptimistic(text);        // 立即显示（带“发送中”标记）
    await sendMessage(text);    // 完成后 messages 更新，乐观值被真实值替换
  }

  return (
    <>
      {optimistic.map(m => <p key={m.id}>{m.text}{m.sending && ' (发送中…)'}</p>)}
      {/* addOptimistic 必须在 Action 或 startTransition 中调用；form 的 action 本身就是 Action */}
      <form action={action}><input name="text" /></form>
    </>
  );
}
```

下面用 React 18 的 state **模拟它的效果**。演示后面是 useOptimistic 版本的逐行对照。

```jsx play title="用 React 18 模拟乐观更新的效果"
import { useState } from 'react';

const fakeServer = (ok) => new Promise((res, rej) => setTimeout(() => ok ? res() : rej(new Error('网络错误')), 1200));

function App() {
  const [likes, setLikes] = useState(42);
  const [pending, setPending] = useState(0);
  const [msg, setMsg] = useState('');

  async function like(shouldSucceed) {
    setPending(p => p + 1);           // ①
    setMsg('');
    try {
      await fakeServer(shouldSucceed);
      setLikes(l => l + 1);           // ②
    } catch (e) {
      setMsg('点赞失败：' + e.message);
    } finally {
      setPending(p => p - 1);         // ③
    }
  }

  return (
    <div>
      <h2>❤️ {likes + pending} {pending > 0 && <small>（同步中…）</small>}</h2>
      <button onClick={() => like(true)}>点赞（会成功）</button>
      <button onClick={() => like(false)}>点赞（会失败）</button>
      <p style={{ color: 'crimson' }}>{msg}</p>
    </div>
  );
}
```

```jsx title="await 之后的 set 函数调用不再属于这个 Action，所以 ② 要再包一层 startTransition"
// 同样的点赞，用 React 19 的 useOptimistic 写（只读代码）
import { useState, useOptimistic, startTransition } from 'react';

function LikeButton() {
  const [likes, setLikes] = useState(42);
  const [optimisticLikes, addOptimistic] = useOptimistic(likes, (current, n) => current + n);
  const [msg, setMsg] = useState('');

  function like(shouldSucceed) {
    setMsg('');
    startTransition(async () => {
      addOptimistic(1);                              // 对应 ①
      try {
        await fakeServer(shouldSucceed);
        startTransition(() => setLikes(l => l + 1)); // 对应 ②
      } catch (e) {
        setMsg('点赞失败：' + e.message);
      }
    }); // Action 结束时，乐观值自动丢弃：对应 ③，不用自己写
  }

  return (
    <div>
      <h2>❤️ {optimisticLikes}</h2>
      <button onClick={() => like(true)}>点赞（会成功）</button>
      <button onClick={() => like(false)}>点赞（会失败）</button>
      <p>{msg}</p>
    </div>
  );
}
```

## use()：在渲染中读取 Promise 和 Context

<strong>它解决了 React 18 中的什么麻烦：</strong>读取一个 Promise，要写 useEffect 加三个 state（数据、加载中、错误）。Hook 又不能写在条件语句里，按条件读取 Context 很别扭。

```jsx
import { use, Suspense } from 'react';

function Comments({ commentsPromise }) {
  const comments = use(commentsPromise); // 未完成时会“暂停”，交给 Suspense
  return comments.map(c => <p key={c.id}>{c.text}</p>);
}

// use 不是 Hook，而是 API：它可以写在条件语句里（但不能放在 try-catch 中）
function Heading({ show }) {
  if (show) {
    const theme = use(ThemeContext);
    return <h1 style={{ color: theme.color }}>标题</h1>;
  }
  return null;
}
```

<CallBox kind="warn" label="常见坑">

传给 `use()` 的 Promise 必须在多次渲染之间是**同一个对象**。在组件里写 `use(fetch(…))`，每次渲染都新建 Promise，组件会反复挂起。`useMemo` 也救不了：组件首次挂载就挂起时，这次渲染被丢弃，`useMemo` 记住的值一起丢了。Promise 要来自组件之外：服务端组件通过 props 传入，或者数据请求库的缓存。

另外，`use()` 可以放在 `if` 里，但不要写成“缓存里有值就跳过 `use()`”。挂起时调用了、恢复后不调用，React 19.3 会在开发模式给出警告。

</CallBox>

## Activity：隐藏界面，但保留它的 state

React 19.2 新增 `<Activity>`。它解决的是“切换标签页或返回上一页时，不想丢掉另一部分界面的 state”。

```jsx title="Activity（只能阅读）"
import { Activity } from 'react';

function Tabs({ tab }) {
  return (
    <>
      <Activity mode={tab === 'a' ? 'visible' : 'hidden'}><PageA /></Activity>
      <Activity mode={tab === 'b' ? 'visible' : 'hidden'}><PageB /></Activity>
    </>
  );
}
```

`mode="hidden"` 时，组件的 DOM 被隐藏，**state 保留**，它的 effect 被清理（不再运行），也不再响应更新。切回 `visible` 时，state 还在，effect 重新运行。三种隐藏方式的区别：

| 做法 | state | effect | 隐藏时的渲染 |
|---|---|---|---|
| 条件渲染 `{show && <Page />}` | 丢失 | 卸载时清理 | 不渲染 |
| CSS `display: none` | 保留 | 一直在运行 | 照常重新渲染 |
| `<Activity mode="hidden">` | 保留 | 被清理 | 低优先级，空闲时才处理 |

本课的实验台运行的正是 React 18.3.1。官方推荐的升级路线是三步：

1. 先升到 **React 18.3.1**。它和 18.2 行为相同，但会对 19 将移除的 API 打印弃用警告。把这些警告清掉。
2. 运行官方 codemod：`npx codemod@latest react/19/migration-recipe`。它会自动改写其中大部分写法。
3. 再升到 React 19。

React 19 移除了下面这些 API：

| 被移除的 API | 替代写法 |
|---|---|
| 函数组件的 `defaultProps` | 参数默认值：`function Heading({ text = '你好' })` |
| 函数组件的 `propTypes` | TypeScript 类型 |
| 字符串 ref：`ref="input"` | ref 回调或 `useRef` |
| `ReactDOM.render`、`ReactDOM.hydrate` | `createRoot`、`hydrateRoot` |
| `ReactDOM.findDOMNode` | 用 ref 拿 DOM 节点 |
| `react-dom/test-utils` 里的 `act` | 从 `react` 导入 `act` |

`forwardRef` 在 19 中仍然能用，只是函数组件现在可以直接把 `ref` 当 prop 接收，通常不再需要它。

</details>

<details className="optional">
<summary><span className="opt-tag">选读</span>其他实用改进<small>可以先跳过，需要时再展开</small></summary>

- **ref 作为普通 prop**：函数组件可以直接接收 `ref`。React 18 中必须用 `forwardRef` 包一层。
- **\<Context\> 直接作为 Provider**：写 `<ThemeContext value="dark">` 即可。React 18 中必须写 `.Provider`。
- **ref 回调支持返回清理函数**。React 18 中，卸载时 ref 回调会以 null 再调用一次，你要自己判断参数是不是 null。
- **文档元数据**：在组件里直接渲染 `<title>`、`<meta>`，React 会自动提升到 `<head>`。React 18 中要用 effect 修改 document.title，或引入第三方库。
- **样式表和脚本写在组件里**：在组件里渲染 `<link rel="stylesheet" href="…" precedence="default">` 或 `<script async src="…">`，React 会按 `precedence` 排好样式表的顺序，并自动去重：多个组件写同一个地址，只加载一次。
- **预加载 API**：`react-dom` 提供 `preload`、`preinit`、`preconnect`、`prefetchDNS`，让浏览器提前加载资源。例如 `preload('/font.woff2', { as: 'font' })`。
- **更好的水合错误提示**。水合是服务端渲染后，React 在浏览器里接管 HTML 的过程，第 29 课会详细讲。React 18 中出错时只说“不匹配”；19 会列出服务器和浏览器渲染结果的差异。

</details>

<details className="optional">
<summary><span className="opt-tag">选读</span>大型表单<small>可以先跳过，需要时再展开</small></summary>

表单变大后，按这几条组织（第 43 课《表单与校验架构》会专门讲）：

1. 用 `FormData` 读取字段，例如 `formData.get('email')`。
2. 校验两次。客户端校验给出即时反馈。服务器校验保证安全，不能省略。
3. Action 返回每个字段的错误，例如 `{ errors: { email: '…' } }`。
4. 让屏幕阅读器读到错误：出错的输入框加 `aria-invalid`，再用 `aria-describedby` 指向错误文字。

```jsx title="useActionState 返回字段错误"
async function signup(prevState, formData) {
  const email = String(formData.get('email') ?? '');
  if (!email.includes('@')) return { errors: { email: '邮箱格式不对' }, email };
  await api.signup(email);
  return { ok: true };
}

function Signup() {
  const [state, formAction, isPending] = useActionState(signup, {});
  const err = state.errors?.email;
  return (
    <form action={formAction}>
      <label htmlFor="email">邮箱</label>
      {/* 提交后表单会重置，用 defaultValue 填回用户的输入 */}
      <input id="email" name="email" defaultValue={state.email}
        aria-invalid={err ? true : undefined} aria-describedby={err ? 'email-error' : undefined} />
      {err && <p id="email-error">{err}</p>}
      <button disabled={isPending}>注册</button>
    </form>
  );
}
```

字段很多、字段之间有联动校验、需要边输入边提示时，用 **React Hook Form + Zod**。用 Zod 写一份 schema，客户端和服务器共用同一套规则。

<details className="optional">
<summary><span className="opt-tag">选读</span>React 19.1、19.2 与 19.3 新增<small>可以先跳过，需要时再展开</small></summary>

| 版本与 API | 作用 | 在 React 18 中的麻烦 |
|---|---|---|
| 19.1 Owner Stack：`captureOwnerStack` | 开发模式下，返回“直接负责渲染这个组件”的组件调用链，用来调试 | 组件栈只显示层级，看不出是哪个组件创建了出问题的元素 |
| 19.1 `useId` 格式 | 格式从 `:r1:` 改为 `«r1»`；19.2 又改为 `_r_1_`。不要依赖 id 的具体格式 | 旧格式含冒号，不能直接当 CSS 选择器用 |
| 19.2 Partial Pre-rendering：`prerender`、`resume` | 先预渲染页面的静态部分，之后再恢复渲染动态部分 | 要么整页静态生成，要么整页服务端渲染 |
| 19.2 `eslint-plugin-react-hooks` v6 | `recommended` 预设默认使用 flat config；基于 React Compiler 的新规则需要自己开启 | 旧的 `extends` 写法在新的 ESLint 配置里不能直接用 |
| 19.2 `useEffectEvent` | 从 effect 中提取事件逻辑。它总能读到最新值，不必写进依赖数组。见“闭包陷阱与 Effect 依赖”一课 | 想读最新值又不想重启 effect，只能手动用 ref 同步 |
| 19.2 `cacheSignal` | 只用于服务端组件。`cache()` 的结果失效时发出信号，可以中止请求 | 渲染已经放弃了，发出的请求还在继续，浪费服务器资源 |
| 19.2 Performance Tracks | Chrome DevTools 性能面板中新增 React 轨道，显示调度优先级、组件渲染和 effect | 性能面板只显示一堆 JS 函数，看不出是哪个组件、哪个优先级 |
| 19.3 `<ViewTransition>`、`addTransitionType` | 用浏览器的 View Transition API，为元素的进入、离开、移动做动画 | 离开的元素已被卸载，要做退场动画只能引入动画库 |
| 19.3 Fragment ref | 给 `<Fragment>` 传 ref，操作它的 DOM 子节点 | 要拿到一组子元素，只能多包一层 div，改变了 DOM 结构 |
| 19.3 `use(browser())` | 让组件跳过服务端渲染，只在浏览器中渲染 | 要写 useEffect + “已挂载” state，先渲染占位再渲染真实内容 |
| 19.3 服务端组件直接渲染 Context | 服务端组件可以直接渲染从 `'use client'` 模块导入的 Context，不用再包一层客户端 Provider 组件 | 要多写一个只为包 Provider 的客户端组件 |
| 19.3 过渡更新各自独立渲染 | 慢的过渡更新不再拖住其他无关的过渡 | 一个慢的过渡会让别的过渡一起等 |
| 19.3 Trusted Types | 支持浏览器的 Trusted Types API，防止基于 DOM 的 XSS | 开启 Trusted Types 的网站上，React 写入 HTML 的部分会被浏览器拦截 |
