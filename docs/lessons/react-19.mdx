# Actions：异步提交、表单与乐观更新

<LessonHeader />

<Warmup />

<LessonGoals />

<LessonProse>

用户点“保存”，页面把数据发给服务器，等结果，再显示成功或失败。这是 Web 应用里最常见的**异步提交**。React 19 把它做成了一等能力，叫 **Action**。

本课的示例里，`api`、`save`、`fakeServer` 都是模拟的异步函数（用 `setTimeout` 等一会儿再返回），不是真的服务器。

## 一次提交要管的 4 件事

一次异步提交，至少要管 4 件事：

| 要管的事 | 手写时要做什么 | React 19 的接管方式 |
|---|---|---|
| 提交中（pending） | `useState(false)`：提交前设为 true，结束后设回 false | `useTransition` 的 `isPending`、`useActionState` 的第三个返回值、`useFormStatus` |
| 错误和结果 | 再加一个 `useState(null)`，在 try/catch 里设置 | `useActionState` 的返回值 |
| 成功后重置表单 | 手动清空每个受控字段的 state | `<form action>` 自动重置非受控字段 |
| 乐观值 | 再加一个临时 state，失败时手动回滚 | `useOptimistic` |

这些 API 围绕同一个概念：Action。后面按这条线逐个看：Action、表单的 `action` 属性、`useActionState`、`useFormStatus`、`useOptimistic`，最后看失败怎么处理。

<CallBox kind="tip" label="维护 React 18 项目时">

React 18 没有 Action、`<form action>`、`useActionState`、`useOptimistic`。18 里要像上表第二列那样自己写 state。本课的“手写版乐观更新”示例就是这种写法，用来和 19 对照。

</CallBox>

## Action：放进 transition 的异步函数

`startTransition` 可以接收**异步函数**。这类函数叫 **Action**。React 会追踪它：函数开始时 `isPending` 变成 true，函数结束（正常返回、提前 return 或抛错）时变回 false。

手写时的麻烦是：每次提交都要成对地设置 pending。中途 return 或抛错时，很容易忘了设回 false，按钮就一直显示“提交中”。

```jsx
// 手写：自己管 pending 和错误
const [isPending, setIsPending] = useState(false);
const [error, setError] = useState(null);
async function handleSubmit() {
  setIsPending(true);
  const err = await updateName(name);
  setIsPending(false);
  if (err) setError(err); else redirect('/profile');
}

// Action：React 管 pending
const [isPending, startTransition] = useTransition();
function handleSubmit() {
  startTransition(async () => {
    const err = await updateName(name);
    if (err) { setError(err); return; }
    redirect('/profile');
  });
}
```

有一个细节要注意：**`await` 之后，函数已经不在这个 transition 里了**。`await` 之后的 set 函数调用是普通的紧急更新。要让它仍作为 transition 更新，再包一层 `startTransition`。

下面的示例有两个保存按钮。两个按钮的区别，只在 `await` 之后有没有再包一层 `startTransition`。点保存，等 0.8 秒，再看控制台里每次渲染打印的 `isPending` 和 `name`。点“重置”回到旧名字，再试另一个按钮。

```jsx play title="Action：异步函数当 transition"
import { useState, useTransition } from 'react';

// 模拟的服务器：0.8 秒后保存成功
const save = () => new Promise(resolve => setTimeout(resolve, 800));

function App() {
  const [name, setName] = useState('旧名字');
  const [isPending, startTransition] = useTransition();

  function rename(wrapAgain) {
    startTransition(async () => {
      await save();
      // 到这里，已经不在 transition 里了
      if (wrapAgain) startTransition(() => setName('新名字'));
      else setName('新名字');
    });
  }

  console.log('渲染：isPending=' + isPending + '，name=' + name);
  return (
    <div>
      <p>{name}（{isPending ? '提交中…' : '空闲'}）</p>
      <button onClick={() => rename(true)}>保存（再包一层）</button>
      <button onClick={() => rename(false)}>保存（不再包）</button>
      <button onClick={() => setName('旧名字')}>重置</button>
    </div>
  );
}
```

## 表单的 action 属性与 useActionState

手写表单要写 `onSubmit` 和 `e.preventDefault()`，每个字段还要一个受控 state。结果和错误又各占一个 state。

`<form>` 的 `action` 属性可以直接接收函数。提交时，React 调用它并传入 `FormData`。`useActionState` 把 Action 的返回值和 pending 打包给你：

- 返回 `[state, formAction, isPending]`。
- Action 的形状是 `(上一次的 state, formData) => 新的 state`。第一个参数是上一次的 state，不是 `formData`。

输入 `taken@example.com` 会得到“已订阅过”。

```jsx play title="useActionState 与 form action"
import { useActionState } from 'react';

// 模拟的服务器：0.8 秒后返回。taken@example.com 已经订阅过
const api = {
  subscribe: email => new Promise(resolve => setTimeout(() => resolve(email !== 'taken@example.com'), 800)),
};

// Action：(上一次的 state, formData) => 新的 state
async function subscribe(prevState, formData) {
  const email = String(formData.get('email') ?? '').trim();
  if (!email.includes('@')) return { error: '邮箱格式不对' };
  const ok = await api.subscribe(email);
  if (!ok) return { error: '这个邮箱已经订阅过了' };
  return { ok: true };
}

function App() {
  const [state, formAction, isPending] = useActionState(subscribe, {});
  return (
    <form action={formAction}>
      <input name="email" placeholder="邮箱" />
      <button disabled={isPending}>{isPending ? '提交中…' : '订阅'}</button>
      {state.error && <p style={{ color: 'crimson' }}>{state.error}</p>}
      {state.ok && <p>订阅成功 🎉</p>}
    </form>
  );
}
```

Action 结束后，React 会重置表单里的非受控字段。出错返回时也一样，输入框会被清空。要保留用户的输入，见本课末尾选读“大型表单”里的 `defaultValue` 写法。

<CallBox kind="tip" label="要点">

`useActionState` 的 Action 抛出的错误，不会变成 state。它会交给最近的错误边界。预期内的失败（例如“邮箱已订阅”）要用**返回值**表达。本课后面的“失败怎么办”会专门讲。

</CallBox>

## useFormStatus：深层的按钮读取提交状态

深层的提交按钮可以调用 react-dom 的 `useFormStatus()`，读取所在表单的 pending。这样 `isPending` 就不用一层层传下去。注意：它必须在 form **内部**的子组件中调用。

```jsx play title="useFormStatus：按钮写在哪里"
import { useFormStatus } from 'react-dom';

const save = () => new Promise(resolve => setTimeout(resolve, 1500));

// 按钮 B 在子组件 SubmitB 里
function SubmitB() {
  const { pending } = useFormStatus();
  return <button disabled={pending}>{pending ? 'B：提交中…' : 'B：提交'}</button>;
}

function App() {
  // 按钮 A 直接写在 App 里
  const { pending } = useFormStatus();
  return (
    <form action={save}>
      <button disabled={pending}>{pending ? 'A：提交中…' : 'A：提交'}</button>
      <SubmitB />
    </form>
  );
}
```

## useOptimistic：先显示结果，再等服务器

点赞、发消息时，先**立刻**显示结果，再等服务器确认。失败时自动回滚。这叫**乐观更新**。

先看手写版。你要自己多存一个“临时值”：成功时替换，失败时回滚，连续点击时还要处理多个临时值。

```jsx play title="手写版乐观更新（对照用）"
import { useState } from 'react';

const fakeServer = ok => new Promise((res, rej) => setTimeout(() => (ok ? res() : rej(new Error('网络错误'))), 1200));

function App() {
  const [likes, setLikes] = useState(42);
  const [pending, setPending] = useState(0); // 乐观值：正在等待的点赞数
  const [msg, setMsg] = useState('');

  async function like(shouldSucceed) {
    setPending(p => p + 1); // 先显示
    setMsg('');
    try {
      await fakeServer(shouldSucceed);
      setLikes(l => l + 1); // 成功：真实值加 1
    } catch (e) {
      setMsg('点赞失败：' + e.message);
    } finally {
      setPending(p => p - 1); // 成功和失败都要自己撤销乐观值
    }
  }

  return (
    <div>
      <h2>❤️ {likes + pending}</h2>
      <button onClick={() => like(true)}>点赞（会成功）</button>
      <button onClick={() => like(false)}>点赞（会失败）</button>
      <p style={{ color: 'crimson' }}>{msg}</p>
    </div>
  );
}
```

再看 `useOptimistic`。它接收真实值和一个“怎样叠加乐观值”的函数，返回要显示的值和一个触发函数。乐观值只在 Action 进行中有效。**Action 结束时，React 自动丢弃乐观值**，界面回到真实值。失败时真实值没变，所以不用自己回滚。

```jsx play title="useOptimistic：先显示，失败再回滚"
import { useState, useOptimistic, startTransition } from 'react';

const fakeServer = ok => new Promise((res, rej) => setTimeout(() => (ok ? res() : rej(new Error('网络错误'))), 1200));

function App() {
  const [likes, setLikes] = useState(42);
  const [optimisticLikes, addOptimistic] = useOptimistic(likes, (current, n) => current + n);
  const [msg, setMsg] = useState('');

  function like(shouldSucceed) {
    setMsg('');
    startTransition(async () => {
      addOptimistic(1); // ①
      try {
        await fakeServer(shouldSucceed);
        startTransition(() => setLikes(l => l + 1)); // ②
      } catch (e) {
        setMsg('点赞失败：' + e.message);
      }
    }); // Action 结束时，乐观值自动丢弃
  }

  return (
    <div>
      <h2>❤️ {optimisticLikes}</h2>
      <button onClick={() => like(true)}>点赞（会成功）</button>
      <button onClick={() => like(false)}>点赞（会失败）</button>
      <p style={{ color: 'crimson' }}>{msg}</p>
    </div>
  );
}
```

两点规则：

- `addOptimistic` 必须在 Action 或 `startTransition` 里调用。表单的 `action` 本身就是 Action。在普通事件处理函数里直接调用，开发模式会警告：“An optimistic state update occurred outside a transition or action.”
- ② 要再包一层 `startTransition`，原因和上一节一样：`await` 之后不再属于这个 Action。

表单里的写法更常见。把 `addOptimistic` 写在表单的 `action` 函数里：

```jsx
function Chat({ messages, sendMessage }) {
  const [optimistic, addOptimistic] = useOptimistic(
    messages,
    (current, newText) => [...current, { id: 'tmp-' + Date.now(), text: newText, sending: true }]
  );

  async function action(formData) {
    const text = formData.get('text');
    addOptimistic(text);        // 立即显示（带“发送中”标记）
    await sendMessage(text);    // 完成后 messages 更新，乐观值被真实值替换
  }

  return (
    <>
      {optimistic.map(m => <p key={m.id}>{m.text}{m.sending && ' (发送中…)'}</p>)}
      <form action={action}><input name="text" /></form>
    </>
  );
}
```

## 失败怎么办：返回错误值，还是抛错

Action 失败有两种情况，处理方式不同：

| 失败的种类 | 例子 | 怎么表达 |
|---|---|---|
| 预期内的失败 | 邮箱格式不对、用户名已被占用 | 在 Action 里**返回**错误值，界面用 state 显示 |
| 意外的错误 | 服务器崩溃、代码有 bug | 让它**抛出**，交给最近的错误边界 |

下面的示例用 `useActionState`，Action 对三种输入分别处理。输入 `bad` 返回错误值；输入 `boom` 抛错；其他输入成功。错误边界在[Suspense、懒加载与错误边界](/lessons/suspense)一课讲过。

```jsx play title="Action 抛错与返回错误值"
import { Component, useActionState } from 'react';

class Boundary extends Component {
  state = { error: null };
  static getDerivedStateFromError(error) {
    return { error };
  }
  render() {
    if (this.state.error) return <p>错误边界接住了：{this.state.error.message}</p>;
    return this.props.children;
  }
}

// 模拟的服务器：0.4 秒后返回
async function save(prevState, formData) {
  await new Promise(resolve => setTimeout(resolve, 400));
  const name = formData.get('name');
  if (name === 'boom') throw new Error('服务器崩溃了');
  if (name === 'bad') return { error: '名字不合法' };
  return { ok: true };
}

function NameForm() {
  const [state, formAction, isPending] = useActionState(save, {});
  return (
    <form action={formAction}>
      <input name="name" placeholder="试试 bad、boom 或别的" />
      <button disabled={isPending}>{isPending ? '提交中…' : '保存'}</button>
      {state.error && <p style={{ color: 'crimson' }}>{state.error}</p>}
      {state.ok && <p>已保存</p>}
    </form>
  );
}

function App() {
  return (
    <Boundary>
      <NameForm />
    </Boundary>
  );
}
```

`useOptimistic` 和失败也有关：Action 抛错时，乐观值同样被丢弃，界面回到真实值。

`use()` 在渲染中读取 Promise，配合 Suspense 显示加载状态。完整讲解见 [Suspense 数据获取与资源模式](/lessons/suspense-data)：

```jsx play title="use() 读取 Promise，配合 Suspense"
import { use, Suspense, useState } from 'react';

// 模拟请求。同一个 id 只请求一次：Promise 缓存在组件外面
const cache = new Map();
function fetchUser(id) {
  if (!cache.has(id)) {
    const names = { 1: 'Alice', 2: 'Bob' };
    cache.set(id, new Promise(resolve => setTimeout(() => resolve({ name: names[id] }), 1000)));
  }
  return cache.get(id);
}

function Profile({ userPromise }) {
  const user = use(userPromise); // 未完成时“暂停”这个组件，交给最近的 Suspense
  return <h3>用户：{user.name}</h3>;
}

function App() {
  const [userPromise, setUserPromise] = useState(() => fetchUser(1));
  return (
    <div>
      <button onClick={() => setUserPromise(fetchUser(1))}>看 Alice</button>
      <button onClick={() => setUserPromise(fetchUser(2))}>看 Bob</button>
      <Suspense fallback={<h3>加载中…</h3>}>
        <Profile userPromise={userPromise} />
      </Suspense>
    </div>
  );
}
```

`<Activity>` 隐藏界面但保留 state。完整讲解见[渲染机制](/lessons/rendering)：

```jsx play title="Activity：隐藏界面，保留 state"
import { Activity, useState, useEffect } from 'react';

function Draft({ name }) {
  const [text, setText] = useState('');
  useEffect(() => {
    console.log(name + ' 的 effect 运行');
    return () => console.log(name + ' 的 effect 被清理');
  }, [name]);
  return <input value={text} onChange={e => setText(e.target.value)} placeholder={name + ' 的输入框'} />;
}

function App() {
  const [tab, setTab] = useState('a');
  return (
    <div>
      <button onClick={() => setTab('a')}>标签 A</button>
      <button onClick={() => setTab('b')}>标签 B</button>
      <div>
        {/* 标签 A 用条件渲染，标签 B 用 Activity */}
        {tab === 'a' && <Draft name="A" />}
        <Activity mode={tab === 'b' ? 'visible' : 'hidden'}>
          <Draft name="B" />
        </Activity>
      </div>
    </div>
  );
}
```

`<ViewTransition>` 用浏览器的 View Transition API，为元素的进入和离开做动画。放在 `startTransition` 里的更新才会触发动画。目前只有这里有它的示例：

```jsx play title="ViewTransition：进入和离开的动画"
import { ViewTransition, startTransition, useState } from 'react';

function App() {
  const [show, setShow] = useState(false);
  return (
    <div>
      <button onClick={() => startTransition(() => setShow(s => !s))}>{show ? '收起' : '展开'}</button>
      {show && (
        <ViewTransition>
          <p style={{ padding: 12, background: '#cfe8f3', color: '#0f1d24', borderRadius: 6 }}>我是一张会淡入淡出的卡片</p>
        </ViewTransition>
      )}
    </div>
  );
}
```

表单变大后，按这几条组织（[表单与校验架构](/lessons/form-architecture)会专门讲）：

1. 用 `FormData` 读取字段，例如 `formData.get('email')`。
2. 校验两次。客户端校验给出即时反馈。服务器校验保证安全，不能省略。
3. Action 返回每个字段的错误，例如 `{ errors: { email: '…' } }`。
4. 让屏幕阅读器读到错误：出错的输入框加 `aria-invalid`，再用 `aria-describedby` 指向错误文字。

```jsx title="useActionState 返回字段错误"
async function signup(prevState, formData) {
  const email = String(formData.get('email') ?? '');
  if (!email.includes('@')) return { errors: { email: '邮箱格式不对' }, email };
  await api.signup(email);
  return { ok: true };
}

function Signup() {
  const [state, formAction, isPending] = useActionState(signup, {});
  const err = state.errors?.email;
  return (
    <form action={formAction}>
      <label htmlFor="email">邮箱</label>
      {/* 提交后表单会重置，用 defaultValue 填回用户的输入 */}
      <input id="email" name="email" defaultValue={state.email}
        aria-invalid={err ? true : undefined} aria-describedby={err ? 'email-error' : undefined} />
      {err && <p id="email-error">{err}</p>}
      <button disabled={isPending}>注册</button>
    </form>
  );
}
```

<summary><span className="opt-tag">选读</span>React 19 的其他实用改进<small>可以先跳过，需要时再展开</small></summary>

- **文档元数据**：在组件里直接渲染 `<title>`、`<meta>`，React 会自动提升到 `<head>`。不再需要用 effect 修改 `document.title`，也不需要第三方库。
- **样式表和脚本写在组件里**：在组件里渲染 `<link rel="stylesheet" href="…" precedence="default">` 或 `<script async src="…">`，React 会按 `precedence` 排好样式表的顺序，并自动去重：多个组件写同一个地址，只加载一次。
- **预加载 API**：`react-dom` 提供 `preload`、`preinit`、`preconnect`、`prefetchDNS`，让浏览器提前加载资源。例如 `preload('/font.woff2', { as: 'font' })`。
- **更好的水合错误提示**。水合是服务端渲染后，React 在浏览器里接管 HTML 的过程，[流式 SSR、选择性水合与 RSC 缓存](/lessons/streaming-ssr)一课会详细讲。水合出错时，React 19 会列出服务器和浏览器渲染结果的差异。
