React 19（2024 年 12 月发布）带来了一批围绕**异步操作和表单**的新特性。**这一课的实验台运行 React 19.3.0 开发版**（实验台标题栏的标记会显示版本）：本课的示例都是真正的 React 19 代码，可以直接改着试。其他课的实验台仍然运行 React 18.3.1。依赖真实服务端的内容（例如服务端组件把 Promise 传给 `use()`、Server Function 的 `'use server'`）实验台跑不了，课文里只用只读片段说明；示例里的 `api`、`save` 等都是模拟的异步函数。

一次异步提交（例如“修改用户名”）要管理 4 件事。React 18 中，每一件都要自己写 state。React 19 为每一件提供了现成的 API：

| 要管的事 | React 18 | React 19 |
|---|---|---|
| 提交中（pending） | `useState(false)`，提交前设为 true，结束后设回 false | 异步 `startTransition`、`useActionState`、`useFormStatus` |
| 错误和结果 | 再加一个 `useState(null)`，在 try/catch 里设置 | `useActionState` 的返回值 |
| 成功后重置表单 | 手动清空每个受控字段的 state | `<form action>` 自动重置非受控字段 |
| 乐观值 | 再加一个临时 state，失败时手动回滚 | `useOptimistic` |

## Actions：异步函数直接作为 transition

React 19 允许在 `startTransition` 中使用**异步函数**。这类函数叫 **Action**。React 会自动追踪它的 pending 状态。

<strong>它解决了 React 18 中的什么麻烦：</strong>每次提交都要成对地设置 isPending。中途 return 或抛错时，很容易忘了设回 false，按钮就一直显示“提交中”。

```jsx
// React 18：手动管理一切
const [isPending, setIsPending] = useState(false);
const [error, setError] = useState(null);
async function handleSubmit() {
  setIsPending(true);
  const err = await updateName(name);
  setIsPending(false);
  if (err) setError(err); else redirect('/profile');
}

// React 19：异步 transition 自动处理 pending
const [isPending, startTransition] = useTransition();
function handleSubmit() {
  startTransition(async () => {
    const err = await updateName(name);
    if (err) { setError(err); return; }
    redirect('/profile');
  });
}
```

## 表单的 action 属性与 useActionState

<strong>它解决了 React 18 中的什么麻烦：</strong>表单要写 onSubmit 和 `e.preventDefault()`，每个字段还要一个受控 state。结果和错误又各占一个 state。

`<form>` 的 `action` 属性可以直接接收函数。提交时，React 调用它并传入 `FormData`。`useActionState` 把 Action 的返回值和 pending 打包给你。Action 的第一个参数是上一次的 state。

下面的 `api.subscribe` 是模拟的异步函数（0.8 秒后返回），不是真的服务器。输入 `taken@example.com` 会得到“已订阅过”。

```jsx play title="useActionState 与 form action"
import { useActionState } from 'react';

// 模拟的服务器：0.8 秒后返回。taken@example.com 已经订阅过
const api = {
  subscribe: email => new Promise(resolve => setTimeout(() => resolve(email !== 'taken@example.com'), 800)),
};

// Action：(上一次的 state, formData) => 新的 state
async function subscribe(prevState, formData) {
  const email = String(formData.get('email') ?? '').trim();
  if (!email.includes('@')) return { error: '邮箱格式不对' };
  const ok = await api.subscribe(email);
  if (!ok) return { error: '这个邮箱已经订阅过了' };
  return { ok: true };
}

function App() {
  const [state, formAction, isPending] = useActionState(subscribe, {});
  return (
    <form action={formAction}>
      <input name="email" placeholder="邮箱" />
      <button disabled={isPending}>{isPending ? '提交中…' : '订阅'}</button>
      {state.error && <p style={{ color: 'crimson' }}>{state.error}</p>}
      {state.ok && <p>订阅成功 🎉</p>}
    </form>
  );
}
```

注意：Action 结束后，React 会重置表单里的非受控字段。出错返回时也一样，输入框会被清空。要保留用户的输入，见下面选读“大型表单”里的 `defaultValue` 写法。

<CallBox kind="tip" label="要点">

深层的提交按钮可以调用 react-dom 的 `useFormStatus()`，读取所在表单的 pending。这样 isPending 就不用一层层传下去。注意：它必须在 form **内部**的子组件中调用。

</CallBox>

下面的 `save` 是模拟的异步函数（1.5 秒后完成）。

```jsx play title="useFormStatus：按钮写在哪里"
import { useFormStatus } from 'react-dom';

const save = () => new Promise(resolve => setTimeout(resolve, 1500));

// 按钮 B 在子组件 SubmitB 里
function SubmitB() {
  const { pending } = useFormStatus();
  return <button disabled={pending}>{pending ? 'B：提交中…' : 'B：提交'}</button>;
}

function App() {
  // 按钮 A 直接写在 App 里
  const { pending } = useFormStatus();
  return (
    <form action={save}>
      <button disabled={pending}>{pending ? 'A：提交中…' : 'A：提交'}</button>
      <SubmitB />
    </form>
  );
}
```

## useOptimistic：乐观更新

点赞、发消息时，先**立刻**显示结果，再等服务器确认。失败时自动回滚。

<strong>它解决了 React 18 中的什么麻烦：</strong>你要自己多存一个“临时值”，成功时替换，失败时回滚，连续点击时还要处理多个临时值。

```jsx
function Chat({ messages, sendMessage }) {
  const [optimistic, addOptimistic] = useOptimistic(
    messages,
    (current, newText) => [...current, { id: 'tmp-' + Date.now(), text: newText, sending: true }]
  );

  async function action(formData) {
    const text = formData.get('text');
    addOptimistic(text);        // 立即显示（带“发送中”标记）
    await sendMessage(text);    // 完成后 messages 更新，乐观值被真实值替换
  }

  return (
    <>
      {optimistic.map(m => <p key={m.id}>{m.text}{m.sending && ' (发送中…)'}</p>)}
      {/* addOptimistic 必须在 Action 或 startTransition 中调用；form 的 action 本身就是 Action */}
      <form action={action}><input name="text" /></form>
    </>
  );
}
```

下面是真正的 `useOptimistic`。`fakeServer` 是模拟的网络请求（1.2 秒）。

```jsx play title="useOptimistic：先显示，失败再回滚"
import { useState, useOptimistic, startTransition } from 'react';

const fakeServer = ok => new Promise((res, rej) => setTimeout(() => (ok ? res() : rej(new Error('网络错误'))), 1200));

function App() {
  const [likes, setLikes] = useState(42);
  const [optimisticLikes, addOptimistic] = useOptimistic(likes, (current, n) => current + n);
  const [msg, setMsg] = useState('');

  function like(shouldSucceed) {
    setMsg('');
    startTransition(async () => {
      addOptimistic(1); // ①
      try {
        await fakeServer(shouldSucceed);
        startTransition(() => setLikes(l => l + 1)); // ②
      } catch (e) {
        setMsg('点赞失败：' + e.message);
      }
    }); // Action 结束时，乐观值自动丢弃
  }

  return (
    <div>
      <h2>❤️ {optimisticLikes}</h2>
      <button onClick={() => like(true)}>点赞（会成功）</button>
      <button onClick={() => like(false)}>点赞（会失败）</button>
      <p style={{ color: 'crimson' }}>{msg}</p>
    </div>
  );
}
```

`await` 之后的 set 函数调用不再属于这个 Action，所以 ② 要再包一层 `startTransition`。作为对照，下面是 React 18 的写法：自己多存一个 `pending` 数字，成功和失败后都要手动收尾。

```jsx title="React 18 的对照写法（只读）"
function LikeButton() {
  const [likes, setLikes] = useState(42);
  const [pending, setPending] = useState(0);
  const [msg, setMsg] = useState('');

  async function like(shouldSucceed) {
    setPending(p => p + 1);           // 对应 ①：乐观值
    setMsg('');
    try {
      await fakeServer(shouldSucceed);
      setLikes(l => l + 1);           // 对应 ②
    } catch (e) {
      setMsg('点赞失败：' + e.message);
    } finally {
      setPending(p => p - 1);         // 对应 Action 结束：自己撤销乐观值
    }
  }
  return <h2>❤️ {likes + pending}</h2>; // 省略按钮
}
```

## use()：在渲染中读取 Promise 和 Context

<strong>它解决了 React 18 中的什么麻烦：</strong>读取一个 Promise，要写 useEffect 加三个 state（数据、加载中、错误）。Hook 又不能写在条件语句里，按条件读取 Context 很别扭。

```jsx play title="use() 读取 Promise，配合 Suspense"
import { use, Suspense, useState } from 'react';

// 模拟请求。同一个 id 只请求一次：Promise 缓存在组件外面
const cache = new Map();
function fetchUser(id) {
  if (!cache.has(id)) {
    const names = { 1: 'Alice', 2: 'Bob' };
    cache.set(id, new Promise(resolve => setTimeout(() => resolve({ name: names[id] }), 1000)));
  }
  return cache.get(id);
}

function Profile({ userPromise }) {
  const user = use(userPromise); // 未完成时“暂停”这个组件，交给最近的 Suspense
  return <h3>用户：{user.name}</h3>;
}

function App() {
  const [userPromise, setUserPromise] = useState(() => fetchUser(1));
  return (
    <div>
      <button onClick={() => setUserPromise(fetchUser(1))}>看 Alice</button>
      <button onClick={() => setUserPromise(fetchUser(2))}>看 Bob</button>
      <Suspense fallback={<h3>加载中…</h3>}>
        <Profile userPromise={userPromise} />
      </Suspense>
    </div>
  );
}
```

`use` 不是 Hook，而是 API：它可以写在条件语句里（但不能放在 try-catch 中），还可以读取 Context：

```jsx title="use() 按条件读取 Context（只读片段）"
function Heading({ show }) {
  if (show) {
    const theme = use(ThemeContext);
    return <h1 style={{ color: theme.color }}>标题</h1>;
  }
  return null;
}
```

<CallBox kind="warn" label="常见坑">

传给 `use()` 的 Promise 必须在多次渲染之间是**同一个对象**。在组件里写 `use(fetch(…))`，每次渲染都新建 Promise，组件会反复挂起。`useMemo` 也救不了：组件首次挂载就挂起时，这次渲染被丢弃，`useMemo` 记住的值一起丢了。Promise 要来自组件之外：服务端组件通过 props 传入，或者数据请求库的缓存。

另外，`use()` 可以放在 `if` 里，但不要写成“缓存里有值就跳过 `use()`”。挂起时调用了、恢复后不调用，React 19.3 会在开发模式给出警告。

</CallBox>

## Activity：隐藏界面，但保留它的 state

React 19.2 新增 `<Activity>`。它解决的是“切换标签页或返回上一页时，不想丢掉另一部分界面的 state”。

```jsx play title="Activity：隐藏界面，保留 state"
import { Activity, useState, useEffect } from 'react';

function Draft({ name }) {
  const [text, setText] = useState('');
  useEffect(() => {
    console.log(name + ' 的 effect 运行');
    return () => console.log(name + ' 的 effect 被清理');
  }, [name]);
  return <input value={text} onChange={e => setText(e.target.value)} placeholder={name + ' 的输入框'} />;
}

function App() {
  const [tab, setTab] = useState('a');
  return (
    <div>
      <button onClick={() => setTab('a')}>标签 A</button>
      <button onClick={() => setTab('b')}>标签 B</button>
      <div>
        {/* 标签 A 用条件渲染，标签 B 用 Activity */}
        {tab === 'a' && <Draft name="A" />}
        <Activity mode={tab === 'b' ? 'visible' : 'hidden'}>
          <Draft name="B" />
        </Activity>
      </div>
    </div>
  );
}
```

`mode="hidden"` 时，组件的 DOM 被隐藏，**state 保留**，它的 effect 被清理（不再运行）；更新仍会处理，但推迟到更低的优先级。切回 `visible` 时，state 还在，effect 重新运行。三种隐藏方式的区别：

| 做法 | state | effect | 隐藏时的渲染 |
|---|---|---|---|
| 条件渲染 `{show && <Page />}` | 丢失 | 卸载时清理 | 不渲染 |
| CSS `display: none` | 保留 | 一直在运行 | 照常重新渲染 |
| `<Activity mode="hidden">` | 保留 | 被清理 | 低优先级，空闲时才处理 |

## ref 和 Context 的两处简化

函数组件现在可以直接把 `ref` 当 prop 接收，通常不再需要 `forwardRef`。ref 回调还可以返回一个清理函数：卸载时 React 调用它。React 18 中，卸载时 ref 回调会以 `null` 再调用一次，你要自己判断参数是不是 null。

```jsx play title="ref 作为普通 prop"
import { useRef, useState, useCallback } from 'react';

// 函数组件直接接收 ref，不需要 forwardRef
function FancyInput({ ref, label }) {
  return (
    <label>
      {label}：<input ref={ref} />
    </label>
  );
}

function Box() {
  const attach = useCallback(node => {
    console.log('ref 回调：挂上 <' + node.tagName.toLowerCase() + '>');
    return () => console.log('ref 回调：返回的清理函数运行了');
  }, []);
  return <div ref={attach}>我是一个方框</div>;
}

function App() {
  const inputRef = useRef(null);
  const [show, setShow] = useState(true);
  return (
    <div>
      <FancyInput ref={inputRef} label="姓名" />
      <button onClick={() => inputRef.current.focus()}>聚焦输入框</button>
      <button onClick={() => setShow(s => !s)}>{show ? '卸载方框' : '挂上方框'}</button>
      {show && <Box />}
    </div>
  );
}
```

Context 对象本身可以直接当 Provider 用。React 18 中必须写 `.Provider`。

```jsx play title="Context 直接当 Provider"
import { createContext, useContext, useState } from 'react';

const ThemeContext = createContext('light');

function Panel() {
  const theme = useContext(ThemeContext);
  const dark = theme === 'dark';
  return (
    <p style={{ padding: 12, borderRadius: 6, background: dark ? '#222' : '#eee', color: dark ? '#eee' : '#222' }}>
      当前主题：{theme}
    </p>
  );
}

function App() {
  const [theme, setTheme] = useState('light');
  return (
    // React 18 要写 <ThemeContext.Provider value={theme}>
    <ThemeContext value={theme}>
      <button onClick={() => setTheme(t => (t === 'light' ? 'dark' : 'light'))}>切换主题</button>
      <Panel />
    </ThemeContext>
  );
}
```

## useEffectEvent 与 ViewTransition

`useEffectEvent`（19.2 起稳定）从 effect 中提取事件逻辑：它总能读到最新的 props 和 state，又不必写进依赖数组。下面切换主题不会重新连接，只有换房间才会。

```jsx play title="useEffectEvent：读最新值但不重启 effect"
import { useState, useEffect, useEffectEvent } from 'react';

function ChatRoom({ roomId, theme }) {
  const onConnected = useEffectEvent(() => {
    console.log('已连接到 ' + roomId + '，当前主题：' + theme);
  });
  useEffect(() => {
    console.log('连接到 ' + roomId + ' …');
    const id = setTimeout(() => onConnected(), 600);
    return () => {
      clearTimeout(id);
      console.log('断开 ' + roomId);
    };
  }, [roomId]); // 不用写 theme，也不用写 onConnected
  return <p>房间：{roomId}，主题：{theme}</p>;
}

function App() {
  const [roomId, setRoomId] = useState('general');
  const [theme, setTheme] = useState('light');
  return (
    <div>
      <button onClick={() => setRoomId(r => (r === 'general' ? 'travel' : 'general'))}>换房间</button>
      <button onClick={() => setTheme(t => (t === 'light' ? 'dark' : 'light'))}>换主题</button>
      <ChatRoom roomId={roomId} theme={theme} />
    </div>
  );
}
```

`<ViewTransition>`（19.3 起稳定）用浏览器的 View Transition API，为元素的进入、离开、更新做动画。只有放在 `startTransition`（或 Suspense 展开、`useDeferredValue`）里的更新才会触发动画，紧急更新会立即生效。

```jsx play title="ViewTransition：进入和离开的动画"
import { ViewTransition, startTransition, useState } from 'react';

function App() {
  const [show, setShow] = useState(false);
  return (
    <div>
      <button onClick={() => startTransition(() => setShow(s => !s))}>{show ? '收起' : '展开'}</button>
      {show && (
        <ViewTransition>
          <p style={{ padding: 12, background: '#cfe8f3', color: '#0f1d24', borderRadius: 6 }}>我是一张会淡入淡出的卡片</p>
        </ViewTransition>
      )}
    </div>
  );
}
```

- **ref 和 Context 的简化**：见上面“ref 和 Context 的两处简化”。
- **文档元数据**：在组件里直接渲染 `<title>`、`<meta>`，React 会自动提升到 `<head>`。React 18 中要用 effect 修改 document.title，或引入第三方库。

- **预加载 API**：`react-dom` 提供 `preload`、`preinit`、`preconnect`、`prefetchDNS`，让浏览器提前加载资源。例如 `preload('/font.woff2', { as: 'font' })`。
- **更好的水合错误提示**。水合是服务端渲染后，React 在浏览器里接管 HTML 的过程，第 29 课会详细讲。React 18 中出错时只说“不匹配”；19 会列出服务器和浏览器渲染结果的差异。

表单变大后，按这几条组织（第 43 课《表单与校验架构》会专门讲）：

1. 用 `FormData` 读取字段，例如 `formData.get('email')`。
2. 校验两次。客户端校验给出即时反馈。服务器校验保证安全，不能省略。
3. Action 返回每个字段的错误，例如 `{ errors: { email: '…' } }`。
4. 让屏幕阅读器读到错误：出错的输入框加 `aria-invalid`，再用 `aria-describedby` 指向错误文字。

```jsx title="useActionState 返回字段错误"
async function signup(prevState, formData) {
  const email = String(formData.get('email') ?? '');
  if (!email.includes('@')) return { errors: { email: '邮箱格式不对' }, email };
  await api.signup(email);
  return { ok: true };
}

function Signup() {
  const [state, formAction, isPending] = useActionState(signup, {});
  const err = state.errors?.email;
  return (
    <form action={formAction}>
      <label htmlFor="email">邮箱</label>
      {/* 提交后表单会重置，用 defaultValue 填回用户的输入 */}
      <input id="email" name="email" defaultValue={state.email}
        aria-invalid={err ? true : undefined} aria-describedby={err ? 'email-error' : undefined} />
      {err && <p id="email-error">{err}</p>}
      <button disabled={isPending}>注册</button>
    </form>
  );
}
```
