# 数据请求：TanStack Query

<LessonHeader />

<Warmup />

<LessonGoals />

<LessonProse>

第 15 课我们用 useEffect 请求数据。那时要自己处理 loading、error 和竞态。真实应用还会遇到更多问题：

- 两个组件请求同一个接口，发了两次请求
- 切走再切回页面，又要重新等待加载
- 数据在别处被修改了，这里显示的还是旧的
- 请求失败要不要自动重试？窗口重新获得焦点时要不要刷新？

这些都属于**服务端状态**的管理问题。TanStack Query（原名 React Query）解决了这些问题。它是目前最流行的方案。

## useQuery：读取数据

```jsx title="和第 15 课的手写版本对比一下"
import { QueryClient, QueryClientProvider, useQuery } from '@tanstack/react-query';

const queryClient = new QueryClient();

function App() {
  return (
    <QueryClientProvider client={queryClient}>
      <Todos />
    </QueryClientProvider>
  );
}

// fetch 遇到 404/500 不会自己抛错，所以要检查 res.ok
async function getJSON(url, init) {
  const res = await fetch(url, init);
  if (!res.ok) throw new Error('请求失败：' + res.status);
  return res.json();
}

function Todos() {
  const { data, isPending, isError, error, isFetching } = useQuery({
    queryKey: ['todos'],                  // 缓存的“名字”
    queryFn: () => getJSON('/api/todos'), // 失败时必须抛错，isError 才会为 true
    staleTime: 60_000,                    // 1 分钟内认为数据是新鲜的
  });

  if (isPending) return <p>加载中…</p>;
  if (isError) return <p>出错了：{error.message}</p>;
  return <ul>{data.map(t => <li key={t.id}>{t.title}</li>)}</ul>;
}
```

## queryKey：缓存的身份证

`queryKey` 决定数据存在缓存的哪个位置。**查询依赖的所有变量都要写进 key**，比如 `['user', userId]`。userId 变了，key 就变了，会自动请求新数据；切回之前的 userId 时，页面立刻显示缓存。同时，它在后台检查是否需要更新。

## 自己动手：迷你 useQuery

先自己写一个带缓存的**迷你版**，看清原理。实验台也能运行真的 TanStack Query，所以本课分四层：

1. **迷你实现**（本节和下一节）：用 `useSyncExternalStore` 实现一个带缓存的迷你 useQuery，弄懂缓存、去重和过期刷新，并通过预测检验自己的理解。
2. **真库示例**（“用真的 TanStack Query”一节）：在实验台里运行 @tanstack/react-query 5.104.1，看状态字段、缓存共享、后台刷新、mutation 和乐观更新的真实行为。
3. **本机任务**（课末）：在你的电脑上装真库，把同样的实验做一遍，并按清单自查。
4. **项目课**：[《实战四：城市天气应用》](/lessons/project-weather)用真库做依赖查询、错误处理和测试。

注意 effect 的依赖数组只写了 `key`，没写 `queryFn`。这看起来违反了第 15 课“依赖数组不要撒谎”。原因是：依赖规则没有消失，它**搬到了 queryKey 上**。queryFn 用到的每个变量都必须写进 queryKey。所以 key 不变时，新的 queryFn 和旧的请求同一份数据，不需要重新请求。反过来，queryFn 每次渲染都是新函数，写进依赖会让 effect 每次渲染都重新执行。真实的 TanStack Query 也是这样：queryFn 每次渲染换成新函数，不会触发重新请求；它只认 queryKey。

```jsx play title="迷你 useQuery"
import { useSyncExternalStore, useEffect, useState } from 'react';

// ===== 迷你 Query 缓存 =====
const cache = new Map();      // key -> { data, updatedAt, fetching, promise }
const listeners = new Set();
const notify = () => listeners.forEach(l => l());
const subscribe = (l) => { listeners.add(l); return () => listeners.delete(l); };

function fetchQuery(key, fn) {
  const entry = cache.get(key) || {};
  if (entry.promise) return entry.promise;                  // ① 这个 key 已有 promise 时
  const promise = fn().then(
    data => { cache.set(key, { data, updatedAt: Date.now() }); notify(); },
    // 失败：记下错误，清掉 promise。下次需要时可以重新请求
    error => { cache.set(key, { ...cache.get(key), error, fetching: false, promise: null }); notify(); }
  );
  cache.set(key, { ...entry, error: null, fetching: true, promise }); notify();
  return promise;
}

function useQuery({ queryKey, queryFn, staleTime = 0 }) {
  const key = JSON.stringify(queryKey);
  const entry = useSyncExternalStore(subscribe, () => cache.get(key));
  useEffect(() => {
    const e = cache.get(key);
    const stale = !e || !e.updatedAt || Date.now() - e.updatedAt > staleTime;
    if (stale) fetchQuery(key, queryFn);
  }, [key]); // 只写 key：queryFn 用到的变量都已在 key 里（见正文）
  return {
    data: entry && entry.data,
    isPending: !entry || (entry.data === undefined && !entry.error),
    isFetching: !!(entry && entry.fetching),
    isError: !!(entry && entry.error),
    error: entry && entry.error,
  };
}

// ===== 模拟后端 =====
let calls = 0;
const api = (id) => new Promise(r => setTimeout(() => {
  calls++;
  console.log('🌐 发出请求：用户 ' + id + '（累计 ' + calls + ' 次）');
  r({ id, name: ['张三', '李四', '王五'][id - 1], at: new Date().toLocaleTimeString('zh-CN') });
}, 900));

// ===== 应用 =====
function User({ id }) {
  const { data, isPending, isFetching, isError, error } = useQuery({ queryKey: ['user', id], queryFn: () => api(id), staleTime: 5000 });
  if (isPending) return <p>⏳ 首次加载中…</p>;
  if (isError && !data) return <p>❌ 出错了：{error.message}</p>;
  return <p>👤 {data.name}，数据获取于 {data.at} {isFetching && <small>（后台刷新中…）</small>}</p>;
}

function App() {
  const [id, setId] = useState(1);
  return (
    <div>
      {[1, 2, 3].map(n => <button key={n} onClick={() => setId(n)} disabled={n === id}>用户 {n}</button>)}
      <User id={id} />
      <User id={id} />
      <p style={{ color: 'gray', fontSize: 13 }}>两个 User 组件，同一个 id。</p>
    </div>
  );
}
```

迷你版和真库的差别：

1. 真库失败后默认重试 3 次，重试间隔合计约 7 秒（1、2、4 秒），再加 4 次请求本身的耗时，才会报错；迷你版立刻报错。
2. 真库在网络恢复时，也会刷新过期的数据。
3. 真库在没有组件使用一份缓存 5 分钟后删除它（`gcTime`）。
4. 迷你版没有 `invalidateQueries` 和 `useMutation`。

## staleTime：新鲜期内不请求，过期后台刷新

缓存里有数据，不等于这份数据还可信。`staleTime` 就是“这份数据多久之内算新鲜”。新鲜期内，用到它的组件不会触发请求；过期以后，组件挂载、窗口重新获得焦点这类时刻，会先显示缓存，同时在后台请求新数据。默认值是 0，数据一到手就算过期。

下面的迷你版补上了“窗口重新获得焦点时刷新”。页面上的按钮用来模拟“切到别的标签页再切回来”。先预测，再运行。

```jsx play title="staleTime：切回标签页会不会请求"
import { useSyncExternalStore, useEffect, useRef, useState } from 'react';

// ===== 迷你 Query 缓存（第二版：窗口重新获得焦点时，过期的数据在后台刷新） =====
const cache = new Map();      // key -> { data, updatedAt, fetching, promise }
const listeners = new Set();
const notify = () => listeners.forEach(l => l());
const subscribe = (l) => { listeners.add(l); return () => listeners.delete(l); };

function fetchQuery(key, fn) {
  const entry = cache.get(key) || {};
  if (entry.promise) return entry.promise;
  const promise = fn().then(
    data => { cache.set(key, { data, updatedAt: Date.now() }); notify(); },
    error => { cache.set(key, { ...cache.get(key), error, fetching: false, promise: null }); notify(); }
  );
  cache.set(key, { ...entry, error: null, fetching: true, promise }); notify();
  return promise;
}
const isStale = (entry, staleTime) => !entry || !entry.updatedAt || Date.now() - entry.updatedAt >= staleTime;

function useQuery({ queryKey, queryFn, staleTime = 0 }) {
  const key = JSON.stringify(queryKey);
  const entry = useSyncExternalStore(subscribe, () => cache.get(key));
  const opts = useRef({ queryFn, staleTime });      // 总是指向最新的 queryFn 和 staleTime
  useEffect(() => { opts.current = { queryFn, staleTime }; });
  useEffect(() => {
    const refresh = () => {
      if (isStale(cache.get(key), opts.current.staleTime)) fetchQuery(key, opts.current.queryFn);
    };
    refresh();                                       // 组件挂载时
    window.addEventListener('focus', refresh);       // 窗口重新获得焦点时
    return () => window.removeEventListener('focus', refresh);
  }, [key]);
  return {
    data: entry && entry.data,
    isPending: !entry || entry.data === undefined,
    isFetching: !!(entry && entry.fetching),
  };
}

// ===== 模拟后端 =====
let calls = 0;
const getTime = () => new Promise(resolve => setTimeout(() => {
  calls++;
  console.log('🌐 发出请求（累计 ' + calls + ' 次）');
  resolve({ at: new Date().toLocaleTimeString('zh-CN'), n: calls });
}, 600));

// ===== 应用 =====
function App() {
  const [staleTime, setStaleTime] = useState(0);
  const { data, isPending, isFetching } = useQuery({ queryKey: ['time'], queryFn: getTime, staleTime });
  return (
    <div>
      <label>staleTime：
        <select value={staleTime} onChange={e => setStaleTime(Number(e.target.value))}>
          <option value={0}>0（默认）</option>
          <option value={60000}>1 分钟</option>
        </select>
      </label>
      {isPending
        ? <p>⏳ 首次加载中…</p>
        : <p>服务器时间 {data.at}（第 {data.n} 次请求）{isFetching && <small>　后台刷新中…</small>}</p>}
      <button onClick={() => window.dispatchEvent(new Event('focus'))}>模拟：切到别的标签页再切回来</button>
    </div>
  );
}
```

这个示例同样没有 `invalidateQueries`、重试和垃圾回收。真库在窗口重新获得焦点时的行为，由 `refetchOnWindowFocus` 控制，默认开启。迷你版为了方便模拟，监听的是 window 的 `focus` 事件。真库（5.x）监听的是页面可见性的变化（`visibilitychange`）：切换浏览器标签页再切回来，或者最小化窗口再恢复，才会触发；只有 window 的 `focus` 事件时不会。

## useMutation：修改数据

```jsx title="修改后让相关缓存失效，是最简单可靠的同步方式"
import { useMutation, useQueryClient } from '@tanstack/react-query';

function AddTodo() {
  const queryClient = useQueryClient();
  const mutation = useMutation({
    mutationFn: (title) => getJSON('/api/todos', {   // getJSON 见上一个示例
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ title }),
    }),
    onSuccess: () => {
      // 让 ['todos'] 缓存失效 → 所有用到它的组件自动重新获取
      queryClient.invalidateQueries({ queryKey: ['todos'] });
    },
  });

  return (
    <button disabled={mutation.isPending} onClick={() => mutation.mutate('新任务')}>
      {mutation.isPending ? '保存中…' : '添加'}
    </button>
  );
}
```

分工规则：**服务端数据交给 TanStack Query；纯客户端 state 交给 useState 或 Zustand**。很多项目引入它之后，Redux 里的大部分代码都可以删掉了。

## 乐观更新：先改界面，失败再回滚

简单情况不用动缓存：`const { variables, isPending } = useMutation(…)`，在列表末尾加一行 `{isPending && <li style={{ opacity: 0.5 }}>{variables}</li>}`。`variables` 是你传给 `mutate` 的参数。请求结束后，`invalidateQueries` 换成真数据。只有多个组件都要看到这条临时数据时，才用下面的缓存写法。

缓存写法的步骤如下：

1. 在 `onMutate` 中取消进行中的请求，保存旧数据，再用 `setQueryData` 写入新数据。
2. `onMutate` 返回旧数据。
3. 在 `onError` 中把旧数据写回去，并提示用户。
4. 在 `onSettled` 中调用 `invalidateQueries`，和服务器对齐。

```jsx title="React 19 的 useOptimistic 是另一种写法（第 30 课）"
useMutation({
  mutationFn: addTodo,
  onMutate: async (title) => {
    await queryClient.cancelQueries({ queryKey: ['todos'] });
    const prev = queryClient.getQueryData(['todos']);
    queryClient.setQueryData(['todos'], old => [...(old ?? []), { id: 'temp', title }]);
    return { prev };                                 // 会作为 onError 的第 3 个参数（v5 后期末尾还多一个 context 参数，三参数写法仍可用）
  },
  onError: (err, title, result) => queryClient.setQueryData(['todos'], result?.prev),
  onSettled: () => queryClient.invalidateQueries({ queryKey: ['todos'] }),
});
```

## 用真的 TanStack Query

下面的示例运行 @tanstack/react-query 5.104.1 的开发版（本课对真库行为的描述都按这个版本实测）。它只在示例用到时才加载。示例里的“服务器”都是返回 Promise 的模拟函数，不发任何网络请求。上面几节的 `useQuery`、`useMutation` 代码是只读的，这里全部可以运行。

### QueryClientProvider 与 useQuery 的状态字段

`QueryClient` 保存所有缓存。`QueryClientProvider` 把它交给下面的所有组件。`useQuery` 返回的状态分成两组，不要混在一起：

- `status` 回答“有没有数据”：`pending`（还没有数据）、`error`（请求失败）、`success`（有数据）。`isPending`、`isError`、`isSuccess` 是它的简写。
- `fetchStatus` 回答“请求在不在进行”：`fetching`（正在请求）、`paused`（想请求但没有网络）、`idle`（没有请求）。`isFetching` 是它的简写。

两组状态互相独立。依次点“用户 2”“用户 3”，再点回“用户 1”，对照表格看每个字段怎么变。

```jsx play title="真库：useQuery 的状态字段"
import { useState } from 'react';
import { QueryClient, QueryClientProvider, useQuery } from '@tanstack/react-query';

// ===== 模拟后端：不发真实请求，只返回 Promise（800 毫秒后成功；用户 3 不存在，会失败） =====
const fetchUser = id => new Promise((resolve, reject) => setTimeout(() => {
  if (id === 3) reject(new Error('用户 3 不存在'));
  else resolve({ id, name: ['张三', '李四'][id - 1] });
}, 800));

// 真库默认在失败后重试 3 次，重试间隔合计约 7 秒（1、2、4 秒），再加 4 次请求本身的耗时，所以要等约 10 秒才报错。这里关掉重试，让错误立刻显示。
const queryClient = new QueryClient({ defaultOptions: { queries: { retry: false } } });

function UserCard({ id }) {
  const q = useQuery({ queryKey: ['user', id], queryFn: () => fetchUser(id) });
  return (
    <table>
      <tbody>
        <tr><td>status</td><td>{q.status}</td></tr>
        <tr><td>fetchStatus</td><td>{q.fetchStatus}</td></tr>
        <tr><td>isPending</td><td>{String(q.isPending)}</td></tr>
        <tr><td>isFetching</td><td>{String(q.isFetching)}</td></tr>
        <tr><td>data</td><td>{q.data ? q.data.name : '（没有）'}</td></tr>
        <tr><td>error</td><td>{q.error ? q.error.message : '（没有）'}</td></tr>
      </tbody>
    </table>
  );
}

function App() {
  const [id, setId] = useState(1);
  return (
    <QueryClientProvider client={queryClient}>
      {[1, 2, 3].map(n => <button key={n} onClick={() => setId(n)} disabled={n === id}>用户 {n}</button>)}
      <UserCard id={id} />
    </QueryClientProvider>
  );
}
```

点回“用户 1”时，表格是 `success` 加 `fetching`：缓存里有数据，所以先显示它；`staleTime` 默认是 0，数据已经过期，所以同时在后台请求。`pending` 只在“还没有任何数据”时出现。

### queryKey 与缓存共享

相同的 `queryKey` 共享同一份缓存和同一个请求。先预测，再运行。

```jsx play title="真库：相同的 queryKey 共享请求"
import { useState } from 'react';
import { QueryClient, QueryClientProvider, useQuery } from '@tanstack/react-query';

// ===== 模拟后端：每次调用都在控制台记一行 =====
let calls = 0;
const fetchUser = id => new Promise(resolve => {
  calls++;
  console.log('🌐 请求用户 ' + id + '（累计 ' + calls + ' 次）');
  setTimeout(() => resolve({ id, name: ['张三', '李四'][id - 1] }), 600);
});

const queryClient = new QueryClient();

function UserName({ id }) {
  const { data, isPending } = useQuery({
    queryKey: ['user', id],
    queryFn: () => fetchUser(id),
    staleTime: 10_000,                       // 10 秒内认为数据是新鲜的
  });
  return <li>用户 {id}：{isPending ? '加载中…' : data.name}</li>;
}

function App() {
  const [extra, setExtra] = useState(false);
  return (
    <QueryClientProvider client={queryClient}>
      <ul>
        <UserName id={1} />
        <UserName id={1} />
        <UserName id={2} />
        {extra && <UserName id={1} />}
      </ul>
      <button onClick={() => setExtra(true)} disabled={extra}>再挂载一个用户 1</button>
    </QueryClientProvider>
  );
}
```

### staleTime 与后台刷新

组件隐藏再显示，就是卸载再挂载。缓存不会随组件卸载而删除（没有组件使用的缓存默认保留 5 分钟，这个时间叫 `gcTime`）。重新挂载时，Query 看这份数据新不新鲜，决定要不要请求。按下面的顺序试：

1. 保持 `staleTime` 为 0。点“隐藏时钟”，再点“显示时钟”。
2. 选“30 秒”，再隐藏、显示。数据在 30 秒内，不会请求。

```jsx play title="真库：staleTime 决定重新挂载时请不请求"
import { useState } from 'react';
import { QueryClient, QueryClientProvider, useQuery } from '@tanstack/react-query';

// ===== 模拟后端：返回“服务器时间”，每次调用在控制台记一行 =====
let calls = 0;
const fetchTime = () => new Promise(resolve => {
  calls++;
  console.log('🌐 请求服务器时间（累计 ' + calls + ' 次）');
  setTimeout(() => resolve({ at: new Date().toLocaleTimeString('zh-CN'), n: calls }), 600);
});

const queryClient = new QueryClient();

function Clock({ staleTime }) {
  const { data, isPending, isFetching } = useQuery({ queryKey: ['time'], queryFn: fetchTime, staleTime });
  if (isPending) return <p>⏳ 首次加载中…</p>;
  return <p>服务器时间 {data.at}（第 {data.n} 次请求）{isFetching && <small>　后台刷新中…</small>}</p>;
}

function App() {
  const [staleTime, setStaleTime] = useState(0);
  const [shown, setShown] = useState(true);
  return (
    <QueryClientProvider client={queryClient}>
      <label>staleTime：
        <select value={staleTime} onChange={e => setStaleTime(Number(e.target.value))}>
          <option value={0}>0（默认）</option>
          <option value={30000}>30 秒</option>
        </select>
      </label>
      <button onClick={() => setShown(!shown)} style={{ marginLeft: 8 }}>{shown ? '隐藏' : '显示'}时钟</button>
      {shown && <Clock staleTime={staleTime} />}
    </QueryClientProvider>
  );
}
```

第 1 步里，旧时间先显示出来，旁边出现“后台刷新中…”，随后换成新时间。第 2 步里，控制台没有新的请求行。

### useMutation 与 invalidateQueries

`useMutation` 负责修改服务器上的数据。`mutate` 的参数会交给 `mutationFn`。修改成功后，缓存里的列表还是旧的，需要告诉 Query“这份数据过期了”：`invalidateQueries` 把匹配的缓存标为过期，正在显示的会立刻重新请求。先预测，再运行。

```jsx play title="真库：mutation 成功后不失效缓存"
import { QueryClient, QueryClientProvider, useMutation, useQuery, useQueryClient } from '@tanstack/react-query';

// ===== 模拟后端：数据只存在这个数组里，不发真实请求 =====
const db = [{ id: 1, title: '读完这一课' }, { id: 2, title: '写一个 useQuery' }];
const sleep = ms => new Promise(resolve => setTimeout(resolve, ms));
async function listTodos() {
  await sleep(300);
  console.log('🌐 GET 待办（服务器里有 ' + db.length + ' 条）');
  return [...db];
}
async function addTodo(title) {
  await sleep(300);
  db.push({ id: Date.now(), title });
  console.log('🌐 POST 添加“' + title + '”（服务器里有 ' + db.length + ' 条）');
}

const queryClient = new QueryClient();

function Todos() {
  const client = useQueryClient();
  // staleTime 设成 Infinity：数据永远算新鲜，不会因为别的原因自己刷新，现象更干净
  const { data = [] } = useQuery({ queryKey: ['todos'], queryFn: listTodos, staleTime: Infinity });
  const add = useMutation({
    mutationFn: addTodo,
    onSuccess: () => {
      // client.invalidateQueries({ queryKey: ['todos'] });
    },
  });
  return (
    <div>
      <ul>{data.map(t => <li key={t.id}>{t.title}</li>)}</ul>
      <button disabled={add.isPending} onClick={() => add.mutate('新任务 ' + (data.length + 1))}>
        {add.isPending ? '保存中…' : '添加一条'}
      </button>
    </div>
  );
}

function App() {
  return <QueryClientProvider client={queryClient}><Todos /></QueryClientProvider>;
}
```

### 乐观更新：先改缓存，失败再回滚

下面的示例用缓存写法。点“添加一条”：新的一行立刻出现，1 秒后变成正式数据。勾选“服务器拒绝保存”再点一次：新的一行先出现，1 秒后消失，并显示回滚提示。

```jsx play title="真库：乐观更新与回滚"
import { useState } from 'react';
import { QueryClient, QueryClientProvider, useMutation, useQuery, useQueryClient } from '@tanstack/react-query';

// ===== 模拟后端：数据只存在这个数组里。勾选“服务器拒绝保存”后，添加会失败 =====
const db = [{ id: 1, title: '读完这一课' }];
const sleep = ms => new Promise(resolve => setTimeout(resolve, ms));
async function listTodos() {
  await sleep(300);
  return [...db];
}
async function addTodo({ title, fail }) {
  await sleep(1000);
  if (fail) throw new Error('服务器拒绝保存');
  db.push({ id: Date.now(), title });
}

const queryClient = new QueryClient();

function Todos() {
  const client = useQueryClient();
  const [fail, setFail] = useState(false);
  const [message, setMessage] = useState('');
  const { data = [] } = useQuery({ queryKey: ['todos'], queryFn: listTodos });
  const add = useMutation({
    mutationFn: addTodo,
    onMutate: async ({ title }) => {
      setMessage('');
      await client.cancelQueries({ queryKey: ['todos'] });   // 先取消进行中的请求，免得它回来盖掉乐观数据
      const prev = client.getQueryData(['todos']);           // 保存旧数据
      client.setQueryData(['todos'], old => [...(old ?? []), { id: 'temp', title: title + '（保存中）' }]);
      return { prev };                                       // 返回值会交给 onError
    },
    onError: (err, vars, result) => {
      client.setQueryData(['todos'], result.prev);           // 失败：把旧数据写回去
      setMessage('已回滚：' + err.message);
    },
    onSettled: () => client.invalidateQueries({ queryKey: ['todos'] }),   // 无论成败，都和服务器对齐
  });
  return (
    <div>
      <ul>{data.map(t => <li key={t.id}>{t.title}</li>)}</ul>
      <button onClick={() => add.mutate({ title: '新任务 ' + (data.length + 1), fail })}>添加一条</button>
      <label style={{ marginLeft: 8 }}><input type="checkbox" checked={fail} onChange={e => setFail(e.target.checked)} />服务器拒绝保存</label>
      <p style={{ color: 'crimson' }}>{message}</p>
    </div>
  );
}

function App() {
  return <QueryClientProvider client={queryClient}><Todos /></QueryClientProvider>;
}
```

## 分页与无限滚动

列表很长时，服务器一次只返回一部分。前端有两种常见的取法：

- **分页**：一次只看一页，用“上一页”“下一页”切换。页码是 `useQuery` 的一个变量，写进 `queryKey`。
- **无限滚动或“加载更多”**：已加载的内容留在屏幕上，新的一页接在后面。用 `useInfiniteQuery`。

### 分页：keepPreviousData

页码一变，`queryKey` 就变了，新的 key 下还没有数据，`isPending` 会重新变成 `true`，界面闪回“加载中”。`placeholderData: keepPreviousData` 让 Query 在新页回来之前，继续把上一页的数据当作占位数据显示。占位期间 `isPlaceholderData` 是 `true`。先预测，再运行。

```jsx play title="真库：分页与 keepPreviousData"
import { useState } from 'react';
import { QueryClient, QueryClientProvider, useQuery, keepPreviousData } from '@tanstack/react-query';

// ===== 模拟后端：23 篇文章，每页 5 篇。不发真实请求，只返回 Promise =====
const ALL = Array.from({ length: 23 }, (_, i) => '文章 ' + (i + 1));
const PAGE_SIZE = 5;
let calls = 0;
const fetchPosts = page => new Promise(resolve => {
  calls++;
  console.log('🌐 请求第 ' + page + ' 页（累计 ' + calls + ' 次）');
  setTimeout(() => resolve({
    items: ALL.slice((page - 1) * PAGE_SIZE, page * PAGE_SIZE),
    totalPages: Math.ceil(ALL.length / PAGE_SIZE),
  }), 700);
});

const queryClient = new QueryClient();

function Posts() {
  const [page, setPage] = useState(1);
  const { data, isPending, isFetching, isPlaceholderData } = useQuery({
    queryKey: ['posts', page],           // 页码是查询用到的变量，要写进 key
    queryFn: () => fetchPosts(page),
    placeholderData: keepPreviousData,   // 本例要观察的选项
  });
  if (isPending) return <p>⏳ 首次加载中…</p>;
  return (
    <div>
      <ul>{data.items.map(t => <li key={t}>{t}</li>)}</ul>
      <button onClick={() => setPage(p => p - 1)} disabled={page === 1}>上一页</button>
      <span>　第 {page} 页 / 共 {data.totalPages} 页　</span>
      <button onClick={() => setPage(p => p + 1)} disabled={isPlaceholderData || page >= data.totalPages}>下一页</button>
      {isFetching && <small>　请求中…</small>}
    </div>
  );
}

function App() {
  return <QueryClientProvider client={queryClient}><Posts /></QueryClientProvider>;
}
```

“下一页”在占位期间被禁用，是为了不在新页还没回来时继续往后翻。到最后一页时，也要用服务器返回的总页数把它禁用。

### 无限滚动：useInfiniteQuery

`useInfiniteQuery` 把已加载的每一页放在 `data.pages` 数组里。它比 `useQuery` 多了几个选项和字段：

| 名字 | 作用 |
|---|---|
| `initialPageParam` | 第一页的参数（v5 必填） |
| `queryFn({ pageParam })` | 用 `pageParam` 请求一页 |
| `getNextPageParam(lastPage, allPages)` | 根据最后一页算出下一页的参数。返回 `undefined` 或 `null` 表示没有下一页 |
| `fetchNextPage()` | 请求下一页，接在 `data.pages` 末尾 |
| `hasNextPage` | `getNextPageParam` 的返回值不是 `undefined` 或 `null` 时为 `true` |
| `isFetchingNextPage` | 正在请求下一页 |

`pageParam` 可以是页码，也可以是服务器返回的游标（cursor）。游标指向“从哪里继续”，数据在翻页期间有增删时，游标比页码更稳。先预测，再运行。

```jsx play title="真库：useInfiniteQuery 加载更多"
import { QueryClient, QueryClientProvider, useInfiniteQuery } from '@tanstack/react-query';

// ===== 模拟后端：10 条动态，每次返回 4 条，cursor 是起始位置。不发真实请求 =====
const ALL = Array.from({ length: 10 }, (_, i) => '动态 ' + (i + 1));
const SIZE = 4;
let calls = 0;
const fetchFeed = cursor => new Promise(resolve => {
  calls++;
  console.log('🌐 请求 cursor=' + cursor + '（累计 ' + calls + ' 次）');
  setTimeout(() => {
    const next = cursor + SIZE;
    resolve({ items: ALL.slice(cursor, next), nextCursor: next < ALL.length ? next : undefined });
  }, 600);
});

const queryClient = new QueryClient();

function Feed() {
  const { data, isPending, fetchNextPage, hasNextPage, isFetchingNextPage } = useInfiniteQuery({
    queryKey: ['feed'],
    initialPageParam: 0,                                // 第一页的参数
    queryFn: ({ pageParam }) => fetchFeed(pageParam),
    getNextPageParam: lastPage => lastPage.nextCursor,  // 返回 undefined 表示没有下一页
  });
  if (isPending) return <p>⏳ 首次加载中…</p>;
  const items = data.pages.flatMap(page => page.items);
  return (
    <div>
      <ul>{items.map(t => <li key={t}>{t}</li>)}</ul>
      <p>已加载 {data.pages.length} 页，共 {items.length} 条</p>
      <button onClick={() => fetchNextPage()} disabled={!hasNextPage || isFetchingNextPage}>
        {isFetchingNextPage ? '加载中…' : hasNextPage ? '加载更多' : '没有更多了'}
      </button>
    </div>
  );
}

function App() {
  return <QueryClientProvider client={queryClient}><Feed /></QueryClientProvider>;
}
```

真实项目里，常把“加载更多”换成滚动到底自动加载：用 `IntersectionObserver` 观察列表末尾的一个元素，它进入视口时调用 `fetchNextPage()`。条件仍然是 `hasNextPage && !isFetchingNextPage`，避免重复请求。

<CallBox kind="warn" label="常见坑">

`useInfiniteQuery` 的数据过期重新获取时，Query 会按顺序重新请求已经加载的**每一页**。页数很多时，这是不小的开销，可以用 `maxPages` 限制缓存的页数。

</CallBox>

## 常见坑

| 现象或需求 | 做法 |
|---|---|
| 接口失败后，要等很久才显示错误 | 默认会重试 3 次，重试间隔合计约 7 秒（1、2、4 秒），再加 4 次请求本身的耗时。测试里要设 `retry: false` |
| 断网时一直显示“加载中”，没有错误 | 默认的 `networkMode` 是 `'online'`：没有网络时，查询暂停（`fetchStatus` 是 `paused`），不发请求，也不报错。想在断网时得到错误，设 `networkMode: 'always'` |
| key 到处手写，容易拼错 | 用 key 工厂集中定义：`userKeys = { all: ['users'], detail: id => ['users', id] }`。`invalidateQueries({ queryKey: userKeys.all })` 能一次让所有用户缓存失效。v5 也可以用 `queryOptions({ queryKey, queryFn })` 把两者绑在一起 |
| 翻页或搜索时，界面闪回“加载中” | `placeholderData: keepPreviousData`：换 key 时先显示上一页数据（见上一节） |
| 要等前一个数据到了再请求 | `enabled: !!userId` |
| 只请求一次、不需要缓存；或数据已在服务端组件、loader 里取好 | 不必引入 Query |

<CallBox kind="deep" label="深入一点">

在 Next.js App Router 中，很多数据可以在服务端组件里直接 `await`。这时不需要 useQuery。TanStack Query 适合客户端频繁交互的数据。例如无限滚动、轮询和乐观更新。两者可以搭配使用。

</CallBox>

## 本机任务：用真库做一遍

请在[《项目搭建与工具链》](/lessons/engineering)里创建的 Vite 项目里做下面几步。

1. 运行 `npm install @tanstack/react-query`。在 `main.tsx` 里创建一个 `QueryClient`，用 `QueryClientProvider` 包住 `<App />`。
2. 新建 `src/api.ts`，写一个模拟后端：

```ts title="在本机项目里：src/api.ts"
let calls = 0;
const names: Record<number, string> = { 1: '张三', 2: '李四', 3: '王五' };

export async function fetchUser(id: number) {
  calls += 1;
  console.log(`🌐 请求用户 ${id}（累计 ${calls} 次）`);
  await new Promise(resolve => setTimeout(resolve, 800));
  if (!names[id]) throw new Error('用户不存在');
  return { id, name: names[id] };
}

export async function renameUser(id: number, name: string) {
  await new Promise(resolve => setTimeout(resolve, 300));
  names[id] = name;
}
```

3. 写一个 `UserCard` 组件：`useQuery` 的 `queryKey` 是 `['user', id]`，`queryFn` 调用 `fetchUser(id)`，`staleTime` 设为 `10_000`。按“加载中、出错、成功”渲染。
4. 在页面上放“用户 1”到“用户 4”四个按钮，同时渲染**两个**同一个 `id` 的 `UserCard`。
5. 再写一个“改名”按钮：用 `useMutation` 调用 `renameUser`，成功后 `invalidateQueries({ queryKey: ['user', id] })`。

对照下面的表自查：

| 做什么 | 应该看到 |
|---|---|
| 打开页面，两个 `UserCard` 同时显示用户 1 | 控制台只有 1 行“请求用户 1” |
| 点“用户 2”，10 秒内再点回“用户 1” | 名字立刻显示，没有新的请求日志 |
| 等超过 10 秒，再切回一个看过的用户 | 先显示旧名字，随后出现 1 行请求日志 |
| 把 `staleTime` 改成 0，切到别的浏览器标签页再切回来 | 出现 1 行请求日志（页面重新可见时触发；只有 window 的 `focus` 事件不算）。`staleTime` 是 10 秒且没过期时，不出现 |
| 点“用户 4” | 默认重试 3 次：控制台共 4 行“请求用户 4”，重试间隔合计约 7 秒（1、2、4 秒），再加 4 次请求本身的 0.8 秒，约 10 秒后才显示“用户不存在”。给 `useQuery` 加 `retry: false`，约 0.8 秒后就显示 |
| 点“改名” | 名字更新，控制台多 1 行请求（`invalidateQueries` 触发的重新获取） |
| 把 `queryKey` 改成 `['user']`（漏写 id），再点“用户 2” | 页面仍显示用户 1 的名字：漏写依赖的症状。试完改回来 |

想看每个 key 是新鲜还是过期，可以再装 `@tanstack/react-query-devtools`，把 `<ReactQueryDevtools />` 放进 `QueryClientProvider` 里。

做完后，你就可以在项目课里直接用这套写法了。
