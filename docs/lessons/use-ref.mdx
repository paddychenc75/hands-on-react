# useRef：不触发渲染的“口袋”

<LessonHeader />

<Warmup />

<LessonGoals />

<LessonProse>

`useRef` 返回一个对象 `{ current: 初始值 }`。在组件存在的整个期间，这个对象都是**同一个**。你可以随时修改 `.current`。**修改它不会触发重新渲染**。

## 用途一：访问 DOM 元素

把 ref 传给 JSX 元素的 `ref` 属性，React 会在挂载后把真实 DOM 节点放进 `ref.current`。

```jsx play title="ref 操作 DOM"
import { useRef } from 'react';

function App() {
  const inputRef = useRef(null);
  const boxRef = useRef(null);

  return (
    <div>
      <input ref={inputRef} placeholder="点按钮让我获得焦点" />
      <button onClick={() => inputRef.current.focus()}>聚焦</button>
      <button onClick={() => {
        const r = boxRef.current.getBoundingClientRect();
        console.log('盒子尺寸：', Math.round(r.width), 'x', Math.round(r.height));
      }}>测量盒子</button>
      <div ref={boxRef} style={{ marginTop: 8, padding: 20, background: '#e3f3f9' }}>我是一个盒子</div>
    </div>
  );
}
```

## 用途二：保存可变值

有些值需要跨渲染保留，但不显示在界面上。例如定时器 id、上一次的值、是否已初始化的标记。用 state 保存，会造成不必要的重新渲染。用普通变量保存，每次渲染时值会被重置。这时应该用 ref。

```jsx play title="用 ref 保存定时器 id 的秒表"
import { useState, useRef } from 'react';

function App() {
  const [time, setTime] = useState(0);
  const timerRef = useRef(null);   // 存定时器 id，不需要显示
  const renders = useRef(0);       // 记录渲染次数
  renders.current++;

  function start() {
    if (timerRef.current) return;
    timerRef.current = setInterval(() => setTime(t => t + 1), 100);
  }
  function stop() {
    clearInterval(timerRef.current);
    timerRef.current = null;
  }

  return (
    <div>
      <h2>{(time / 10).toFixed(1)} 秒</h2>
      <button onClick={start}>开始</button>
      <button onClick={stop}>停止</button>
      <button onClick={() => { stop(); setTime(0); }}>重置</button>
      <p style={{ color: 'gray' }}>组件已渲染 {renders.current} 次</p>
    </div>
  );
}
```

这个秒表还差一件事：组件从页面上消失时，定时器也该停下。这需要第 14 课的“清理函数”。学完那一课，可以回来补上。

## ref 和 state 的对比

|  | useState | useRef |
|---|---|---|
| 修改后是否重新渲染 | 是 | **否** |
| 修改方式 | 调用 set 函数，下次渲染才看到新值 | 直接 `ref.current = x`，立即生效 |
| 适合存什么 | 需要显示在界面上的数据 | DOM 节点、定时器 id 等“幕后”数据 |

<CallBox kind="warn" label="常见坑">

**不要在渲染期间读写 ref.current**。上面的 renders 计数只用于演示。渲染应该是纯的；ref 应该在事件处理函数里使用，或在第 14 课会讲的 effect 里使用。如果某个值要显示在界面上，就该用 state。

原因：React 可能把同一次渲染执行不止一遍。例如开发环境的严格模式会调用组件函数两次，`renders.current++` 就会多加。读 ref 也一样：ref 变了不会重新渲染，界面上显示的可能是旧值。唯一的例外是初始化：`if (ref.current === null) ref.current = 创建一次的对象;`。

</CallBox>

<CallBox kind="like" label="打个比方">

state 像公告栏，一改大家（界面）都看到；ref 像你的私人口袋，往里放东西谁也不会被通知，但需要时随时能掏出来。

</CallBox>

## 用途三：把 ref 传给自己的组件

在 React 19 里，`ref` 是自定义组件的**普通 prop**。函数组件可以直接从 props 里取出 `ref`，再交给里面的 DOM 元素。父组件就能拿到子组件内部的节点。

```jsx play title="ref 作为普通 prop"
import { useRef } from 'react';

function FancyInput({ ref, placeholder }) {
  return <input ref={ref} placeholder={placeholder} style={{ padding: 6 }} />;
}

function App() {
  const inputRef = useRef(null);
  return (
    <div>
      <FancyInput ref={inputRef} placeholder="我在子组件里" />
      <p>
        <button onClick={() => inputRef.current.focus()}>聚焦</button>{' '}
        <button onClick={() => console.log('ref.current 是：', inputRef.current.tagName)}>
          ref.current 是什么？
        </button>
      </p>
    </div>
  );
}
```

注意，子组件必须自己把 `ref` 取出来，再交给某个 DOM 元素。没有取出来，父组件的 `ref.current` 就一直是 `null`。

<CallBox kind="tip" label="维护 React 18 项目时">

React 18 及更早的版本里，函数组件收不到 `ref` 这个 prop，要用 `forwardRef` 包装：`const FancyInput = forwardRef(function FancyInput(props, ref) { … })`。React 19 仍然支持 `forwardRef`，官方说明以后会弃用它。读到旧项目里的 `forwardRef` 时，把它看成“让函数组件收到 ref 的包装”即可。更完整的用法见 [DOM 逃生舱](/lessons/escape-hatches)。

</CallBox>

## ref 回调：挂载时调用，移除时清理

`ref` 属性除了接收 `useRef` 创建的对象，还可以接收一个函数，叫 **ref 回调**。DOM 节点放进页面时，React 调用它，参数是这个节点。

从 React 19 起，ref 回调可以**返回一个清理函数**。节点从页面移除时，React 调用清理函数。这样“挂载时做什么，移除时就撤销什么”写在同一处，例如注册和取消监听。

```jsx play title="ref 回调：挂载与清理"
import { useState } from 'react';

function App() {
  const [show, setShow] = useState(true);
  const [n, setN] = useState(0);
  return (
    <div>
      <button onClick={() => setShow(s => !s)}>{show ? '隐藏' : '显示'}输入框</button>{' '}
      <button onClick={() => setN(n + 1)}>重新渲染（{n}）</button>
      {show && (
        <input
          placeholder="我带着一个 ref 回调"
          ref={node => {
            console.log('挂载：' + node.tagName);
            return () => console.log('清理：节点离开页面');
          }}
        />
      )}
    </div>
  );
}
```

在 React 18 里没有清理函数。节点移除时，React 会再调用一次 ref 回调，参数是 `null`，所以回调里要写 `if (node)` 判断。React 19 里，回调返回了清理函数，移除时就不再用 `null` 调用它。

<CallBox kind="warn" label="常见坑">

示例里的 ref 回调是内联箭头函数，每次渲染都是一个新函数。React 发现 `ref` 换了，就先调用旧的清理函数，再用新函数挂载一次。点“重新渲染”按钮，控制台会再出现“清理”和“挂载”。回调里的工作很重时，用 `useCallback` 让函数保持不变。

</CallBox>
