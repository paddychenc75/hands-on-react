# 闭包陷阱与 Effect 依赖

<LessonHeader />

<Warmup />

<LessonGoals />

<LessonProse>

这是从“会用 React”到“精通 React”必须跨过的一道坎。核心规则：**每一次渲染，都有自己的 props、state、事件处理函数和 effect**。先用一个演示检验这条规则。

```jsx play title="3 秒后打印什么？"
import { useState } from 'react';

function App() {
  const [count, setCount] = useState(0);

  function showLater() {
    setTimeout(() => {
      console.log('打印 count：' + count);
    }, 3000);
  }

  return (
    <div>
      <p>count: {count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <button onClick={showLater}>3 秒后打印 count</button>
    </div>
  );
}
```

组件函数每次执行，都会创建一批新的局部变量和函数。这些函数通过**闭包**“记住”了创建它们的那次渲染中的值，并且永远不会改变。

这不是 bug，而是一种可预测的特性：事件处理函数“属于”它被创建的那次渲染。

## 经典陷阱：effect 中的过期闭包

```jsx play title="这个计数器会怎样？"
import { useState, useEffect } from 'react';

function App() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      setCount(count + 1);
    }, 1000);
    return () => clearInterval(id);
  }, []);

  return <h2>{count}</h2>;
}
```

effect 只在挂载时运行一次。所以 interval 回调中的 `count` 永远是第一次渲染时的 0。回调每秒都执行 `setCount(0 + 1)`。

## 三种修复方式

| 方法 | 代码 | 评价 |
|---|---|---|
| ① 补全依赖 | `}, [count])` | 能用，但每秒都要清理并重建定时器 |
| ② 函数式更新 | `setCount(c => c + 1)` | **最佳**：不再读取 count，依赖可以为空 |
| ③ useReducer | `dispatch({ type: 'tick' })` | 适合逻辑依赖多个状态时，dispatch 引用永远稳定 |

<CallBox kind="tip" label="要点">

减少依赖时，不要直接删掉依赖数组里的值。正确的做法是**修改代码，让 effect 不再需要那个值**。常用方法有三个：

1. 使用函数式更新。
2. 把函数移到 effect 内部。
3. 把不依赖 props 和 state 的对象移到组件外部。

真实项目里，ESLint 的 `react-hooks/exhaustive-deps` 规则会指出漏写的依赖。看到它的警告时，按上面三个方法改代码，不要用注释关掉它。

</CallBox>

## 把事件逻辑从 effect 中分开：useEffectEvent

有时，effect 里有一段逻辑，需要读最新的值，但这个值变化时不该让 effect 重新运行。例如聊天室：切换房间要重新连接，切换主题不该重新连接。可是“连接成功”后的提示要用当前主题。

如果把 `theme` 写进依赖，切换主题就会断开再重连。如果不写，就是过期闭包。

**Effect Event** 解决这个问题。React 19.2 起，`useEffectEvent` 把这段逻辑提取出来。它总能读到最新的 props 和 state，而且不是 effect 的依赖。下面的代码用到了 React 19 才有的 API，**只能阅读**，实验台运行不了：

```jsx title="只读：React 19.2 的 useEffectEvent"
import { useEffect, useEffectEvent } from 'react';

function ChatRoom({ roomId, theme }) {
  // 读最新的 theme，但它自己不是依赖
  const onConnected = useEffectEvent(() => {
    showToast('已连接 ' + roomId, theme);
  });

  useEffect(() => {
    const conn = createConnection(roomId);
    conn.on('connected', () => onConnected());
    conn.connect();
    return () => conn.disconnect();
  }, [roomId]); // 只有 roomId 变化才重连
}
```

它有两条限制：

1. 只能在 effect 内部（或另一个 Effect Event 里）调用，不要在渲染时调用。
2. 不要把它传给别的组件，也不要放进依赖数组。

它不是“绕过依赖检查”的工具。只有逻辑本来就属于“事件”（发生了某件事，要做点什么），而且你不希望它的值引起重新同步，才用它。如果 `roomId` 变了就该重连，它就必须留在依赖里。

## React 18 中的写法：用 ref 读取最新值

实验台运行的是 React 18.3.1，没有 `useEffectEvent`。在 React 18，以及 19.2 之前的版本，用 ref 保存最新值。它就是 `useEffectEvent` 的手写版：

```jsx
const latestCount = useRef(count);
useEffect(() => { latestCount.current = count; }); // 每次渲染后同步

useEffect(() => {
  const id = setInterval(() => {
    console.log('最新的 count:', latestCount.current);
  }, 1000);
  return () => clearInterval(id);
}, []); // 依赖为空，但能读到最新值
```

用同样的办法改写上面的聊天室。先看代码里两个 effect 的依赖数组，再预测：

```jsx play title="聊天室：读到最新主题"
import { useState, useEffect, useRef } from 'react';

function ChatRoom({ roomId, theme }) {
  const latestTheme = useRef(theme);
  useEffect(() => { latestTheme.current = theme; }); // 每次渲染后同步

  useEffect(() => {
    console.log('连接 ' + roomId);
    const id = setInterval(() => {
      console.log('[' + roomId + '] 当前主题：' + latestTheme.current);
    }, 1000);
    return () => {
      clearInterval(id);
      console.log('断开 ' + roomId);
    };
  }, [roomId]);

  return <p>房间：{roomId}，主题：{theme}</p>;
}

function App() {
  const [roomId, setRoomId] = useState('综合');
  const [theme, setTheme] = useState('浅色');
  return (
    <div>
      <button onClick={() => setTheme(theme === '浅色' ? '深色' : '浅色')}>切换主题</button>
      <button onClick={() => setRoomId(roomId === '综合' ? '旅行' : '综合')}>切换房间</button>
      <ChatRoom roomId={roomId} theme={theme} />
    </div>
  );
}
```

## 对象和函数作为依赖

<CallBox kind="warn" label="常见坑">

在组件内定义的对象或函数，每次渲染都是新引用。把它放进依赖数组后，effect 会**每次渲染都执行**。如果 effect 里又调用 set 函数，就会**无限循环**。解决方法：把它移到组件外部，或移到 effect 内部，或用 useMemo、useCallback 固定它的引用。

</CallBox>
