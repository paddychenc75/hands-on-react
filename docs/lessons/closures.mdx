# 闭包陷阱与 Effect 依赖

<LessonHeader />

<Warmup />

<LessonGoals />

<LessonProse>

这是从“会用 React”到“精通 React”必须跨过的一道坎。核心规则：**每一次渲染，都有自己的 props、state、事件处理函数和 effect**。先用一个演示检验这条规则。

```jsx play title="3 秒后打印什么？"
import { useState } from 'react';

function App() {
  const [count, setCount] = useState(0);

  function showLater() {
    setTimeout(() => {
      console.log('打印 count：' + count);
    }, 3000);
  }

  return (
    <div>
      <p>count: {count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <button onClick={showLater}>3 秒后打印 count</button>
    </div>
  );
}
```

组件函数每次执行，都会创建一批新的局部变量和函数。这些函数通过**闭包**“记住”了创建它们的那次渲染中的值，并且永远不会改变。

这不是 bug，而是一种可预测的特性：事件处理函数“属于”它被创建的那次渲染。

## 经典陷阱：effect 中的过期闭包

```jsx play title="这个计数器会怎样？"
import { useState, useEffect } from 'react';

function App() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      setCount(count + 1);
    }, 1000);
    return () => clearInterval(id);
  }, []);

  return <h2>{count}</h2>;
}
```

effect 只在挂载时运行一次。所以 interval 回调中的 `count` 永远是第一次渲染时的 0。回调每秒都执行 `setCount(0 + 1)`。

## 四种修复方式

| 方法 | 代码 | 评价 |
|---|---|---|
| ① 补全依赖 | `}, [count])` | 能用，但每秒都要清理并重建定时器 |
| ② 函数式更新 | `setCount(c => c + 1)` | **最佳**：不再读取 count，依赖可以为空 |
| ③ useReducer | `dispatch({ type: 'tick' })` | 适合逻辑依赖多个状态时，dispatch 引用永远稳定 |
| ④ useEffectEvent | 在 effect 里调用 `onTick()`，`onTick` 读最新值 | 回调要读最新的 state，但值变化时不该重启 effect（见下一节） |

<CallBox kind="tip" label="要点">

减少依赖时，不要直接删掉依赖数组里的值。正确的做法是**修改代码，让 effect 不再需要那个值**。常用方法有三个：

1. 使用函数式更新。
2. 把函数移到 effect 内部。
3. 把不依赖 props 和 state 的对象移到组件外部。

真实项目里，ESLint 的 `react-hooks/exhaustive-deps` 规则会指出漏写的依赖。看到它的警告时，按上面三个方法改代码，不要用注释关掉它。

</CallBox>

## 把事件逻辑从 effect 中分开：useEffectEvent

有时，effect 里有一段逻辑要读最新的值，但这个值变化时不该让 effect 重新运行。例如聊天室：切换房间要重新连接，切换主题不该重新连接。可是连接期间每秒的提示，要用当前的主题。

第一种写法是老老实实把 `theme` 写进依赖。先看代码里 effect 的依赖数组，再预测：

```jsx play title="主题写进依赖会怎样"
import { useState, useEffect } from 'react';

function ChatRoom({ roomId, theme }) {
  useEffect(() => {
    console.log('连接 ' + roomId);
    const id = setInterval(() => {
      console.log('[' + roomId + '] 当前主题：' + theme);
    }, 1000);
    return () => {
      clearInterval(id);
      console.log('断开 ' + roomId);
    };
  }, [roomId, theme]);

  return <p>房间：{roomId}，主题：{theme}</p>;
}

function App() {
  const [roomId, setRoomId] = useState('综合');
  const [theme, setTheme] = useState('浅色');
  return (
    <div>
      <button onClick={() => setTheme(theme === '浅色' ? '深色' : '浅色')}>切换主题</button>
      <button onClick={() => setRoomId(roomId === '综合' ? '旅行' : '综合')}>切换房间</button>
      <ChatRoom roomId={roomId} theme={theme} />
    </div>
  );
}
```

依赖写得没错：effect 用了 `theme`，就必须依赖它。问题出在设计上：`theme` 在这里只是被“读取”，它不是“要不要重新连接”的理由。

**Effect Event** 解决这个问题。`useEffectEvent`（React 19.2 起稳定）把“读最新值”的那段逻辑提取成一个函数。这个函数总能读到最新的 props 和 state，而且不是 effect 的依赖。

```jsx play title="聊天室：读到最新主题"
import { useState, useEffect, useEffectEvent } from 'react';

function ChatRoom({ roomId, theme }) {
  // 读最新的 roomId 和 theme，但它自己不是 effect 的依赖
  const onTick = useEffectEvent(() => {
    console.log('[' + roomId + '] 当前主题：' + theme);
  });

  useEffect(() => {
    console.log('连接 ' + roomId);
    const id = setInterval(() => onTick(), 1000);
    return () => {
      clearInterval(id);
      console.log('断开 ' + roomId);
    };
  }, [roomId]); // 只有 roomId 变化才重连

  return <p>房间：{roomId}，主题：{theme}</p>;
}

function App() {
  const [roomId, setRoomId] = useState('综合');
  const [theme, setTheme] = useState('浅色');
  return (
    <div>
      <button onClick={() => setTheme(theme === '浅色' ? '深色' : '浅色')}>切换主题</button>
      <button onClick={() => setRoomId(roomId === '综合' ? '旅行' : '综合')}>切换房间</button>
      <ChatRoom roomId={roomId} theme={theme} />
    </div>
  );
}
```

Effect Event 有三条限制：

1. 只在 effect 内部（或另一个 Effect Event 里）调用。在渲染期间调用，React 会报错：`A function wrapped in useEffectEvent can't be called during rendering.`
2. 不要把它传给别的组件。
3. 不要把它写进依赖数组。它每次渲染都是新函数，写进去会让 effect 每次渲染都重新运行。

<CallBox kind="warn" label="常见坑">

`useEffectEvent` 不是“绕过依赖检查”的工具。只有逻辑本来就属于“事件”（发生了某件事，要做点什么），而且你不希望它读到的值引起重新同步，才用它。如果 `roomId` 变了就该重连，它就必须留在依赖里。

</CallBox>

<CallBox kind="tip" label="维护 React 19.2 之前的项目时">

`useEffectEvent` 从 React 19.2 开始提供。React 18 和 React 19.0、19.1 都没有它。这些版本的项目用 ref 保存最新值，效果相同：

```jsx
const latestTheme = useRef(theme);
useEffect(() => { latestTheme.current = theme; }); // 每次渲染后同步

useEffect(() => {
  const id = setInterval(() => {
    console.log('当前主题：', latestTheme.current);
  }, 1000);
  return () => clearInterval(id);
}, []); // 依赖为空，但能读到最新值
```

`useEffectEvent` 就是这种手写版的官方形式。有了它，新代码不需要自己写这套 ref 的同步。

</CallBox>

## 对象和函数作为依赖

<CallBox kind="warn" label="常见坑">

在组件内定义的对象或函数，每次渲染都是新引用。把它放进依赖数组后，effect 会**每次渲染都执行**。如果 effect 里又调用 set 函数，就会**无限循环**。解决方法：把它移到组件外部，或移到 effect 内部，或用 useMemo、useCallback 固定它的引用。

</CallBox>
