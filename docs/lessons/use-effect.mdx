# useEffect 与副作用

<LessonHeader />

<Warmup />

<LessonGoals />

<LessonProse>

组件函数应该是“纯”的。它只根据 props 和 state 计算 JSX。但真实应用必须和**外部系统**交互，例如：发网络请求、设定时器、订阅 WebSocket、修改 document.title。这些操作叫**副作用（side effect）**。

`useEffect` 让组件**与外部系统保持同步**。它在渲染完成、页面更新之后运行。

## effect 描述一次同步

每个 effect 只回答两个问题：

1. 怎样**开始同步**？写在 effect 的函数体里。
2. 怎样**停止同步**？写在 effect 返回的清理函数里。

```jsx
useEffect(() => {
  // 开始同步：渲染提交到页面后运行
  return () => {
    // 停止同步（可选的清理函数）：重新同步之前、或组件从页面上消失时运行
  };
}, [依赖1, 依赖2]); // 依赖数组：effect 读到的、会变的值
```

依赖数组不是你挑的。effect 里读到的每个 props 和 state，都要写进去。每次渲染后，React 比较这些值：

1. 都没变：什么也不做，上一次的同步继续。
2. 有一个变了：先运行上一次的清理函数，停止旧的同步；再运行 effect，开始新的同步。

你可能听过“挂载时执行、更新时执行”的说法。它来自旧的 class 组件。在函数组件里，按“开始同步 / 停止同步”来想更不容易出错。

## 从结果上看：三种依赖写法

下面的演示有三个 effect，依赖数组各不相同。先想一想：在输入框里打字时，哪些 effect 会运行？

```jsx play title="观察三种 effect 的执行时机"
import { useState, useEffect } from 'react';

function App() {
  const [count, setCount] = useState(0);
  const [name, setName] = useState('');

  useEffect(() => {
    console.log('effect ①（没有依赖数组）');
  });

  useEffect(() => {
    console.log('effect ②（依赖 []）');
  }, []);

  useEffect(() => {
    console.log('effect ③（依赖 [count]）：count =', count);
    document.title = '点击了 ' + count + ' 次';
  }, [count]);

  return (
    <div>
      <button onClick={() => setCount(count + 1)}>count: {count}</button>
      <input value={name} onChange={e => setName(e.target.value)} placeholder="输入，观察控制台" />
    </div>
  );
}
```

| 写法 | 什么时候运行 | 典型用途 |
|---|---|---|
| `useEffect(fn)` | 每次渲染后都重新同步 | 很少用，容易造成性能问题 |
| `useEffect(fn, [])` | effect 不读任何会变的值，所以第一次渲染后同步一次就够了 | 连接不依赖 props 和 state 的外部系统，例如 window 事件 |
| `useEffect(fn, [a, b])` | 第一次渲染后开始同步；a 或 b 变化后，先停止旧的同步，再开始新的 | 根据 id 请求数据、同步某个值 |

`[]` 的意思是“effect 不读任何会变的值”，不是“我想只执行一次”。如果 effect 读了 count，却写 `[]`，它会一直用第一次渲染时的 count。

## 清理函数：善始善终

effect 可能开启一个持续运行的东西。例如定时器、事件监听或订阅。这时，必须在清理函数里关闭它。否则组件卸载后它还在运行，造成**内存泄漏**或奇怪的 bug。

```jsx play title="定时器的启动与清理"
import { useState, useEffect } from 'react';

function Clock() {
  const [now, setNow] = useState(new Date());

  useEffect(() => {
    console.log('⏱ 开始同步：启动定时器');
    const id = setInterval(() => setNow(new Date()), 1000);
    return () => {
      console.log('🧹 停止同步：清理定时器');
      clearInterval(id);
    };
  }, []);

  return <h2>{now.toLocaleTimeString('zh-CN')}</h2>;
}

function App() {
  const [show, setShow] = useState(true);
  return (
    <div>
      <button onClick={() => setShow(!show)}>{show ? '移除' : '显示'}时钟</button>
      {show && <Clock />}
    </div>
  );
}
```

<CallBox kind="like" label="打个比方">

effect 就像进房间开灯，清理函数就是出房间关灯。React 保证：每次“再次进房间”之前，都会先替你执行上一次的“关灯”。

</CallBox>

## 请求数据

在 effect 里请求数据是很常见的写法。注意要处理**竞态问题**：用户快速切换时，旧请求可能比新请求晚返回，覆盖掉正确的数据。用一个 `ignore` 标记即可解决。

```jsx play title="带竞态处理的数据请求"
import { useState, useEffect } from 'react';

// 模拟一个网络请求：随机延迟返回
function fakeFetch(id) {
  return new Promise(r => setTimeout(() => r({ id, name: '用户 #' + id }), 300 + Math.random() * 1200));
}

function App() {
  const [userId, setUserId] = useState(1);
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(false);

  useEffect(() => {
    let ignore = false;           // 标记这次请求是否已过期
    setLoading(true);
    fakeFetch(userId).then(data => {
      if (!ignore) {              // 只采用最新一次请求的结果
        setUser(data);
        setLoading(false);
      }
    });
    return () => { ignore = true; }; // userId 变化时，旧请求作废
  }, [userId]);

  return (
    <div>
      {[1, 2, 3, 4].map(id => (
        <button key={id} onClick={() => setUserId(id)} disabled={id === userId}>用户 {id}</button>
      ))}
      <p>{loading ? '加载中…' : user && user.name}</p>
    </div>
  );
}
```

<CallBox kind="deep" label="深入一点">

在 effect 里请求数据适合学习和小项目。它有几个局限：每个组件都要重写加载、出错、竞态这套代码；结果没有缓存，回到页面要重新请求；不能在服务端运行。真实项目通常用框架自带的数据获取，或 TanStack Query 这类库（第 37 课）。下一课会先把这套代码封装成自定义 Hook `useFetch`，并补上失败分支。

</CallBox>

<CallBox kind="warn" label="常见坑">

**依赖数组不要撒谎**。effect 中用到的 props、state，以及由它们算出的值，都要写进依赖数组。漏写会导致 effect 读到旧值（“闭包陷阱”），第 22 课会深入讲解。在真实项目里，ESLint 插件 `react-hooks/exhaustive-deps` 会帮你检查。

</CallBox>

<CallBox kind="warn" label="常见坑">

effect 里调用 set 函数，每次都设成一个新值（例如 `setCount(count + 1)`、新建的对象或数组），又不写依赖数组，就会**无限循环**：渲染 → effect → set → 渲染……依赖数组里放每次渲染都新建的对象或数组，effect 同样每次都运行。

</CallBox>

## 你可能不需要 effect

effect 是用来与**外部系统**同步的“逃生舱”。下面这些情况都**不需要** effect：

- **根据 props/state 计算出的值**：直接在渲染时计算。比如 `const fullName = first + ' ' + last`，不要用 effect 去 setFullName
- **响应用户操作**：直接写在事件处理函数里，比如点击购买后发请求
- **props 变化时重置状态**：给组件换一个 key

## 严格模式：多做一轮“开始 → 停止 → 再开始”

开发环境中，严格模式（`<StrictMode>`）会在组件第一次出现时，多做一轮同步。顺序是：**开始同步 → 停止同步 → 再开始同步**。

这样做是为了检查你的清理函数：如果 effect 只会开始、停不下来（或者停得不彻底），多出来的这一轮会让问题立刻暴露，例如两个定时器同时在跑。生产环境不会多做这一轮。

```jsx play title="严格模式：开始 → 停止 → 再开始"
import { useState, useEffect, StrictMode } from 'react';

function Room({ id }) {
  useEffect(() => {
    console.log('连接 ' + id);
    return () => console.log('断开 ' + id);
  }, [id]);
  return <p>已进入房间 {id}</p>;
}

function App() {
  const [show, setShow] = useState(false);
  return (
    <div>
      <button onClick={() => setShow(s => !s)}>{show ? '离开' : '进入'}房间</button>
      {show && (
        <StrictMode>
          <Room id="a" />
        </StrictMode>
      )}
    </div>
  );
}
```

真实项目里，`<StrictMode>` 包在整个应用的最外面，应用一启动就会这样。示例里让它随按钮一起出现，是为了让你点击时能观察到。

严格模式还有两个检查：把组件函数调用两次，用来暴露渲染里的副作用；React 19 起，也对 ref 回调做同样的“挂载 → 清理 → 再挂载”。如果你在控制台看到 effect 运行了两次，这是正常的。本课练习的检查也会用严格模式运行你的代码。
