## 需求说明

| 编号 | 需求 | 验收时看什么 |
|---|---|---|
| 1 | 搜索页 `/`：输入至少两个字的城市名，点“搜索”，搜索词写进网址的 `?q=` | 刷新页面、复制网址到新标签页，搜索词和结果都还在 |

## 数据来源

天气和城市数据来自 **Open-Meteo**（open-meteo.com）。它**不需要注册，也不需要密钥**，浏览器可以直接请求。下面三个请求都能直接返回数据，响应头允许跨域（`access-control-allow-origin: *`）。

| 用途 | 请求 | 返回 |
|---|---|---|
| 按名字搜索城市 | `https://geocoding-api.open-meteo.com/v1/search?name=上海&count=8&language=zh` | `{ results: [{ id, name, latitude, longitude, country, admin1 … }] }` |
| 按 id 取一个城市 | `https://geocoding-api.open-meteo.com/v1/get?id=1796236&language=zh` | 一个城市对象 |
| 取天气 | `https://api.open-meteo.com/v1/forecast?latitude=31.22&longitude=121.46&current=temperature_2m,weather_code,wind_speed_10m&daily=weather_code,temperature_2m_max,temperature_2m_min&timezone=auto&forecast_days=5` | `{ current: {…}, daily: { time: […], … } }` |

三点注意：

1. **没有匹配时，搜索接口不返回 `results` 字段**，而不是返回空数组。要在 API 层统一成空数组。
2. 搜索词太短（一个字）通常查不到，所以需求里要求至少两个字。
3. 免费接口只用于**非商业**用途，需要署名（CC BY 4.0），并有调用次数限制（每天不到一万次）。做学习项目够用。条款以 [open-meteo.com/en/terms](https://open-meteo.com/en/terms) 为准。

<CallBox kind="tip" label="备选方案">

## 每一份状态放在哪里

动手前先做第 27 课的练习：**给每一份数据归类，再选放的地方**。

| 数据 | 属于哪一类 | 放在哪里 | 为什么 |
|---|---|---|---|
| 搜索词 `q` | URL 状态 | `useSearchParams` | 刷新、分享、后退都能还原 |
| 输入框里还没提交的文字 | 界面状态 | `SearchForm` 里的 `useState` | 只和这个表单有关 |
| 搜索结果、城市资料、天气 | 服务器状态 | `useQuery` | 缓存、去重、重试、加载和错误都由库管理 |
| 收藏的城市 | 浏览器里的客户端状态 | `localStorage`，用 `useSyncExternalStore` 读取 | 不属于服务器；多个组件共享；刷新后还在 |
| 加载中、出错 | 派生数据 | `useQuery` 返回的 `isPending`、`isError` | 不要自己再存一份 |

**同一份数据只放一处**。最常见的错误是把两类状态混在一起，例如往服务器返回的城市对象上加一个 `fav` 字段。下面的示例演示另一个常见的混淆：把搜索词存在自己的 state 里，又同时存在 URL 里。

```jsx play title="URL 才是搜索词的唯一数据源"
import { useState } from 'react';

// 用一个对象模拟浏览器的历史记录和网址（实验台里不能真的改网址）
function App() {
  const [history, setHistory] = useState(['?q=上海']);
  const [index, setIndex] = useState(0);
  const url = history[index];
  const q = new URLSearchParams(url).get('q') || '';

  function search(next) {
    setHistory([...history.slice(0, index + 1), '?q=' + next]);
    setIndex(index + 1);
  }

  return (
    <div>
      <p>网址：<code>{url}</code></p>
      <button onClick={() => search('北京')}>搜索“北京”</button>{' '}
      <button disabled={index === 0} onClick={() => setIndex(index - 1)}>后退</button>
      <SearchBox initial={q} />
      <p>结果列表显示：{q} 的天气</p>
    </div>
  );
}

function SearchBox({ initial }) {
  const [text, setText] = useState(initial); // 用网址里的 q 当初始值
  return <p>输入框：<input value={text} onChange={e => setText(e.target.value)} /></p>;
}
```

示例里的“结果列表”直接读网址，所以永远是对的。输入框把网址里的 `q` 复制进了自己的 state，之后两者就各管各的。本机项目里的做法是给 `SearchForm` 加 `key={q}`：`q` 一变，表单重新挂载，草稿重新从网址初始化。这就是第 7 课讲过的“用 key 重置 state”。代价是提交后输入框会重新挂载，焦点会丢，这个小项目可以接受。

## 里程碑 1：类型和接口层

所有请求集中写在一个文件里，组件不直接调用 `fetch`。这样换数据来源、写测试都只改一处。注意三件事：`fetch` 不会因为 404 或 500 抛错，要自己检查 `res.ok`；把“没有 `results` 字段”统一成空数组；把接口的字段名转换成界面用的名字。

```ts title="在本机项目里：src/api/weather.ts"
export interface City {
  id: number;
  name: string;
  latitude: number;
  longitude: number;
  country?: string;
  admin1?: string;
}

export interface DayForecast {
  date: string;
  weatherCode: number;
  max: number;
  min: number;
}

export interface Forecast {
  current: { temperature: number; weatherCode: number; windSpeed: number };
  daily: DayForecast[];
}

const GEO_URL = 'https://geocoding-api.open-meteo.com/v1';
const FORECAST_URL = 'https://api.open-meteo.com/v1/forecast';

async function getJson<T>(url: string, signal?: AbortSignal): Promise<T> {
  const res = await fetch(url, { signal });
  if (!res.ok) throw new Error(`请求失败（${res.status}）`);
  return (await res.json()) as T;
}

export async function searchCities(name: string, signal?: AbortSignal): Promise<City[]> {
  const params = new URLSearchParams({ name, count: '8', language: 'zh', format: 'json' });
  const data = await getJson<{ results?: City[] }>(`${GEO_URL}/search?${params}`, signal);
  return data.results ?? []; // 没有匹配时，接口不返回 results 字段
}

export async function getCity(id: number, signal?: AbortSignal): Promise<City> {
  const city = await getJson<City | { generationtime_ms: number }>(`${GEO_URL}/get?id=${id}&language=zh`, signal);
  if (!('id' in city)) throw new Error('找不到这个城市');
  return city;
}

interface ForecastResponse {
  current: { temperature_2m: number; weather_code: number; wind_speed_10m: number };
  daily: { time: string[]; weather_code: number[]; temperature_2m_max: number[]; temperature_2m_min: number[] };
}

export async function getForecast(city: Pick<City, 'latitude' | 'longitude'>, signal?: AbortSignal): Promise<Forecast> {
  const params = new URLSearchParams({
    latitude: String(city.latitude),
    longitude: String(city.longitude),
    current: 'temperature_2m,weather_code,wind_speed_10m',
    daily: 'weather_code,temperature_2m_max,temperature_2m_min',
    timezone: 'auto',
    forecast_days: '5',
  });
  const data = await getJson<ForecastResponse>(`${FORECAST_URL}?${params}`, signal);
  return {
    current: { temperature: data.current.temperature_2m, weatherCode: data.current.weather_code, windSpeed: data.current.wind_speed_10m },
    daily: data.daily.time.map((date, i) => ({
      date,
      weatherCode: data.daily.weather_code[i],
      max: data.daily.temperature_2m_max[i],
      min: data.daily.temperature_2m_min[i],
    })),
  };
}

// WMO 天气代码 → 中文。只列常用分组，其余显示“未知”。
export function weatherLabel(code: number): string {
  if (code === 0) return '晴';
  if (code <= 3) return '多云';
  if (code === 45 || code === 48) return '雾';
  if (code >= 51 && code <= 57) return '毛毛雨';
  if ((code >= 61 && code <= 67) || (code >= 80 && code <= 82)) return '雨';
  if ((code >= 71 && code <= 77) || code === 85 || code === 86) return '雪';
  if (code >= 95) return '雷暴';
  return '未知';
}
```

## 里程碑 2：搜索页（URL、useQuery 和四种状态）

先写三个查询 Hook。**`queryKey` 里要写全所有影响结果的参数**：搜索词变了，就是另一份缓存。`signal` 让 Query 在组件卸载或参数变化时取消过期的请求。

```ts title="在本机项目里：src/api/queries.ts"
import { useQuery } from '@tanstack/react-query';
import { getCity, getForecast, searchCities, type City } from './weather.ts';

// queryKey 里写全所有影响结果的参数：搜索词变了，就是另一份缓存。
export function useCitySearch(q: string) {
  return useQuery({
    queryKey: ['cities', q],
    queryFn: ({ signal }) => searchCities(q, signal),
  });
}

export function useCity(id: number) {
  return useQuery({
    queryKey: ['city', id],
    queryFn: ({ signal }) => getCity(id, signal),
  });
}

// 依赖查询：要等城市数据到了，才有经纬度可以请求。
export function useForecast(city: City | undefined) {
  return useQuery({
    queryKey: ['forecast', city?.id],
    queryFn: ({ signal }) => getForecast(city as City, signal),
    enabled: city !== undefined,
    staleTime: 5 * 60_000,
  });
}
```

再写结果列表。每一种状态都要处理，而且**顺序有讲究**：先判断 `isPending`，再判断 `isError`，最后才能读 `data`。

```tsx title="在本机项目里：src/components/CityResults.tsx"
import { Link } from 'react-router';
import { useCitySearch } from '../api/queries.ts';
import QueryError from './QueryError.tsx';

export default function CityResults({ q }: { q: string }) {
  const search = useCitySearch(q);

  if (search.isPending) return <p role="status">加载中…</p>;
  if (search.isError) return <QueryError error={search.error} onRetry={() => search.refetch()} />;
  if (search.data.length === 0) return <p>没有找到“{q}”</p>;

  return (
    <ul>
      {search.data.map((city) => (
        <li key={city.id}>
          <Link to={`/city/${city.id}`}>{city.name}</Link>
          <span>
            {' '}
            {[city.admin1, city.country].filter(Boolean).join('，')}
          </span>
        </li>
      ))}
    </ul>
  );
}
```

下面的示例用我们学过的东西，写出这四种状态的渲染逻辑。重点看 `status` 的判断顺序，以及“没有找到”和“出错”是两件不同的事。

```jsx play title="加载、出错、没有找到、成功：四种状态"
import { useState, useEffect } from 'react';

const CITIES = ['上海', '上饶', '北京'];

// 模拟接口：搜“火星”没有结果（返回空数组），搜“错误”失败，其余按名字过滤
function searchCities(q) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (q === '错误') reject(new Error('请求失败（500）'));
      else resolve(CITIES.filter(c => c.startsWith(q)));
    }, 600);
  });
}

function useCitySearch(q) {
  const [state, setState] = useState({ status: 'pending', data: undefined, error: undefined });
  const [tick, setTick] = useState(0); // 点“重试”时加 1，让 effect 再运行一次
  useEffect(() => {
    let ignore = false;
    setState({ status: 'pending', data: undefined, error: undefined });
    searchCities(q).then(
      data => { if (!ignore) setState({ status: 'success', data, error: undefined }); },
      error => { if (!ignore) setState({ status: 'error', data: undefined, error }); }
    );
    return () => { ignore = true; };
  }, [q, tick]);
  return { ...state, retry: () => setTick(t => t + 1) };
}

function Results({ q }) {
  const search = useCitySearch(q);
  if (search.status === 'pending') return <p role="status">加载中…</p>;
  if (search.status === 'error')
    return (
      <div role="alert">
        <p>出错了：{search.error.message}</p>
        <button onClick={search.retry}>重试</button>
      </div>
    );
  if (search.data.length === 0) return <p>没有找到“{q}”</p>;
  return <ul>{search.data.map(c => <li key={c}>{c}</li>)}</ul>;
}

function App() {
  const [q, setQ] = useState('上');
  return (
    <div>
      {['上', '火星', '错误'].map(w => (
        <button key={w} onClick={() => setQ(w)} style={{ marginRight: 6 }}>搜“{w}”</button>
      ))}
      <p>当前搜索词：<b>{q}</b></p>
      <Results q={q} />
    </div>
  );
}
```

在本机项目里，这些状态不用自己写，`useQuery` 返回的 `isPending`、`isError` 和 `data` 就是它们。但**判断顺序和“空不是错”的原则**是你要自己写对的。

**应该看到：**

| 操作 | 应该看到 |
|---|---|

## 里程碑 3：详情页（路由参数和依赖查询）

详情页要两个请求：先按 id 取城市，再用城市的经纬度取天气。第二个请求**依赖**第一个的结果，所以用 `enabled` 控制：城市数据没到之前不发请求（`queries.ts` 里的 `useForecast` 已经写了）。

  const forecast = useForecast(city.data);
  const { isFavorite, toggle } = useFavorites();

  if (city.isPending) return <p role="status">加载中…</p>;
  if (city.isError) return <QueryError error={city.error} onRetry={() => city.refetch()} />;

  const fav = isFavorite(city.data.id);

  return (
    <main>
      <p>
        <Link to="/">← 返回搜索</Link>
      </p>
      <h1>{city.data.name}</h1>
      <button type="button" aria-pressed={fav} onClick={() => toggle({ id: city.data.id, name: city.data.name })}>
        {fav ? '★ 已收藏' : '☆ 收藏'}
      </button>

      {forecast.isPending && <p role="status">正在获取天气…</p>}
      {forecast.isError && <QueryError error={forecast.error} onRetry={() => forecast.refetch()} />}
      {forecast.data && (
        <>
          <p>
            现在 {forecast.data.current.temperature}°C，{weatherLabel(forecast.data.current.weatherCode)}，风速 {forecast.data.current.windSpeed} km/h
          </p>
          <ul aria-label="未来五天">
            {forecast.data.daily.map((d) => (
              <li key={d.date}>
                {d.date}：{weatherLabel(d.weatherCode)}，{d.min}° ~ {d.max}°
              </li>
            ))}
          </ul>
        </>
      )}
    </main>
  );
}

## 里程碑 4：收藏（客户端状态）

收藏只存在用户的浏览器里，不是服务器的数据，所以**不放进 React Query**。多个组件（详情页的按钮、搜索页的列表）要共享它，刷新后还要在，所以用 `localStorage` 保存，用 `useSyncExternalStore`（第 27 课）读取。

```ts title="在本机项目里：src/hooks/useFavorites.ts"
import { useSyncExternalStore } from 'react';

export interface Favorite {
  id: number;
  name: string;
}

const KEY = 'weather-favorites';
const listeners = new Set<() => void>();

// getSnapshot 每次都要返回同一个对象（除非数据真的变了），所以按原始字符串缓存解析结果。
let lastRaw: string | null = null;
let lastValue: Favorite[] = [];

function getSnapshot(): Favorite[] {
  const raw = localStorage.getItem(KEY);
  if (raw !== lastRaw) {
    lastRaw = raw;
    try {
      lastValue = raw ? (JSON.parse(raw) as Favorite[]) : [];
    } catch {
      lastValue = [];
    }
  }
  return lastValue;
}

function subscribe(listener: () => void) {
  listeners.add(listener);
  window.addEventListener('storage', listener); // 别的标签页改了收藏
  return () => {
    listeners.delete(listener);
    window.removeEventListener('storage', listener);
  };
}

function save(next: Favorite[]) {
  localStorage.setItem(KEY, JSON.stringify(next));
  listeners.forEach((l) => l());
}

// 收藏是浏览器里的数据，不是服务器数据：不放进 React Query。
export function useFavorites() {
  const favorites = useSyncExternalStore(subscribe, getSnapshot);
  const isFavorite = (id: number) => favorites.some((f) => f.id === id);
  const toggle = (fav: Favorite) => save(isFavorite(fav.id) ? favorites.filter((f) => f.id !== fav.id) : [...favorites, fav]);
  return { favorites, isFavorite, toggle };
}
```

两个细节：`getSnapshot` 每次必须返回**同一个对象**（除非数据真的变了），所以按原始字符串缓存解析结果；订阅里同时监听 `storage` 事件，别的标签页改了收藏，这里也会更新。

下面的示例演示“服务器状态”和“界面状态”分开以后的行为：切换城市不会重复请求，收藏不会触发请求。

```jsx play title="服务器缓存与收藏：互不干扰"
import { useState, useEffect } from 'react';

const DB = { 1: { id: 1, name: '上海', temp: 16 }, 2: { id: 2, name: '北京', temp: 11 } };
const log = [];   // 记录每一次真正发出的“请求”
const cache = new Map();

function loadCity(id) {
  log.push('请求 ' + DB[id].name);
  return new Promise(resolve => setTimeout(() => resolve(DB[id]), 300)).then(c => (cache.set(id, c), c));
}

function useCity(id) {
  const [, force] = useState(0);
  useEffect(() => {
    if (cache.has(id)) return;
    let ignore = false;
    loadCity(id).then(() => { if (!ignore) force(n => n + 1); });
    return () => { ignore = true; };
  }, [id]);
  return cache.get(id);
}

function App() {
  const [id, setId] = useState(1);
  const [favs, setFavs] = useState([]);   // 界面状态：只放收藏的 id
  const city = useCity(id);
  const isFav = favs.includes(id);

  return (
    <div>
      <button onClick={() => setId(1)}>上海</button>{' '}
      <button onClick={() => setId(2)}>北京</button>{' '}
      <button onClick={() => setFavs(isFav ? favs.filter(f => f !== id) : [...favs, id])}>
        {isFav ? '★ 已收藏' : '☆ 收藏'}
      </button>
      <p>{city ? city.name + '：' + city.temp + '°C' : '加载中…'}</p>
      <p>已收藏的 id：{favs.join('、') || '（无）'}</p>
      <p>请求记录：{log.join('，') || '（无）'}</p>
    </div>
  );
}
```

**应该看到：**

| 操作 | 应该看到 |
|---|---|
| 在详情页点“☆ 收藏” | 按钮变成“★ 已收藏”；网络面板里没有新请求 |
| 回到搜索页 | 上方出现“收藏”列表 |
| 刷新页面 | 收藏还在 |
| 在另一个标签页取消收藏 | 这个标签页的列表跟着更新（`storage` 事件） |

```tsx title="在本机项目里：src/test/utils.tsx"
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
import { render } from '@testing-library/react';
import { MemoryRouter } from 'react-router';
import { vi } from 'vitest';
import App from '../App.tsx';

// 用一个假的 fetch 代替真实网络：按网址片段返回准备好的数据。
export function mockFetch(routes: Record<string, unknown | Response>) {
  const fetchMock = vi.fn(async (input: RequestInfo | URL) => {
    const url = String(input);
    const key = Object.keys(routes).find((k) => url.includes(k));
    if (!key) throw new Error(`没有准备这个请求的假数据：${url}`);
    const body = routes[key];
    return body instanceof Response ? body : new Response(JSON.stringify(body), { status: 200 });
  });
  vi.stubGlobal('fetch', fetchMock);
  return fetchMock;
}

export function renderApp(path: string) {
  // 每个测试用新的 QueryClient，缓存不会串；测试里关掉重试，失败立刻显示。
  const client = new QueryClient({ defaultOptions: { queries: { retry: false } } });
  return render(
    <QueryClientProvider client={client}>
      <MemoryRouter initialEntries={[path]}>
        <App />
      </MemoryRouter>
    </QueryClientProvider>,
  );
}
```

<CallBox kind="warn" label="常见坑">

测试里不关重试，“请求失败”的测试会失败。`useQuery` 默认失败后重试 3 次，间隔 1 秒起；而 `findBy…` 默认只等 1 秒，等不到错误提示就超时。在这个项目里去掉 `retry: false`，错误测试会在约 1 秒后报“找不到 role="alert"”。

## 常见坑

| 现象 | 原因 | 修法 |
|---|---|---|
| 后退后输入框里是旧文字，结果列表是新的 | 草稿用 `useState(q)` 初始化，之后和 URL 脱节 | 给 `SearchForm` 加 `key={q}` |
| 错误时页面崩溃，报 `Cannot read properties of undefined` | 先读了 `data.length`，再判断 `isError` | 顺序：`isPending`、`isError`、再读 `data` |
| 切换城市后，先短暂看到上一个城市的天气 | `queryKey` 里漏了城市 id | 把 id 写进 `queryKey` |
| `localStorage.getItem is not a function`（运行测试时） | Node 25 及以后的版本默认带 `localStorage`，盖住了 jsdom 的 | 用 Node 24，或把 `test` 脚本改成 `NODE_OPTIONS=--no-experimental-webstorage vitest run`（新版本的 Vitest 修好后可以去掉） |
| 收藏一点就报“getSnapshot 应该被缓存” | `getSnapshot` 每次返回新数组 | 按原始字符串缓存解析结果 |
| 刷新详情页得到 404 | 静态托管没有路由回退 | 见第 31 课的 `vercel.json` |
