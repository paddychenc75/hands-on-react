## 剩余问题（合并去重）

### 机制仍有漏洞
1. 提示阶梯只看字面差异：每次加一个分号就算一次尝试，3 次即可解锁答案。
2. 阶段测验答完前离开不留记录，没有冷却；每答一题就显示答案。实测反复进出能看完全部新题和答案。
3. 课前热身在刚答完课内题几分钟后又出同一题，答对会把复习间隔从 1 天拉到 3 天，间隔复习被短路。
4. 阶段测验一旦通过就永久“已掌握”，没有隔段时间的复测。
5. 自我解释的 30 字门槛可以用无意义的字填满。
6. 看过参考答案后，独立写出相同代码也会被当成“答案原文”拒绝（只有一种写法的题会卡住）。

### 部分练习检查判错
- 放行：lifting-state 不提升 state 也能通过；use-ref 把定时器 id 放模块变量或 useState 能通过；project-search 空 Hook 能通过；concurrent 用 setTimeout 防抖加空 startTransition 能通过。
- 误拒：TypeScript 的 `tone?: 'info' | 'success' | undefined` 和 `Readonly<{…}>`；lists-keys 的 `key={'todo-' + t.id}`；custom-hooks 内部用两个 useState。
- 4 组课内题与阶段新题重复。

### 内容与呈现
- React 19 课（第 28 课）成为新的过载点：必读约 2500 字、无选读、无练习；Server Components、毕业设计的时长偏低。
- 28 个步骤段落仍用 `<br>1.` 手工编号；正文只有一级标题，层级难扫读。
- 术语残留：可访问性/无障碍、缓存/记忆化、销毁/卸载、“18 里”口语缩写。
- “遥控器”比喻用在两个不同概念上；性能测量课标题写“四个步骤”，图示只有 3 步。

### 关于“怪异模式”这条
讲解专家发现本地构建的 index.html 缺 doctype 和 viewport，手机上媒体查询不生效。已发布的 Artifact 在发布时会自动补上 doctype 和 viewport（第 9 版手机截图已确认布局正常），所以线上不受影响。建议仍在 build.py 里补上，避免本地预览出错。
